### 문제 유형과 출력 구조의 연결

딥러닝에서는 Model부터 고르기보다 무엇을 예측하려는 문제인지 먼저 정해야 한다. 문제 유형을 정하면 정답의 형태, Model 출력, Loss 함수가 함께 연결된다.

```text
예측하려는 대상
→ 문제 유형
→ Target과 Model 출력 형태
→ Loss 함수
```

| 문제 유형 | 판단 기준 | 현재 확인한 기본 출력·Loss |
| --- | --- | --- |
| 회귀 | 연속적인 숫자의 크기나 양을 예측 | 실제 숫자를 출력 |
| 이진 분류 | 둘 중 하나를 선택 | Logit 1개, `BCEWithLogitsLoss` |
| 다중 클래스 분류 | 여러 Class 중 하나를 선택 | Class별 Logit, `CrossEntropyLoss` |
| 다중 레이블 분류 | 여러 항목이 동시에 참일 수 있음 | 여러 항목을 각각 판단 |

### Logit

Logit은 Model이 입력과 현재 Weight를 이용해 계산한 확률 변환 전의 원시 점수다.

```text
logit = 입력 × weight + bias
```

초기 Weight가 Random하게 초기화되므로 학습 전 Logit이 의미 없는 값처럼 보일 수 있다. 하지만 Logit 자체를 Random한 값으로 직접 넣는 것은 아니다. Logit은 확률이 아니어서 `0~1` 범위로 제한되지 않으며, 이진 분류에서는 이후 Sigmoid를 적용해 `0~1` 사이의 값으로 바꿀 수 있다.

### 입력 Tensor의 구조와 기본 모델 후보

데이터 종류에 따라 입력 Tensor의 Shape가 달라진다. 현재 본 예제는 대부분 한 번에 처리할 Sample 수인 Batch Size `B`가 앞에 위치한다.

| 데이터 | 일반적인 Shape | 기본 모델 후보 |
| --- | --- | --- |
| 표 데이터 | `[B, F]` | MLP |
| 이미지 | `[B, C, H, W]` | CNN |
| Text Token | `[B, L]` | RNN·LSTM·Transformer |
| Text Embedding | `[B, L, D]` | RNN·LSTM·Transformer |
| 시계열 | `[B, L, F]` | RNN·LSTM |

긴 문맥을 다루는 기본 후보로는 Transformer도 연결해 이해했다. 다만 RNN 설정 등에 따라 `[L, B, F]`처럼 Batch가 첫 번째가 아닐 수도 있으므로 실제 Model이 요구하는 Shape를 확인해야 한다.

## 3. 학습하며 겪었던 문제점과 해결 과정

### 질문: 회귀가 숫자 계산용인가?

단순히 숫자가 사용된다고 회귀는 아니다. 회귀는 숫자의 실제 크기나 양 자체를 예측하는 문제다.

```text
집값은 얼마인가?
온도는 몇 도인가?
다음 공격의 데미지는 얼마인가?
→ 회귀
```

반면 다음 숫자는 크기가 아니라 Class를 구분하는 번호다.

```text
0 = 고양이
1 = 강아지
2 = 토끼
→ 분류
```

따라서 다음 공격의 실제 Damage를 `153.7`처럼 예측한다면 회귀라고 이해했다.

---

### 질문: Logit은 원시 점수라고 했는데 임의의 Random 값을 넣는 것인가?

아니다. Logit은 Model이 입력과 Weight를 사용해 계산한 결과다.

#### 처음 이해

Logit이라는 원시 점수를 Model에 임의의 Random 값으로 직접 넣는 것인지 궁금했다.

#### 수정된 이해

보통 Model의 초기 Weight가 Random하게 초기화되기 때문에 학습 전 Logit이 Random한 값처럼 보일 수 있다.

```text
Random하게 초기화된 weight
→ 입력과 계산
→ 초기 logit
```

즉, Logit을 Random하게 직접 넣는 것이 아니라 Random하게 초기화된 Weight로 계산한 초기 Logit이 아직 의미 없는 값처럼 나오는 것이다.

Logit은 확률이 아니므로 `0~1` 범위로 제한되지 않는다. 이진 분류에서는 이후 Sigmoid를 적용해 `0~1` 사이의 값으로 바꿀 수 있다는 흐름까지 확인했다.

---

### 이해한 내용: 이진 분류와 다중 클래스 분류

`사망한다 / 사망하지 않는다`처럼 O/X로 나뉘는 문제는 이진 분류다. 이진 분류에서는 일반적으로 Logit 1개를 출력하고 `BCEWithLogitsLoss`를 사용한다.

```text
둘 중 하나
→ 이진 분류
```

`무기 / 방어구 / 소비템 / 재료` 중 하나의 Item이 한 종류로만 분류된다면 다중 클래스 분류다. Class마다 Logit을 하나씩 출력하고 대표적으로 `CrossEntropyLoss`를 사용한다.

```text
여러 선택지
+ 정답은 하나
→ 다중 클래스 분류
```

---

### 이해한 내용: 다중 클래스와 다중 레이블

다중 클래스는 여러 Class 중 하나만 정답이고, 다중 레이블은 하나의 Sample에서 여러 항목이 동시에 참일 수 있다.

```text
다중 클래스
무기 / 방어구 / 소비템 / 재료
→ 하나만 선택

다중 레이블
중독 = O, 화상 = O, 기절 = X, 빙결 = X
→ 여러 상태가 동시에 참일 수 있음
```

---

### 이해한 내용: Batch 차원

여러 입력 Shape를 보면서 현재 예제에서는 기본적으로 Batch가 맨 앞에 위치한다는 점을 파악했다.

```text
표 데이터        [B, F]
이미지           [B, C, H, W]
Text Token       [B, L]
Text Embedding   [B, L, D]
시계열           [B, L, F]
```

`B`는 한 번에 처리하는 Sample 수인 Batch Size다. 다만 RNN 등의 설정에 따라 `[L, B, F]`처럼 Batch가 첫 번째가 아닐 수도 있으므로, 현재는 대부분의 예제가 `[B, ...]` 형태라고 이해했다.

---

### 질문: Sequence는 무엇인가?

Sequence는 순서나 시간의 흐름이 중요한 데이터다.

```text
걷기 → 점프 → 공격 → 회피 → 공격
```

행동의 종류뿐 아니라 어떤 순서로 일어났는지가 중요하다. 문장, 시간에 따른 Sensor 값, 플레이어 행동 기록도 Sequence로 볼 수 있다.

플레이어 32명의 최근 10개 시점에서 시점마다 Feature 4개를 기록했다면 Shape는 다음과 같다.

```text
[32, 10, 4]

32 = Batch
10 = Sequence 길이
4  = 각 시점의 Feature
```

Sequence는 단순히 값이 여러 개 있는 데이터가 아니라 순서나 시간 흐름이 중요한 데이터라고 이해했다.
