# 딥러닝 문제 유형과 입출력 구조 설계

> 학습일: 2026-08-19

## 핵심 정리

딥러닝 문제를 풀 때는 모델부터 고르는 것이 아니라 무엇을 예측하려는지부터 구분해야 한다.

숫자의 실제 크기나 양을 예측하면 회귀이고, 둘 중 하나를 고르면 이진 분류, 여러 선택지 중 하나를 고르면 다중 클래스 분류다. 여러 항목이 동시에 정답이 될 수 있다면 다중 레이블 문제다.

문제 유형을 정하면 정답의 형태, 모델의 출력 개수, Loss와 최종 예측 방식도 함께 결정된다.

입력 데이터는 보통 Batch를 포함한 Tensor로 표현한다. 표 데이터, 이미지, 텍스트, 시계열은 서로 Shape가 다르므로 데이터 구조를 먼저 읽을 수 있어야 한다.

> 결국 “무엇을 맞혀야 하는가?”로 문제 유형을 정하고, “입력 데이터가 어떤 모양인가?”를 보고 입출력 구조와 기본 모델 후보를 정한다고 이해했다.

---

## 문제 유형을 먼저 구분하는 이유

딥러닝에서는 먼저 무엇을 예측하려는 문제인지 구분해야 한다.

```text
문제 유형
→ 정답 y의 형태
→ 모델 출력 형태
→ Loss 함수
→ 최종 예측 방식
```

현재 복습한 문제 유형은 다음과 같다.

| 문제 유형 | 판단 기준 |
| --- | --- |
| 회귀 | 숫자의 실제 크기나 양을 예측 |
| 이진 분류 | 둘 중 하나를 선택 |
| 다중 클래스 분류 | 여러 클래스 중 하나를 선택 |

현재는 Loss 이름이나 세부 구조를 모두 외우기보다 문제를 보고 어떤 유형인지 구분하는 것을 우선한다.

---

## 회귀

### 회귀는 숫자를 계산하는 문제일까?

처음에는 결과가 숫자로 나오거나 숫자를 계산하는 문제를 모두 회귀라고 생각했다.

하지만 숫자로 표현된 정답이라고 해서 모두 회귀인 것은 아니다.

```text
0 = 고양이
1 = 강아지
2 = 토끼
```

여기서 `0`, `1`, `2`는 숫자의 크기가 아니라 클래스를 구분하기 위한 번호다. 따라서 이 문제는 회귀가 아니라 분류다.

회귀는 연속적인 숫자의 실제 크기나 양을 예측하는 문제다.

```text
집값은 얼마인가?
온도는 몇 도인가?
다음 공격의 데미지는 얼마인가?
```

게임에서 다음 공격의 실제 데미지를 `153.7`처럼 예측한다면 회귀다.

```text
숫자의 실제 크기·양을 예측
→ 회귀

숫자가 단순히 클래스 번호
→ 분류
```

## Logit

### Logit은 임의로 넣는 랜덤값일까?

처음에는 Logit이라는 원시 점수를 모델에 랜덤값으로 직접 넣는 것인지 궁금했다.

Logit 자체를 임의로 넣는 것은 아니다. 신경망의 초기 가중치가 랜덤하게 초기화될 수 있어 학습 초기의 Logit이 의미 없는 랜덤값처럼 보인다는 점과 혼동했다.

Logit은 입력과 현재 모델의 가중치를 이용해 모델이 계산한 값이다.

단순한 마지막 Linear Layer라면 다음처럼 생각할 수 있다.

```text
logit = 입력 × 가중치 + bias
```

예를 들어 다음과 같다.

```text
입력 x = 3
가중치 w = 0.7
bias = 0.2

logit = 3 × 0.7 + 0.2
       = 2.3
```

`2.3`은 직접 넣은 랜덤값이 아니라 모델의 계산 결과다.

```text
랜덤하게 초기화된 가중치
→ 입력과 계산
→ 초기 logit
```

초기 가중치가 아직 학습되지 않았기 때문에 초기 Logit도 의미 없는 값처럼 나올 수 있다.

Logit은 확률 자체가 아니므로 `0~1` 범위로 제한되지 않는다.

```text
-3.7
0.2
8.5
100
```

이진 분류에서는 Logit에 Sigmoid를 적용해 `0~1` 사이의 값으로 바꿀 수 있다는 흐름까지 확인했다.

```text
입력
→ 모델 계산
→ logit
→ Sigmoid
→ 확률처럼 해석 가능한 값
```

## 이진 분류

이진 분류는 둘 중 하나를 선택하는 문제다.

```text
사망한다 / 사망하지 않는다
스팸 / 정상
치명타 / 일반 공격
```

“플레이어가 다음 10초 안에 사망할지 예측한다”는 사망과 생존 중 하나를 고르는 O/X 문제이므로 이진 분류다.

정답은 보통 다음처럼 표현할 수 있다.

```text
0 = 아니다
1 = 맞다
```

현재 확인한 기본 흐름은 다음과 같다.

```text
입력
→ 모델
→ logit 1개
→ Sigmoid
→ 0 / 1 판단
```

> 둘 중 하나, O/X, Yes/No를 예측한다면 이진 분류라고 이해했다.

---

## 다중 클래스 분류

다중 클래스 분류는 여러 클래스 중 하나만 고르는 문제다.

```text
전사 / 마법사 / 궁수 / 도적
슬라임 / 고블린 / 오크 / 드래곤
무기 / 방어구 / 소비템 / 재료
```

클래스가 여러 개면 모델은 클래스마다 Logit을 하나씩 만들 수 있다.

```text
[전사, 마법사, 궁수, 도적]

logits = [1.2, 3.8, -0.4, 0.7]
```

이 예에서는 마법사에 해당하는 Logit이 가장 크므로 마법사를 예측할 수 있다.

게임 아이템 하나가 무기, 방어구, 소비템, 재료 중 하나로만 분류된다면 다중 클래스 분류다.

> 선택지는 여러 개지만 정답이 하나라면 다중 클래스 분류라고 이해했다.

---

## 다중 클래스와 다중 레이블

다중 클래스는 여러 선택지 중 하나만 정답이다.

```text
아이템 종류

무기 / 방어구 / 소비템 / 재료
→ 하나만 정답
```

다중 레이블은 여러 항목이 동시에 참일 수 있다.

```text
캐릭터 상태

중독 = O
화상 = O
기절 = X
빙결 = X
```

중독과 화상이 동시에 적용될 수 있으므로 이 문제는 다중 레이블 문제다.

```text
다중 클래스
= 여러 개 중 하나

다중 레이블
= 여러 개가 동시에 참일 수 있음
```

## 데이터 종류와 Tensor Shape

### Batch는 항상 첫 번째 차원일까?

여러 입력 Shape를 보면서 기본적으로 Batch가 맨 앞에 있다는 점을 발견했다.

현재 복습한 일반적인 입력 형태는 다음과 같다.

```text
표 데이터        [B, F]
이미지           [B, C, H, W]
텍스트 token     [B, L]
텍스트 embedding [B, L, D]
시계열           [B, L, F]
```

`B`는 Batch Size이며 한 번에 몇 개의 데이터를 묶어서 처리하는지를 뜻한다.

RGB 이미지 32장을 한 번에 처리한다면 다음과 같다.

```text
[32, 3, 256, 256]
 ↑
Batch
```

처음에는 Batch가 언제나 첫 번째라고 일반화했지만 예외도 있다. RNN 등의 설정에 따라 `[L, B, F]`처럼 Batch가 두 번째에 올 수도 있다.

현재는 다음처럼 이해한다.

> 지금 보는 대부분의 예제는 `[B, ...]` 형태로 시작하지만 항상 그런 것은 아니다.

## 표 데이터

표 데이터는 샘플 하나가 여러 Feature의 묶음으로 표현되는 데이터다.

게임 캐릭터 한 명의 데이터가 다음과 같다고 하자.

```text
[HP, 공격력, 방어력, 이동속도]
```

캐릭터가 32명이고 각 캐릭터에 Feature가 4개 있다면 다음과 같다.

```text
x.shape = [32, 4]

[Batch, Feature]
```

표 데이터의 기본 모델 후보로 MLP가 있다는 것까지 확인했다.

## Sequence

### Sequence는 어떤 데이터일까?

처음에는 Sequence라는 데이터 종류가 구체적으로 무엇을 의미하는지 명확하지 않았다.

Sequence는 순서나 시간의 흐름이 중요한 데이터다.

```text
걷기 → 점프 → 공격 → 회피 → 공격
```

행동 다섯 개가 존재한다는 사실뿐 아니라 어떤 순서로 행동했는지가 중요하다.

문장도 마찬가지다.

```text
나는 너를 좋아한다
너는 나를 좋아한다
```

사용된 단어가 비슷하더라도 순서가 달라지면 의미가 달라질 수 있다.

현재 확인한 Sequence 데이터의 예는 다음과 같다.

```text
문장과 대화
시간에 따른 센서값
플레이어 행동 기록
음성
시간 흐름에 따라 이어지는 데이터
```

플레이어 32명의 최근 10초를 보고, 매 순간 HP, 위치 X, 위치 Y, 속도를 기록한다고 하자.

```text
[32, 10, 4]

32 = Batch
10 = Sequence 길이
4  = 각 시점의 Feature
```

> Sequence는 단순히 값이 여러 개 있는 데이터가 아니라 순서나 시간 흐름이 중요한 데이터라고 이해했다.

## 데이터 구조와 기본 모델 후보

현재는 모델 내부 원리를 깊게 보기보다 데이터 종류와 대표적인 모델 후보를 간단히 연결했다.

```text
표 데이터
→ MLP

이미지
→ CNN

순서가 중요한 데이터
→ RNN / LSTM

긴 텍스트와 긴 문맥
→ Transformer
```

게임 데이터에 적용하면 다음과 같다.

```text
캐릭터 스탯
→ MLP

몬스터 이미지
→ CNN

시간에 따른 플레이어 행동 기록
→ RNN / LSTM

긴 대화나 채팅 문맥
→ Transformer
```

처음부터 가장 최신이거나 복잡한 모델을 선택하는 것이 목표는 아니다. 데이터 구조에 맞는 단순한 Baseline부터 시작한다는 흐름까지 확인했다.

## 다시 볼 때 핵심

회귀는 단순히 숫자가 나오는 문제가 아니라 집값, 온도, 데미지처럼 숫자의 실제 크기나 양을 예측하는 문제다.

분류에서 사용하는 `0`, `1`, `2` 같은 값은 크기가 아니라 클래스 번호일 수 있다.

이진 분류는 둘 중 하나, 다중 클래스 분류는 여러 선택지 중 하나를 고른다. 여러 항목이 동시에 참이 될 수 있다면 다중 레이블이다.

Logit은 모델에 임의로 넣는 랜덤값이 아니라 입력과 현재 가중치로 계산한 확률 변환 전 점수다.

Batch는 한 번에 처리하는 샘플의 개수다. 현재 보는 대부분의 Tensor는 `[B, ...]` 형태지만 항상 Batch가 첫 번째인 것은 아니다.

Sequence는 순서나 시간 흐름이 중요한 데이터다.

모델을 고를 때는 복잡한 모델부터 찾기보다 표, 이미지, Sequence 등 데이터 구조에 맞는 기본 모델부터 생각한다.
