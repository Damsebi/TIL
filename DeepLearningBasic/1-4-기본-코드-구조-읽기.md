# 기본 코드 구조 읽기

> 학습일: 2026-08-19

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

### PyTorch 코드를 읽는 큰 흐름

PyTorch 학습 코드는 처음부터 모든 줄을 해석하기보다 역할이 바뀌는 지점을 먼저 찾는다.

```text
import
→ data
→ model
→ loss / optimizer
→ train / validation
→ 기록 / 저장
```

자주 보는 코드를 역할로 연결하면 다음과 같다.

```text
model     = 예측하는 역할
loss      = 얼마나 틀렸는지 채점하는 역할
optimizer = parameter를 수정하는 역할
lr        = 한 번에 얼마나 크게 수정할지 정하는 값
```

### 데이터에서 예측까지의 흐름

데이터는 다음 순서로 준비된다.

```text
Tensor
→ TensorDataset으로 입력과 정답을 Sample 단위로 묶음
→ DataLoader가 Batch 단위로 꺼냄
→ Model에 입력해 Prediction 생성
```

Model을 정의하는 코드는 예측 구조를 준비하고, `model(batch_x)`처럼 호출하는 코드가 현재 Parameter를 사용해 실제 Prediction을 만든다.

### Train과 Validation 이후의 기록

Train에서는 Prediction과 Loss를 계산한 뒤 Gradient를 구해 Parameter를 수정한다. Validation에서는 Prediction과 Loss만 계산하고 Parameter는 수정하지 않는다.

```text
Train      = 예측 → 채점 → 수정 방향 계산 → parameter 수정
Validation = 예측 → 채점 → 성능 확인
```

Train과 Validation 결과는 함께 확인해야 한다. Train 성능은 계속 좋아지지만 Validation 성능이 나빠지면 과적합을 의심할 수 있다.

```text
metric     = 성능을 평가하는 기준
history    = Epoch별 성적을 기록하는 곳
checkpoint = 학습된 Model 상태를 저장한 것
matrix     = 행렬
```

## 2. 학습하며 겪었던 문제점과 해결 과정

### 질문: Import가 바로 읽히지 않으면 전부 외워야 하는가?

처음부터 모든 Import를 암기하기보다 자주 등장하는 이름의 역할부터 익히고, 반복해서 코드를 보며 눈에 익히는 방향으로 이해했다.

```text
torch         = PyTorch 핵심 기능
nn            = 신경망 관련 기능
DataLoader    = Dataset에서 Batch 단위로 데이터를 꺼냄
TensorDataset = Tensor들을 Dataset 형태로 묶음
```

---

### 질문: Tensor는 차원이고 Vector부터 n차원까지 모두 Tensor라고 부르는 것 아닌가?

Tensor는 차원 자체가 아니라 여러 차원의 수치 데이터를 담을 수 있는 PyTorch의 자료 구조다.

```text
0차원 Tensor → Scalar
1차원 Tensor → Vector
2차원 Tensor → Matrix
3차원 이상   → 고차원 Tensor
```

---

### 질문: `TensorDataset`을 선언하지 않으면 어떤 데이터가 들어오는가?

`TensorDataset`을 사용하지 않아도 `X`와 `y`가 이미 Tensor로 만들어졌다면 그대로 Tensor다. `TensorDataset(X, y)`는 Tensor를 새로 만드는 기능이 아니라 기존 Tensor를 같은 Index끼리 대응시켜 Dataset으로 묶는다.

```text
X[0] ↔ y[0]
X[1] ↔ y[1]
...
```

`TensorDataset`은 Tensor 자료형들을 학습에 사용할 Dataset 구조로 묶는 역할이라고 이해했다.

---

### 이해한 내용: `DataLoader`와 Batch

`batch_size=32`는 데이터를 32개 저장한다는 뜻이 아니라 Dataset에서 한 번에 Sample 32개를 꺼낸다는 뜻이다.

입력 Feature가 4개라면 일반적인 Batch Shape는 다음과 같다.

```text
(32, 4)

32 = 한 번에 처리하는 Sample 수
4  = 각 Sample의 Feature 수
```

---

### 질문: Model 부분이 Prediction을 만드는 것인가?

맞다. Model 정의는 예측을 어떤 구조로 수행할지 정하고, Model 호출은 입력을 사용해 실제 Prediction을 계산한다.

```python
preds = model(batch_x)
```

```text
model     = 예측하는 역할
loss      = 채점하는 역할
optimizer = 수정하는 역할
```

---

### 질문: 왜 입력 4개를 16개로 만들었다가 다시 1개로 만드는가?

`4 → 1`로 바로 출력하는 것도 가능하지만, 한 번의 Linear 계산으로 결과 하나를 만드는 구조가 된다.

```text
4 → 16 → ReLU → 1
```

중간 표현을 두면 입력 Feature 4개를 서로 다른 Weight로 계산한 여러 표현을 만들고 ReLU를 거쳐 더 다양한 패턴을 표현할 수 있다.

#### 처음 이해

입력 데이터 4개를 16개로 나누거나 가능한 조합 16개를 만드는 것이라고 생각했다.

#### 수정된 이해

입력 Feature 4개를 서로 다른 Weight로 계산해 새로운 중간 표현 16개를 만드는 것이다.

---

### 질문: `3 → 6`에서 6은 입력 3개의 전체 조합 개수인가?

아니다. `nn.Linear(3, 6)`은 입력 Feature 3개를 사용해 출력 Feature 6개를 만들도록 사람이 정한 Layer다.

```python
nn.Linear(3, 6)
```

`6`은 순열이나 조합으로 계산된 값이 아니라 사람이 정하는 출력 차원이다.

---

### 질문: Hidden Dimension의 최대값은 이론적으로 무한인가?

특별한 수학적 상한이 정해진 것은 아니며 원하는 크기의 유한한 정수를 설정할 수 있다. 다만 Hidden Dimension이 커지면 Weight와 Bias 등 학습할 Parameter 수와 계산량, Memory 사용량도 증가한다.

따라서 Hidden Dimension은 클수록 무조건 좋은 값이 아니라 문제와 자원에 맞게 정하는 Hyperparameter다.

---

### 이해한 내용: Loss·Optimizer·Learning Rate

Loss는 Prediction과 Target을 비교해 얼마나 틀렸는지 채점하고, Optimizer는 그 결과에서 계산한 Gradient를 이용해 Model의 Parameter를 수정한다.

처음에는 Parameter를 조금씩 수정하는 값을 `iter`와 비슷한 이름으로 기억했지만, 실제로는 `lr`, 즉 Learning Rate였다.

```text
loss      = 얼마나 틀렸는지
optimizer = Model을 수정하는 역할
lr        = 한 번에 얼마나 크게 수정할지
```

---

### 이해한 내용: Train과 Validation

Train에서는 Model을 실제로 수정한다.

```text
예측
→ 채점
→ 수정 방향 계산
→ parameter 수정
```

Validation에서는 Model을 수정하지 않고 현재 성능만 확인한다.

```text
예측
→ 채점
→ 끝
```

따라서 Validation에서 `optimizer.step()`을 실행하면 안 된다고 이해했다.

---

### 질문: Train 성적은 좋아지는데 Validation 성적은 나빠질 수 있는가? 흔한 일인가?

실제로 발생할 수 있고 비교적 흔히 관찰되며, 대표적으로 과적합과 관련된다.

```text
학습 초반
train loss ↓
valid loss ↓

과적합이 진행될 때
train loss ↓
valid loss ↑
```

Model이 일반적인 패턴뿐 아니라 Train 데이터의 세부 특징이나 Noise까지 지나치게 맞추기 시작하면 새로운 Validation 데이터에서는 성능이 떨어질 수 있다. 따라서 Train 성적만으로 학습이 잘됐다고 판단하지 않고 Validation 결과도 함께 확인해야 한다.

---

### 질문: `metric`은 행렬인가? `matrix`와 다른가?

둘은 다른 개념이다.

```text
metric = 평가 지표
matrix = 행렬
```

Accuracy, Precision, Recall, F1 Score 등이 Metric의 예다. Epoch별 `train_loss`와 `valid_loss` 등을 저장하는 곳은 예제의 `history`이며, Metric 자체가 데이터를 저장하는 공간을 뜻하지 않는다.

```text
metric     = 성능을 평가하는 기준
history    = 성적을 기록하는 곳
checkpoint = 학습한 Model 상태를 저장한 것
```
