# ReLU의 역할과 사용 위치

> 학습일: 2026-08-21

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

### 음수는 0으로, 양수는 그대로

ReLU는 **음수는 0으로 바꾸고 양수는 그대로 보내는 함수**로 이해했다. `max(0, x)`에서 양수일 때 새로운 값을 만들어내는 것은 아니다. Tensor의 값은 바뀔 수 있지만 Shape는 그대로다.

4-1강에서 본 것처럼 이런 꺾임이 들어가야 여러 Linear 층으로 복잡한 패턴을 표현할 수 있다. 단순히 학습 효율을 높이기 위해 붙이는 것은 아니다.

### 어디에 붙이는지 구분하기

일반적인 MLP에서는 은닉층의 Linear 뒤에 ReLU를 사용한다.

```text
Linear → ReLU → Linear
```

마지막 출력층에는 ReLU를 무조건 붙이지 않는다. **중간에서 패턴을 표현하는 역할과 마지막에 필요한 예측값을 만드는 역할은 다르기 때문**이다. 출력은 문제 유형과 Loss가 요구하는 형태에 맞춘다.

## 2. 학습하며 겪었던 문제점과 해결 과정

### 이해 수정: ReLU의 목적과 출력값

#### 처음 이해

ReLU가 학습을 비선형적으로 만들어 효율이나 다양성을 높이고, 음수는 0으로 바꾼 뒤 그보다 큰 값을 도출한다고 표현했다.

#### 수정된 이해

ReLU의 목적은 모델에 비선형성을 넣어 단순한 선형 관계를 넘어서는 패턴을 표현하게 하는 것이다. 계산 결과는 다음처럼 구분한다.

```text
x ≤ 0 → 0
x > 0 → x 그대로
```

---

### 이해 수정: 출력층에 ReLU를 무조건 붙이지 않는 이유

#### 처음 이해

ReLU가 값을 바꿀 수 있어서 출력층에 사용하지 않는다고 생각했다.

#### 수정된 이해

값을 바꾸는 것 자체가 문제가 아니다. 회귀·이진 분류·다중 분류마다 필요한 출력과 Loss가 다르므로, 출력층에 ReLU가 맞는지는 그 조건을 보고 정해야 한다.

---

### 질문: `nn.Sequential`은 그냥 순차적으로 실행만 시켜주는 함수인가? 굳이 만들 필요가 있는가?

단순한 함수가 아니라 여러 Layer를 순서대로 묶는 `nn.Module` 컨테이너다.

```python
model = nn.Sequential(
    nn.Linear(4, 16),
    nn.ReLU(),
    nn.Linear(16, 3)
)
```

`model(x)`를 호출하면 차례대로 실행하고, 묶인 Layer들을 **모델 하나처럼 관리해준다.** Parameter 등록, `.to(device)`, `state_dict()`, `train()/eval()`도 그 모델을 통해 사용할 수 있다.

반드시 써야 하는 것은 아니다. 일렬 구조는 `nn.Sequential`이 편하고, 조건문·분기·중간 처리가 필요하면 `nn.Module`을 상속해 `forward()`를 직접 작성한다.

---

### 질문: `super().__init__()`에서 `super`는 무슨 뜻인가?

`super`는 약자가 아니다. 상속 순서에 따라 다음 클래스의 메서드에 접근하게 해주는 기능이다. 이번처럼 `nn.Module`을 상속한 클래스에서는 부모인 `nn.Module`의 초기화를 실행한다.

```python
class ReLUClassifier(nn.Module):
    def __init__(self):
        super().__init__()
```

---

### 질문: 왜 `__init__` 안에 또 `__init__`이 있는가?

같은 함수를 다시 부르는 것이 아니라 **자식과 부모의 서로 다른 초기화 함수**다.

```text
ReLUClassifier.__init__() 시작
→ nn.Module.__init__() 실행
→ 돌아와서 자식 클래스의 Layer 준비
```

부모가 맡은 모델 관리용 초기화를 먼저 하고, 그다음 내가 사용할 Layer를 등록한다고 이해했다.

---

### 질문: `nn.Module.__init__()`을 직접 호출해도 되는가?

`nn.Module.__init__(self)`처럼 직접 호출할 수도 있다. 다만 일반적으로는 `super().__init__()`을 사용한다.

부모 이름을 직접 고정하지 않고 상속 순서에 따라 호출하므로, 부모가 바뀌거나 다중 상속을 사용할 때도 그 구조에 맞춰 초기화를 이어갈 수 있다.

---

### 이해 수정: `forward()`는 학습층이 아니다

#### 처음 이해

`forward`를 학습층이라고 생각했다.

#### 수정된 이해

Layer가 아니라 **입력이 모델 안에서 어떤 순서로 계산되는지 적는 함수**다.

```python
def forward(self, x):
    x = self.fc1(x)
    x = self.relu(x)
    x = self.fc2(x)
    return x
```

이 계산 경로는 학습할 때뿐 아니라 추론할 때도 사용한다.

---

### 질문: Gradient 예시에서 왜 `0.1`을 사용했는가?

`0.1`은 Gradient가 아니라 입력을 조금 바꿔본 임의의 변화량이다.

```text
입력 3.0 → 출력 3.0
입력 3.1 → 출력 3.1

변화율 = 출력 변화량 / 입력 변화량
       = 0.1 / 0.1 = 1
```

양수 영역에서는 입력이 움직인 만큼 출력도 움직이므로 Gradient가 1이다. 예시의 `0.1` 자체에는 특별한 의미가 없다.

### 이해 수정: Dead ReLU

#### 처음 이해

모든 값이 음수여서 ReLU 결과가 0이 되고 움직이지 않는 상태로 이해했다.

#### 수정된 이해

정확히는 **어떤 뉴런의 Linear 출력이 학습 데이터에 대해 계속 음수가 되는 상황**이다. 그 뉴런의 ReLU 출력은 계속 0이고, 음수 영역의 Gradient도 0이라 해당 경로로 학습 신호가 전달되지 않는다.

이처럼 해당 뉴런이 학습에 기여하기 어려워지는 현상을 Dead ReLU라고 한다.
