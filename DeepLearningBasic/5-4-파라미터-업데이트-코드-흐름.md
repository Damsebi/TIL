# 파라미터 업데이트 코드 흐름

> 학습일: 2026-08-24

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

이번에는 이론을 다시 정리하기보다 **코드 한 줄을 실행한 뒤 무엇이 바뀌는지** 확인했다.

```python
optimizer.zero_grad()
pred = model(x)
loss = criterion(pred, y)
loss.backward()
optimizer.step()
```

`criterion(pred, y)`에서 MSE Loss가 계산되고, `backward()`에서 각 Parameter의 `.grad`가 채워진다. **여기까지 Weight·Bias 값은 그대로이고, `step()`에서 실제로 바뀐다.**

## 2. 학습하며 겪었던 문제점과 해결 과정

### 질문: `detach().clone()`은 무엇을 하는가?

```python
grad_after_first = model.weight.grad.detach().clone()
```

이 코드는 **지금의 Gradient 값을 따로 복사해 두는 것**이다.

- `detach()`: 같은 데이터를 바라보되 Autograd 계산 그래프와 분리된 Tensor를 반환한다. 데이터 자체를 복사하지는 않는다.
- `clone()`: 데이터를 별도 메모리에 복사한다.

둘을 이어 쓰면 이후 원본 Gradient가 바뀌어도 저장해 둔 값으로 당시 상태를 비교할 수 있다. 이번처럼 일반적인 `backward()`로 얻은 `.grad`는 보통 그래프를 추적하지 않으므로, **전후 비교에서는 독립된 복사본을 만드는 `clone()`이 특히 중요**하다.

---

### 질문: `detach()`로 분리한 뒤 원래 그래프에 다시 합쳐야 하는가?

그럴 필요 없다. `detach()`는 원본 `model.weight.grad` 자체를 그래프에서 떼어내는 것이 아니라, 분리된 Tensor를 반환한다.

원본 Parameter와 `.grad`는 그대로 남아 있고 Optimizer도 원본을 사용한다. `grad_after_first`는 **옆에 따로 보관한 관찰용 복사본**이므로 다시 합칠 대상이 아니다.

---

### 질문: `detach().clone()`을 하지 않으면 어떻게 되는가?

현재 값을 출력해서 확인하는 정도라면 없어도 학습에는 문제가 없다. Gradient를 따로 기록하는 것은 학습 필수 단계가 아니라 비교를 위한 코드다.

```python
grad_after_first = model.weight.grad
```

이렇게 저장하면 그 순간의 값이 복사되는 것이 아니라 **같은 Tensor를 가리킨다.** 이후 `.grad`에 값이 누적되면 `grad_after_first`로 보이는 값도 함께 바뀔 수 있다.

따라서 “첫 번째 Gradient를 저장했다”고 생각했는데 실제로는 바뀐 값을 보고 있을 수 있다. 전후 값을 비교하려면 독립된 복사본이 필요하다.

---

### 이해 수정: 코드 한 줄이 맡은 역할

#### 처음 이해

- `nn.Linear(1, 1)` 자체를 연속적인 숫자를 학습하는 회귀모델로 봤다.
- `lr=0.1`이 표준 Learning Rate인지 궁금했다.
- `loss.backward()`가 MSE의 제곱·평균 계산도 함께 한다고 생각했다.

#### 수정된 이해

- `nn.Linear(1, 1)`은 입력 Feature 하나를 출력 하나로 바꾸는 레이어다. 이번에는 연속값 Target과 `MSELoss`를 함께 사용해서 회귀 문제로 다룬다.
- `0.1`은 표준값이 아니라, 이번 실습에서 Parameter 변화가 잘 보이도록 정한 하이퍼파라미터다.
- 제곱·평균을 포함한 MSE 계산은 `criterion(pred, y)`에서 끝난다. `backward()`는 **이미 계산한 Loss를 Parameter에 대해 미분**한다.

---

### 질문: Gradient는 하나의 값만 나오는가?

모델 전체에 하나만 나오는 것이 아니다. **Loss에 연결된 학습 Parameter의 요소마다 대응되는 Gradient가 하나씩 있다.**

이번 `nn.Linear(3, 2)` 예제에서 `backward()` 후 Shape는 다음과 같다.

| Parameter | Parameter Shape | Gradient Shape |
| --- | --- | --- |
| `weight` | `(2, 3)` | `weight.grad`: `(2, 3)` |
| `bias` | `(2,)` | `bias.grad`: `(2,)` |

즉 Loss를 Scalar 하나로 만들더라도, 미분 결과는 Weight 6개와 Bias 2개 각각에 대응해 저장된다. **Loss가 하나라는 것과 Gradient 값이 하나라는 것은 다르다.**

---

### 질문: `optimizer.zero_grad()`는 무엇을 초기화하는가?

Optimizer가 관리하는 Parameter들의 이전 `.grad`를 비운다. 이번에는 `model.weight.grad`, `model.bias.grad`에 남아 있는 Gradient가 대상이며, **Weight·Bias 자체를 초기화하는 것이 아니다.**

#### Gradient 누적 실습

같은 입력·Parameter 조건에서 Forward와 Loss를 다시 계산하고, 중간에 `zero_grad()` 없이 `backward()`를 하면 새 Gradient가 기존 `.grad`에 더해진다.

```python
optimizer.zero_grad()
loss = criterion(model(x), y)
loss.backward()
grad_after_first = model.weight.grad.detach().clone()

# Parameter는 그대로 두고 Forward와 Loss를 다시 계산한다.
loss = criterion(model(x), y)
loss.backward()
grad_after_second = model.weight.grad.detach().clone()
```

첫 번째 Gradient가 `-8`이고 두 번째 계산에서도 `-8`이 나오면 `.grad`에는 `-16`이 남는다. 새 값으로 덮어쓰는 것이 아니라 `-8 + -8`로 누적된 것이다.

위 코드에서는 두 `backward()` 사이에 `step()`도 실행하지 않아 Parameter를 그대로 유지한다. 일반적인 학습에서는 각 Step 시작 전에 `zero_grad()`로 비워 이번 Batch의 Gradient만 사용한다.
