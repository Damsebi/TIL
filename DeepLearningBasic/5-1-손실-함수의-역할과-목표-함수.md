# 손실 함수의 역할과 목표 함수

> 학습일: 2026-08-24

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

### Loss에서 Parameter Update까지의 흐름

Model은 입력으로 Prediction을 만들고 이를 Target과 비교해 Loss를 계산한다. Loss는 단순히 정답과 오답을 나누는 값이 아니라 Prediction이 Target에서 얼마나 벗어났는지를 학습 기준으로 표현한다.

```text
forward
→ loss 계산
→ backward()로 gradient 계산
→ optimizer.step()으로 parameter 변경
```

Scalar Loss가 만들어졌다고 Parameter가 바로 바뀌는 것은 아니다. `backward()`는 현재 Parameter에서 Loss가 변하는 방향과 변화율인 Gradient를 계산하고, `optimizer.step()`이 그 Gradient를 사용해 Weight와 Bias를 실제로 변경한다.

변경된 Weight와 Bias는 Model의 Parameter 자체에 저장되어 다음 Forward에 사용된다. Gradient는 각 Parameter의 `.grad`에 남아 기본적으로 누적되므로, 일반적인 학습에서는 다음 `backward()` 전에 `optimizer.zero_grad()`로 초기화한다.

### MSE와 Reduction

MSE는 Prediction과 Target의 차이를 제곱한 뒤 평균낸 손실 함수다.

$$
\mathrm{MSE}
=\frac{1}{N}\sum_{i=1}^{N}(\hat{y}_i-y_i)^2
$$

오차를 제곱하면 양수와 음수 오차가 서로 상쇄되지 않는다. 또한 모든 오차의 값이 무조건 커지는 것은 아니지만, 큰 오차가 작은 오차보다 상대적으로 더 큰 영향을 갖게 된다.

```python
manual_loss = ((pred - target) ** 2).mean()
```

`reduction`은 각 원소에서 계산된 Loss를 마지막에 어떻게 정리할지 결정한다.

| `reduction` | 결과 |
| --- | --- |
| `none` | 개별 Loss 유지 |
| `mean` | 개별 Loss의 평균 |
| `sum` | 개별 Loss의 합 |

평균은 여러 오차를 하나의 학습 목표로 만들지만, 평균 Loss가 줄어든다고 모든 Sample의 Loss가 동시에 줄어드는 것은 아니다.

### 손실 함수에 맞는 Prediction과 Target

Prediction과 Target의 Shape·Dtype은 사용하는 손실 함수의 규격에 맞춰야 한다.

| 손실 함수 | Prediction | Target |
| --- | --- | --- |
| `MSELoss` | 회귀 Prediction | 일반적으로 Prediction과 같은 Shape |
| `BCEWithLogitsLoss` | Raw Logit, 일반적으로 `[N, 1]` | 실수형 0 또는 1, Prediction과 같은 Shape |
| `CrossEntropyLoss` | Class별 Raw Logit, `[N, C]` | Class Index, `torch.long`, `[N]` |

`BCEWithLogitsLoss`와 `CrossEntropyLoss`는 Raw Logit을 직접 받으므로 일반적인 사용에서는 Model 출력에 `sigmoid()`나 `softmax()`를 미리 적용하지 않는다. 기본 `reduction='mean'`으로 계산한 Loss는 이후 미분에 사용할 실수형 Scalar Tensor가 된다.

## 2. 학습하며 겪었던 문제점과 해결 과정

### Gradient와 변경된 Parameter의 위치

#### 처음 이해

Weight와 Bias를 먼저 조금 변경해보고 이전 Loss와 새로운 Loss의 차이를 비교한 값이 Gradient라고 생각했다.

#### 해결 및 이해

Gradient는 Parameter를 실제로 변경한 결과가 아니다. 현재 Parameter가 조금 변할 때 Loss가 어느 방향으로 얼마나 변하는지를 나타내는 기울기다.

```text
backward()
→ gradient 계산

optimizer.step()
→ gradient를 사용해 weight와 bias 변경
```

---

#### 질문: 변경된 Weight와 Bias는 Sigmoid가 표현해주는 것인가?

아니다. Sigmoid는 계산 결과를 주로 `0~1` 범위로 변환하는 함수다. Optimizer가 변경한 Weight와 Bias를 저장하거나 표현하는 역할은 하지 않는다.

---

#### 질문: 변경된 Weight와 Bias는 Loss에 기록되는 것인가?

아니다. Weight와 Bias는 Model 내부 Parameter 자체가 새로운 값으로 변경되어 유지된다. Loss는 현재 Prediction과 Target을 비교해 얻은 평가값이며, 다음 Forward에서는 변경된 Parameter가 사용된다.

---

### Gradient 누적과 `zero_grad()`

`backward()`로 계산한 Gradient는 Optimizer가 사용한 뒤에도 Parameter의 `.grad`에 남는다. PyTorch는 Gradient를 기본적으로 누적하므로 일반적인 학습은 다음 순서로 작성한다.

```python
optimizer.zero_grad()
prediction = model(x)
loss = loss_fn(prediction, target)
loss.backward()
optimizer.step()
```

Gradient를 자동으로 지우지 않는 이유는 여러 Gradient를 의도적으로 누적하거나 계산된 값을 확인·수정할 수 있게 하기 위해서다.

---

### MSE의 부호와 제곱

#### 처음 이해

MSE에서 오차를 제곱하면 모든 오차의 숫자가 커지고, 오차의 방향도 Loss에 남는다고 생각했다.

#### 해결 및 이해

같은 크기의 양수와 음수 오차는 Target에서 떨어진 거리가 같다.

```text
target = 3

prediction = 2 → error = -1
prediction = 4 → error = +1
```

MSE에서는 두 오차가 제곱되어 같은 Loss에 기여하므로 Scalar Loss 자체에는 방향이 남지 않는다. 실제 수정 방향은 MSE를 미분해 얻은 Gradient에 나타난다.

```text
loss     → 얼마나 틀렸는가
gradient → 어느 방향으로 수정해야 하는가
```

제곱한다고 모든 오차의 숫자가 커지는 것도 아니다.

```text
0.5² = 0.25
2²   = 4
```

절댓값이 1보다 작은 오차는 제곱하면 작아진다. 핵심은 큰 오차가 작은 오차보다 상대적으로 더 큰 영향을 갖는다는 점이다.

---

#### 질문: Loss는 항상 양수만 나오는가?

MSE는 제곱값의 평균이므로 항상 0 이상이고, 0에 가까울수록 Prediction이 Target에 가깝다. 다만 모든 Custom Loss나 Objective가 반드시 0 이상이어야 하는 것은 아니다.

---

### 평균 Loss와 학습 방향

평균 Loss가 줄어도 모든 Sample의 Loss가 동시에 줄어드는 것은 아니다.

```text
[1, 4, 4] → 평균 3
[2, 2, 2] → 평균 2
```

전체 평균은 줄었지만 첫 번째 Sample의 Loss는 커졌다. 평균은 여러 데이터를 하나의 학습 목표로 정리하는 기준이며, 데이터 불균형이나 특정 오류의 중요도가 다른 문제에서는 Weighting, Sampling 또는 다른 Loss를 고려할 수 있다.

#### 이해한 내용

먼저 기본 설정으로 Model을 학습해 Baseline을 만들고 Validation 결과를 확인한 뒤 Loss, 데이터 처리, Optimizer 등을 조정하는 흐름으로 이해했다. 다만 데이터 불균형처럼 처음부터 명확한 문제는 첫 학습 전부터 반영할 수 있다.

---

#### 질문: Model 학습은 기본적으로 오래 걸리는가?

학습 시간은 Model과 데이터 규모에 따라 다르다. `forward → loss → backward → optimizer.step()` 과정이 많은 Batch와 Epoch에 걸쳐 반복되므로 Model과 데이터가 커질수록 계산량과 학습 시간이 늘어난다.

---

### Loss 함수의 호출과 입력 형식

#### 질문: Prediction과 Target의 Shape는 항상 같아야 하는가?

손실 함수에 따라 다르다. MSE 같은 회귀 Loss에서는 일반적으로 Shape를 맞추지만, `CrossEntropyLoss`는 다음과 같이 서로 다른 구조를 사용한다.

```text
prediction: [batch, num_classes]
target:     [batch]
```

따라서 두 Shape를 무조건 같게 만들기보다 사용하는 손실 함수가 요구하는 형식을 확인해야 한다.

---

#### 질문: MSE를 직접 계산하면서 `.mean()`을 사용해도 되는가?

가능하다. 직접 계산한다는 것은 `nn.MSELoss()`를 사용하지 않고 `오차 → 제곱 → 평균` 구조를 Tensor 연산으로 직접 작성한다는 뜻이다. `.mean()` 연산 자체를 다시 구현하라는 의미는 아니다.

---

#### 이해 수정: `nn.MSELoss()` 호출

처음에는 Prediction과 Target을 생성자에 바로 전달하려고 했다.

```python
loss = nn.MSELoss(pred, target)
```

실제로는 먼저 Loss 객체를 만든 뒤 그 객체에 Prediction과 Target을 전달한다.

```python
criterion = nn.MSELoss()
loss = criterion(pred, target)
```

한 줄로 작성한 `nn.MSELoss()(pred, target)`에서 첫 번째 `()`는 객체 생성이고 두 번째 `()`는 생성한 객체의 호출이다.

---

### 최소 Loss의 위치와 Scalar Tensor

#### 최소 Loss의 위치

`min()`은 최소값을 구하고 `argmin()`은 최소값이 있는 위치를 구한다.

```python
best_idx = torch.tensor(losses).argmin().item()
```

Python List의 `sort()`는 List 자체를 정렬하고 `None`을 반환하므로 원래 순서에서 최소값의 위치를 구하는 용도와 다르다.

---

#### 이해 수정: `tensor(1)`과 `.item()`

`argmin()`의 결과인 `tensor(1)`에서 `1`은 차원이 아니라 최소값이 있는 Index다. 이 결과는 0차원 Scalar Tensor이고, `.item()`을 호출하면 Tensor 안의 값을 Python 숫자로 꺼낼 수 있다.

```text
tensor(123)   → 0차원 Scalar Tensor
tensor([123]) → 원소 하나를 가진 1차원 Tensor
```

---

#### 이해 수정: `argmin()`과 `.item()`의 관계

처음에는 `.item()`이 `argmin()`에 속한 기능이라고 생각했다. 실제로는 두 메서드 모두 Tensor 객체가 가진 기능이다.

```text
Tensor
→ .argmin()
→ 결과 Tensor
→ 결과 Tensor에 .item()
```

`torch.tensor(losses).argmin().item()`은 앞 호출의 반환값에 다음 메서드를 연속해서 호출한 Method Chaining이다. 반면 `nn.MSELoss()(pred, target)`은 메서드를 연속 호출한 것이 아니라 객체를 생성한 뒤 그 객체 자체를 호출한 형태다.

---

### `BCEWithLogitsLoss`와 `CrossEntropyLoss`

#### 질문: 왜 `ce_loss`는 `long`이 아니라 `float`인가?

Target과 Loss의 역할이 다르기 때문이다.

```text
multi_target
→ 정답 Class Index
→ torch.long

ce_loss
→ 예측이 얼마나 틀렸는지를 나타내는 연속적인 값
→ Float Tensor
```

`BCEWithLogitsLoss`와 `CrossEntropyLoss`는 현재 실습에서 Raw Logit을 직접 받으므로 미리 `sigmoid()`나 `softmax()`를 적용하지 않는다.
