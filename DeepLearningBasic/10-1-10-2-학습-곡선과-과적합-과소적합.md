# 학습 곡선과 과적합·과소적합

> 학습일: 2026-08-27

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

Epoch별 Train Loss와 Validation Loss를 그린 것이 **Learning Curve(학습 곡선)**다. Train Loss만 낮추는 것이 목표가 아니라, 학습하면서 배운 패턴이 새로운 데이터에도 통하는지 함께 확인해야 한다.

두 곡선은 각각 얼마나 낮아지는지, 둘 사이의 차이인 `gap`이 어떻게 변하는지를 같이 본다.

| 곡선에서 보이는 흐름 | 해석 |
| --- | --- |
| Train·Validation Loss가 함께 감소하고 Gap도 지나치게 커지지 않음 | 학습과 일반화가 잘 진행되는 신호 |
| 둘 다 높고 충분히 감소하지 않음 | 현재 학습 데이터조차 충분히 배우지 못한 Underfitting(과소적합) 의심 |
| Train Loss는 계속 감소하지만 Validation Loss는 증가함 | 학습 데이터에 지나치게 맞춰지는 Overfitting(과적합) 의심 |

곡선의 높이나 Gap 하나만으로 단정하기보다 학습이 진행되면서 나타나는 추세를 본다. Train·Validation Loss를 직접 비교할 때는 같은 Loss 함수와 `reduction`, Epoch Loss 집계 기준을 맞추는 것이 중요하다.

과소적합에서는 학습이 아직 부족한지 확인하고, 과적합에서는 새로운 데이터에도 잘 적용되도록 만드는 방향을 고려한다. 실험 조건은 **한 번에 하나씩 변경**해야 어떤 변경이 효과가 있었는지 비교하기 쉽다.

## 2. 학습하며 겪었던 문제점과 해결 과정

### 질문: Generalization(일반화)이란?

학습할 때 보지 않았던 새로운 데이터에도 배운 내용을 잘 적용하는 능력이다.

고양이 사진 1,000장을 학습했다면, 그 사진들만 잘 맞히는 것으로는 부족하다. 처음 보는 고양이 사진에도 학습한 패턴이 통해야 한다.

```text
Train에서 배운 패턴
→ 처음 보는 데이터에도 적용
→ Generalization
```

Train에서는 매우 잘 맞히는데 Validation에서는 못 맞힌다면 과적합을 의심한다. Validation Loss는 **배운 것이 학습하지 않은 데이터에도 통하는지** 확인하기 위해 보는 값이라고 이해했다.

---

### 이해한 내용: Train Loss와 Validation Loss의 용도

둘 다 Prediction과 정답을 비교한 Loss지만, 계산한 뒤 사용하는 목적이 다르다.

```text
Train Loss
→ backward()로 Gradient 계산
→ optimizer.step()으로 Parameter 수정

Validation Loss
→ 현재 모델의 일반화 상태 확인
→ Parameter 수정에는 사용하지 않음
```

즉 Train Loss는 모델을 학습시키는 데 쓰고, Validation Loss는 현재 모델이 새로운 데이터에도 잘 적용되는지 판단하는 데 쓴다.

---

### 이해 수정: Accuracy와 Loss

처음에는 Accuracy가 Test 평가용이기 때문에 학습 곡선에서는 Loss를 사용한다고 생각했다.

Accuracy는 **Train·Validation·Test에서 모두 사용할 수 있는 지표**다. Loss를 중요하게 보는 이유는 Test와 구분하기 위해서가 아니라, 모델이 실제로 최소화하는 값이기 때문이다.

Accuracy는 맞힌 비율을 보지만, Cross Entropy 같은 Loss는 정답 여부가 그대로여도 예측 확률의 변화를 반영한다. 그래서 학습 상태를 더 세밀하게 볼 때 Loss Curve가 유용하다고 이해했다.

---

### 이해 수정: Underfitting과 데이터 증가

처음에는 과소적합을 해결하려면 학습 데이터를 더 늘려야 한다고 생각했다.

과소적합은 Train Loss도 충분히 낮아지지 않아 **현재 데이터조차 충분히 배우지 못한 상태**다. 학습이 아직 부족한 경우라면 우선 더 학습시키는 방향을 고려한다. 다만 학습 횟수 부족이 원인이 아닐 수도 있으므로 Epoch를 늘리는 것만으로 항상 해결되는 것은 아니다.

반면 데이터 증가나 Data Augmentation은 Train 데이터에 지나치게 맞춰진 **과적합을 완화하는 방법**으로 사용할 수 있다고 구분했다.

---

### 이해한 내용: Overfitting 대응

과적합이 보이면 다음 방법들을 고려할 수 있다.

- **Dropout**: 특정 뉴런이나 특징 조합에 지나치게 의존하는 것을 줄인다.
- **Early Stopping**: Validation Loss가 개선되지 않는 상태가 일정 횟수 지속되면 학습을 멈춘다.
- **모델 복잡도 감소**: Train 데이터를 지나치게 외우는 것을 완화한다.
- **데이터 증가·Data Augmentation**: 더 다양한 데이터를 학습하게 해 특정 Train 데이터에 대한 의존을 줄인다.

여러 방법을 동시에 적용하면 무엇 때문에 결과가 달라졌는지 알기 어렵다. 따라서 한 번에 하나씩 바꾸고 Train·Validation 곡선이 어떻게 달라지는지 확인한다고 이해했다.

---

### 이해한 내용: Validation과 Test의 구분

```text
Train
→ Parameter 학습

Validation
→ 학습 중 모델 상태 확인과 모델·설정 선택

Test
→ 학습과 모델 선택이 끝난 뒤 최종 성능 평가
```

학습 곡선을 보면서 모델을 바꾸거나 멈출 시점을 판단하는 데 사용하는 것은 Validation이다. Test는 이런 선택을 모두 마친 뒤 최종 성능을 확인하는 용도로 남겨둔다.
