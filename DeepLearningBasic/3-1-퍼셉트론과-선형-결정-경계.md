# 퍼셉트론과 선형 결정 경계

> 학습일: 2026-08-20

## 핵심 정리

퍼셉트론은 입력 Feature에 Weight를 곱해 더하고 Bias를 추가해 하나의 Score `z`를 만든다. 이 Score는 확률이 아니며, 이번 실습에서는 `z > 0`인지에 따라 Class를 결정했다.

`points`의 각 행은 Weight가 섞여 있는 값이 아니라 하나의 입력 데이터 `[x_1, x_2]`다. Weight는 별도의 벡터 `w`에 있으며, `points @ w + b`로 모든 Point의 Score를 한 번에 계산할 수 있다.

Bias가 달라지면 모든 Score와 결정 경계의 위치가 바뀐다. 하지만 Score가 0이라는 기준을 넘지 않으면 최종 Class는 그대로일 수 있다.

> 결국 Weight와 Bias는 Score와 결정 경계를 바꾸지만, Class가 실제로 바뀌는지는 데이터가 결정 경계의 반대편으로 넘어갔는지를 봐야 한다.

---

## 퍼셉트론의 기본 계산

퍼셉트론은 입력값에 Weight를 곱해 모두 더한 뒤 Bias를 추가하여 하나의 Score `z`를 만든다.

$$
z=x_1w_1+x_2w_2+b
$$

각 기호의 의미는 다음과 같다.

```text
x
→ 입력 데이터

w
→ 각 입력에 적용되는 Weight

b
→ Bias

z
→ 퍼셉트론이 계산한 Score
```

`z`는 확률이 아니라 계산된 점수다.

이번 실습에서는 다음 기준으로 Class를 결정했다.

```text
z > 0
→ Class 1

그 외
→ Class 0
```

---

## `points`의 의미

### 한 Point의 두 값은 입력과 Weight일까?

다음 Tensor를 보고 한 Point의 첫 번째 값이 `x_1`이고 두 번째 값이 `w_1`인지 혼동했다.

```python
points = torch.tensor([
    [1.0, 1.0],
    [2.0, 1.0],
    [-1.0, -1.0],
    [-2.0, -1.0]
])
```

처음에는 `[1.0, 1.0]`을 `x_1`과 `w_1`처럼 생각해 두 값을 서로 곱하려고 했다.

```python
points[0, 0] * points[0, 1]
```

다음처럼 두 값을 꺼내 행렬곱을 해야 하는지도 고민했다.

```python
for i, j in points:
    i @ j
```

하지만 `points` 안에는 Weight가 들어 있지 않다. 각 행 전체가 하나의 입력 데이터이고, 두 값은 입력 Feature `x_1`과 `x_2`다.

```text
[ 1.0,  1.0] → x₁ =  1.0, x₂ =  1.0
[ 2.0,  1.0] → x₁ =  2.0, x₂ =  1.0
[-1.0, -1.0] → x₁ = -1.0, x₂ = -1.0
[-2.0, -1.0] → x₁ = -2.0, x₂ = -1.0
```

Weight와 Bias는 별도의 Tensor에 들어 있다.

```python
w = torch.tensor([0.5, 1.0])
b = torch.tensor(0.2)
```

Point 하나에 대한 계산은 다음과 같다.

$$
\begin{bmatrix}
x_1 & x_2
\end{bmatrix}
\begin{bmatrix}
w_1 \\
w_2
\end{bmatrix}
=x_1w_1+x_2w_2
$$

여기에 Bias `b`를 더하면 최종 Score `z`가 된다.

---

## 여러 Point를 한 번에 계산하기

### Point마다 반복문을 사용해야 할까?

처음에는 Point를 `for`문으로 하나씩 꺼내 계산해야 하는지 고민했다.

`points`와 `w`의 Shape는 다음과 같다.

```text
points = (4, 2)
w      = (2,)
```

행렬·벡터 곱을 사용하면 네 Point의 Score를 한 번에 계산할 수 있다.

```python
scores = points @ w + b
```

이 연산은 `points`의 각 행마다 다음 계산을 수행한다.

$$
x_1w_1+x_2w_2+b
$$

결과 `scores`에는 Point 4개의 Score가 들어가므로 Shape는 `(4,)`다.

---

## `scores`의 의미

### `scores`는 Weight나 Bias일까?

다음 초기 코드를 보고 `scores` 자체가 `w`나 `b`의 역할을 하는 값인지 혼동했다.

```python
scores = torch.zeros(len(points))
```

`scores`는 Weight도 Bias도 아니다. 각 Point에 대해 퍼셉트론이 계산한 최종 Score `z`를 담는 변수다.

```text
points
→ Weight 적용
→ Bias 추가
→ scores
→ Class 예측
```

`torch.zeros(len(points))`는 정답 계산이 아니라 Score가 들어갈 자리를 0으로 미리 만든 초기 코드였다.

실제 계산을 대입하면 기존 값은 덮어쓰게 된다.

```python
scores = points @ w + b
```

---

## Class 예측

Score를 계산한 뒤 다음 코드로 Class를 예측했다.

```python
scores = points @ w + b

pred = (scores > 0).long()
print("pred:", pred.tolist())
```

`scores > 0`은 각 Score가 0보다 큰지 검사한다.

```text
True
→ 1

False
→ 0
```

`.long()`은 Boolean 값을 정수 `0`과 `1`로 바꾼다.

전체 흐름은 다음과 같다.

```text
Point [x₁, x₂]
→ x₁w₁ + x₂w₂ + b
→ Score z
→ z > 0인지 확인
→ Class 0 또는 1
```

## Bias 변화와 예측 결과

### Bias를 바꿨는데 왜 Class가 그대로일까?

다음 실습에서 Bias를 바꿨는데도 예측 Class가 같았다.

```python
bias_values = [-1.0, 0.0, 1.0]

for bias in bias_values:
    score = points @ w + bias
    pred = (score > 0).long()
    print("bias=", bias, "pred=", pred.tolist())
```

처음에는 작은 Bias는 Score에 영향을 거의 주지 않는다고 생각했다.

하지만 예측 Class가 같다고 해서 Bias가 Score에 영향을 주지 않은 것은 아니다. Bias가 바뀌면 모든 Score도 실제로 달라진다.

최종 Class는 Score가 0보다 큰지만 보기 때문에 Score가 변해도 0이라는 기준을 넘지 않으면 Class는 유지된다.

`w=[0.5, 1.0]`일 때 Bias를 제외한 Score는 다음과 같다.

```text
[ 1,  1] →  1.5
[ 2,  1] →  2.0
[-1, -1] → -1.5
[-2, -1] → -2.0
```

Bias가 `-1`이면 다음과 같다.

```text
scores = [0.5, 1.0, -2.5, -3.0]
pred   = [1, 1, 0, 0]
```

Bias가 `0`이면 다음과 같다.

```text
scores = [1.5, 2.0, -1.5, -2.0]
pred   = [1, 1, 0, 0]
```

Bias가 `1`이면 다음과 같다.

```text
scores = [2.5, 3.0, -0.5, -1.0]
pred   = [1, 1, 0, 0]
```

Score 자체는 계속 변했지만 모든 Point가 기존과 같은 결정 경계 쪽에 있었기 때문에 Class는 바뀌지 않았다.

예를 들어 어떤 Score가 `-0.5`에서 `0.2`로 변해 0을 넘으면 Class도 바뀐다.

```text
Score
-0.5 → 0.2

Class
0 → 1
```

---

## Bias와 선형 결정 경계

결정 경계는 Score `z`가 0인 지점이다.

이번 Weight를 사용하면 다음 식이 결정 경계가 된다.

$$
0.5x_1+x_2+b=0
$$

`x_2`에 대해 정리하면 다음과 같다.

$$
x_2=-0.5x_1-b
$$

Bias `b`가 변하면 직선의 위치가 이동한다.

```text
Bias 변경
→ 모든 Point의 Score 변경
→ 결정 경계 위치 변경
```

하지만 결정 경계가 이동해도 데이터가 경계 반대편으로 넘어가지 않으면 최종 예측은 그대로일 수 있다.

> Bias 변화가 Score와 결정 경계를 바꾸는 것은 맞지만, 반드시 Class까지 바꾸는 것은 아니다.

---

## 다시 볼 때 핵심

`points`의 각 행은 하나의 입력 데이터이며 두 값은 `x_1`과 `x_2`다. Weight는 별도의 벡터 `w`에 있다.

`points @ w + b`를 사용하면 모든 Point의 Score를 한 번에 계산할 수 있다.

`scores`는 Weight나 Bias가 아니라 각 Point에서 계산된 `z`를 모아둔 결과다.

이번 실습에서는 `z > 0`이면 Class 1, 그 외에는 Class 0으로 분류했다.

Bias를 바꾸면 Score와 선형 결정 경계의 위치가 바뀐다. 하지만 Score가 0을 넘지 않으면 최종 Class는 유지될 수 있다.
