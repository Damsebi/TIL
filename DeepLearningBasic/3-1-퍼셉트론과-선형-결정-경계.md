## 2. 오늘 학습한 내용을 나만의 언어로 정리하기

### 퍼셉트론의 계산

퍼셉트론은 입력 `x`에 Weight `w`를 적용하고 Bias `b`를 더해 하나의 Score `z`를 만든다. 코드에서는 `z = x @ w + b`로 계산할 수 있다.

$$
z=\mathbf{x}^{\mathsf{T}}\mathbf{w}+b
$$

입력 Feature가 두 개라면 다음과 같이 풀어 쓸 수 있다.

$$
z=x_1w_1+x_2w_2+b
$$

`z`는 확률이 아니라 분류에 사용하는 Score다. 이번 실습에서는 `z > 0`이면 Class `1`, 그렇지 않으면 `0`으로 판단했다.

### 여러 Sample의 Score 계산

여러 입력이 `(Sample 수, Feature 수)` Shape의 `points`에 들어 있다면 행렬·벡터 연산으로 모든 Score를 한 번에 계산할 수 있다.

```python
scores = points @ w + b
```

`@`는 `points`의 각 행 `[x1, x2]`와 Weight `[w1, w2]`의 내적을 계산한다.

### Bias와 선형 결정 경계

선형 결정 경계는 `z = 0`이 되는 지점이며 입력 Feature가 두 개인 공간에서는 직선으로 나타난다.

Bias를 변경하면 모든 Score와 결정 경계의 위치가 변한다. 하지만 Score가 분류 기준인 `0`을 넘지 않으면 최종 Class는 그대로일 수 있다.

```text
bias 변화
→ score 변화
→ 결정 경계 이동
→ point가 경계를 넘어간 경우에만 class 변화
```

## 3. 학습하며 겪었던 문제점과 해결 과정

### 이해 수정: `points`·`w`·`scores`의 의미

#### 처음 이해

`points`의 한 행 `[1., 1.]`에서 첫 번째 값이 `x1`이고 두 번째 값이 `w1`인지 혼동했다.

#### 수정된 이해

`points`의 각 행은 하나의 입력이고, Weight와 Bias는 별도로 정의된다.

```text
[x1, x2] = 하나의 입력 point
[w1, w2] = 별도로 정의된 weight
b        = bias
scores   = 각 point에서 계산된 z 값
```

따라서 `points` 안의 두 값을 서로 곱하는 것이 아니라 각 Point와 Weight를 사용해 다음 계산을 한다.

```text
z = x1*w1 + x2*w2 + b
```

`scores = torch.zeros(len(points))`는 Weight나 Bias가 아니라 실습에서 계산 결과를 채워 넣기 위해 임시로 만든 Tensor였다.

---

### 질문: 여러 Point를 계산할 때 `for`문을 사용해야 하는가?

`for x1, x2 in points`처럼 하나씩 계산할 수도 있지만 행렬·벡터 연산으로 모든 Point의 Score를 한 번에 구할 수 있다.

```python
scores = points @ w + b
```

`@`는 각 Point와 Weight의 내적을 계산하므로 반복문으로 작성한 퍼셉트론 계산과 같은 역할을 한다.

---

### 이해 수정: Bias가 변해도 예측 결과가 같았던 이유

#### 처음 이해

Bias 값이 작으면 결과에 큰 영향을 주지 않아서 예측 Class가 같다고 생각했다.

#### 수정된 이해

Bias가 바뀌면 Score 자체와 결정 경계는 실제로 변한다. 하지만 이번 분류 기준은 `score > 0`이므로 Score가 변해도 `0`을 넘어가지 않으면 Class는 바뀌지 않는다.

Bias의 절대적인 크기만 보는 것이 아니라 Point가 변경된 결정 경계의 반대편으로 넘어갔는지를 확인해야 한다.
