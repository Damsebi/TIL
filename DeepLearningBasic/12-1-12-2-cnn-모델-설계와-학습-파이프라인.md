# CNN 모델 설계와 학습 파이프라인

> 학습일: 2026-08-31

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

### 입력과 출력 Shape부터 정하기

CNN 모델을 만들 때는 레이어부터 쌓기보다 **입력 이미지와 최종 출력의 Shape를 먼저 정한다.**

CIFAR-10 이미지는 RGB 32×32 이미지이므로 입력 batch는 다음과 같다.

```text
(N, 3, 32, 32)
 ↑  ↑   ↑   ↑
batch C   H   W
```

따라서 첫 번째 `Conv2d`의 `in_channels`는 `3`이어야 한다. CIFAR-10의 정답 후보는 10개이므로 마지막 `Linear`는 샘플마다 class 점수 10개를 만들고, 최종 logits의 Shape는 `(N, 10)`이 된다.

```text
입력 이미지
→ Conv2d → ReLU → MaxPool2d
→ Conv2d → ReLU → MaxPool2d
→ Flatten
→ Linear
→ class별 logits
```

CNN이 깊어질수록 H와 W는 줄이고 channel 수는 늘리는 구성을 자주 사용한다. 다만 이것이 고정 규칙은 아니므로, 처음에는 작은 baseline 모델로 시작하고 train·validation 결과를 보며 channel이나 layer를 늘린다.

### 학습 전에 Shape 확인하기

학습을 시작하기 전에 DataLoader에서 batch 하나를 꺼내 입력, 정답, 모델 출력의 Shape를 먼저 확인한다.

```text
images.shape = (64, 3, 32, 32)
labels.shape = (64,)
logits.shape = (64, 10)
```

`nn.Linear(in_features, out_features)`의 숫자에는 batch size를 넣지 않는다. 마지막 feature map을 펼친 크기가 `2048`이라면 `nn.Linear(2048, 10)`으로 연결하고, batch가 16개일 때 Shape는 `(16, 2048) → (16, 10)`으로 바뀐다.

### Dataset부터 Validation까지 연결하기

이번에는 앞에서 따로 배운 데이터 처리와 학습 코드를 CNN 하나의 흐름으로 연결했다.

```text
Dataset 생성 및 transform 지정
→ DataLoader가 샘플 요청
→ Dataset이 transform을 적용해 샘플 반환
→ DataLoader가 샘플들을 batch로 묶음
→ CNN이 logits 생성
→ CrossEntropyLoss로 loss 계산
→ backward()
→ optimizer.step()
→ validation으로 현재 성능 확인
```

다중 분류 학습에서는 모델의 raw logits를 `CrossEntropyLoss`에 그대로 전달하므로 모델 끝에 Softmax를 직접 붙이지 않는다.

원래 train Dataset의 일부를 validation으로 분리해 학습 중 모델을 확인하고, test Dataset은 모델과 설정을 모두 선택한 뒤 최종 평가에 사용한다.

## 2. 학습하며 겪었던 문제점과 해결 과정

### 질문: Conv는 무엇인가?

`Conv`는 Convolution의 줄임말이다. 작은 kernel이 이미지의 지역 영역을 훑으면서 특정 패턴에 얼마나 강하게 반응하는지 계산하고, 그 결과로 feature map을 만든다.

---

### 질문: Layer가 많아도 Channel 수가 작으면 괜찮은가?

Channel 수를 작게 두면 각 단계에서 다루는 feature 수와 parameter 부담을 줄일 수 있다. 하지만 layer가 많아지면 연산 단계와 중간 activation이 늘어나므로 계산량과 메모리 사용량은 여전히 커질 수 있다.

```text
channel 증가
→ 한 단계에서 다루는 feature 종류 증가

layer 증가
→ 앞에서 찾은 feature를 여러 단계에 걸쳐 다시 조합
```

따라서 layer가 많고 channel이 작다고 무조건 가벼운 모델은 아니며, baseline의 성능과 비용을 확인하면서 조정해야 한다.

---

### 질문: Linear의 Shape와 CIFAR-10의 출력 10은 어떻게 연결되는가?

`Linear`는 batch를 제외한 feature 차원만 변환한다.

```text
(16, 2048)
→ Linear(2048, 10)
→ (16, 10)
```

여기서 `10`은 CIFAR-10의 class 수다. 샘플마다 10개 class에 대한 점수를 하나씩 출력하므로 batch가 64개라면 logits는 `(64, 10)`이 된다.

---

### 이해 수정: Feature와 Class

#### 처음 이해

CNN이 학습한 feature 하나가 곧 최종 class가 된다고 생각했다.

#### 수정된 이해

Feature는 이미지를 구분하기 위해 CNN이 중간에서 찾아낸 특징이고, class는 모델이 최종적으로 고를 정답 후보이다.

```text
CNN
→ 이미지에서 여러 feature 추출
→ Linear가 feature들을 class별 점수로 변환
→ logits와 실제 label을 비교해 학습
```

즉 CNN은 판단에 사용할 **단서**를 만들고, classifier는 그 단서로 각 class의 점수를 만든다고 이해했다.

---

### 질문: ReLU도 학습하는가?

ReLU도 forward와 backward 흐름에 참여하지만, Conv나 Linear처럼 학습되는 weight와 bias는 없다.

```text
Conv2d / Linear
→ 학습할 parameter 있음

ReLU
→ 학습할 parameter 없음
→ 값에 비선형성을 주고 gradient가 흐르는 방식에는 영향
```

---

### 이해한 내용: Forward·Backward와 Chain Rule

Forward에서는 모델이 logits를 만들고 loss function이 정답과 비교해 loss를 계산한다. `backward()`는 loss에서 앞쪽 연산으로 거슬러 올라가며 Chain Rule로 각 parameter의 gradient를 계산한다.

$$
\frac{\partial L}{\partial x}
=
\frac{\partial L}{\partial z}
\frac{\partial z}{\partial x}
$$

이때 parameter는 아직 바뀌지 않는다. 실제 수정은 `optimizer.step()`에서 일어난다.

$$
w \leftarrow w - \eta \frac{\partial L}{\partial w}
$$

---

### 이해 수정: Dataset·Transform·DataLoader의 순서

처음에는 DataLoader가 Dataset 전체를 먼저 변환해 가지고 있는 것으로 생각했다. 또한 `Normalize`를 평준화라고 표현했다.

정확히는 Dataset을 만들 때 transform을 지정해 두고, DataLoader가 필요한 index의 샘플을 요청하면 Dataset이 그 샘플에 transform을 적용해 반환한다. DataLoader는 반환된 여러 샘플을 batch로 묶는다.

`Normalize`는 **정규화**라고 부른다.

---

### 이해한 내용: Train·Validation·Test와 DataLoader

```text
Train
→ parameter 학습

Validation
→ 학습 중 모델과 설정 확인

Test
→ 모든 선택이 끝난 뒤 최종 평가
```

Train loader는 보통 `shuffle=True`, validation과 test loader는 `shuffle=False`로 사용한다. `batch_size=64`이면 이미지와 label은 각각 `(64, 3, 32, 32)`, `(64,)` 형태로 나온다.

Test 결과를 보고 모델이나 설정을 계속 바꾸면 test가 사실상 validation 역할을 하게 되므로 두 용도를 구분한다.

---

### 질문: Logits와 Label은 Shape가 다른데 어떻게 비교하는가?

CIFAR-10에서 logits `(64, 10)`에는 샘플마다 class 점수 10개가 있고, labels `(64,)`에는 각 샘플의 정답 class index 하나가 있다.

```text
logits[0] = class 10개의 점수
labels[0] = 첫 번째 샘플의 정답 class 번호
```

`CrossEntropyLoss`가 각 샘플의 정답 class에 해당하는 logit을 기준으로 loss를 계산한다. 모델 출력에는 Softmax를 미리 적용하지 않는다.

---

### 이해 수정: `zero_grad()`, `no_grad()`, `eval()`

처음에는 세 기능이 모두 gradient를 끄는 비슷한 역할이라고 생각했다.

```text
optimizer.zero_grad()
→ 이전 backward에서 parameter.grad에 누적된 gradient를 비움

torch.no_grad()
→ 블록 안에서 Autograd 추적을 끔

model.eval()
→ Dropout·BatchNorm 등을 평가 방식으로 전환
```

따라서 validation에서는 `model.eval()`과 `torch.no_grad()`를 함께 사용하지만, `zero_grad()`는 일반적으로 새 학습 batch의 `backward()` 전에 사용한다.

---

### 질문: `zero_grad()`는 언제 실행하는가?

핵심은 다음 `backward()`가 실행되기 전에 이전 gradient를 비우는 것이다. 보통 매 batch의 시작 부분에 두어 순서를 일정하게 유지한다.

```text
zero_grad()
→ forward
→ loss
→ backward()
→ optimizer.step()
```
