# Batch Dimension과 Broadcasting

> 학습일: 2026-08-19

## 핵심 정리

학생 한 명의 Feature가 4개인 1차원 Tensor의 Shape는 `(4,)`다. 뒤의 쉼표는 Python에서 원소가 하나인 Tuple을 나타내는 문법이지 새로운 차원을 뜻하지 않는다.

`unsqueeze`는 크기가 1인 차원을 지정한 위치에 추가하고, `squeeze`는 크기가 1인 차원을 제거한다. 아무 위치에 사용하는 것이 아니라 다음 연산에서 필요한 Shape를 먼저 생각해야 한다.

Broadcasting은 서로 다른 Shape를 일정한 규칙에 따라 자동으로 맞춰 계산하는 기능이다. 편리하지만 Shape가 잘못되어도 오류 없이 의도하지 않은 계산이 실행될 수 있다.

> 결국 계산이 실행됐다는 사실만 믿으면 안 된다. 연산 전에 Shape를 확인하고, 오른쪽부터 Broadcasting 규칙을 비교한 뒤, 실제로 원한 데이터끼리 계산되는지 확인해야 한다.

---

## Batch Dimension과 Shape 표기

### Feature가 4개라면 왜 `(4,)`일까?

처음에는 학생 한 명의 Feature가 4개라면 Shape를 `4`나 `(, 4)`처럼 표현할 수 있을 것으로 생각했다.

`(4,)`의 쉼표를 별도의 차원 정보로 받아들인 것이 혼동의 원인이었다.

`(4,)`는 길이가 4인 1차원 Tensor다. 뒤의 쉼표는 Python에서 원소가 하나인 Tuple을 표현하기 위한 문법이며 새로운 차원을 의미하지 않는다.

`(, 4)` 같은 Shape 표기는 존재하지 않는다.

일반적인 2차원 표 데이터는 다음처럼 읽는다.

```text
(batch_size, features)
```

예를 들어 Shape가 `(2, 4)`라면 학생이 2명이고 학생마다 Feature가 4개 있다는 뜻이다.

```text
학생 한 명을 1차원 Tensor로 표현
→ (4,)

학생 한 명을 Batch 형태로 표현
→ (1, 4)

학생 두 명을 Batch 형태로 표현
→ (2, 4)
```

---

## 이미지 데이터의 Batch Dimension

PyTorch에서 이미지 Batch는 일반적으로 다음 형태로 표현한다.

```text
(N, C, H, W)

N = Batch Size
C = Channels
H = Height
W = Width
```

`(32, 3, 224, 224)`는 RGB 이미지 32장이 있고 각 이미지의 높이와 너비가 `224 × 224`라는 뜻이다.

이미지 한 장의 Shape가 `(3, 224, 224)`라면 Batch 차원을 추가해 다음처럼 만들 수 있다.

```text
(3, 224, 224)
→ (1, 3, 224, 224)
```

## `unsqueeze`

### `unsqueeze(0)`을 하면 `(4, 1)`이 될까?

처음에는 `0`과 `1`이 추가되는 차원의 크기나 방향을 뜻한다고 생각했다. `unsqueeze(1)`을 전치처럼 이해하기도 했다.

하지만 `unsqueeze`의 인자는 새 차원의 크기가 아니라 크기 1인 새 차원을 넣을 위치다.

```text
(4,)
↓ unsqueeze(0)
(1, 4)
```

```text
(4,)
↓ unsqueeze(1)
(4, 1)
```

```text
unsqueeze(0)
→ 0번째 위치에 차원 추가

unsqueeze(1)
→ 1번째 위치에 차원 추가
```

학생 한 명의 Feature 4개를 Batch 형태로 만들려면 `(4,) → (1, 4)`가 필요하다.

```python
sample = sample.unsqueeze(0)
```

반대로 `(4, 1)` 구조가 필요하다면 다음처럼 사용한다.

```python
sample = sample.unsqueeze(1)
```

### `unsqueeze(1)`은 전치일까?

아니다.

`(4,)`은 1차원이므로 아직 행 벡터나 열 벡터 형태로 구분된 2차원 구조가 아니다.

```text
(4,) → unsqueeze(1) → (4, 1)
```

위 연산은 새 차원을 추가한 것이다.

전치는 이미 존재하는 두 차원의 위치를 바꾸는 연산이다.

```text
(1, 4) → transpose → (4, 1)
```

### 학습 중 헷갈렸던 부분

`(4,).unsqueeze(1)`의 결과를 `(1, 4)`라고 한 번 잘못 선택했다.

정답은 `(4, 1)`이다.

`unsqueeze`의 인덱스가 크기가 아니라 새 차원이 들어갈 위치라는 점은 추가 반복이 필요하다.

---

## `unsqueeze` 위치를 잘못 사용하면 어떻게 될까?

값 자체가 같더라도 Shape가 달라지면 모델이 데이터를 다르게 해석할 수 있다.

원래 의도가 학생 1명과 Feature 4개라면 Shape는 `(1, 4)`여야 한다.

실수로 `(4, 1)`을 만들면 학생 4명과 각 학생의 Feature 1개처럼 전혀 다른 구조로 해석될 수 있다.

`unsqueeze`를 사용하기 전에는 다음을 먼저 생각해야 한다.

> 어떤 의미의 차원을 어느 위치에 새로 만들고 싶은가?

---

## `squeeze`

### 계산하기 전에 크기가 1인 차원을 모두 없애는 게 좋을까?

처음에는 계산하기 편하도록 불필요해 보이는 차원을 미리 제거하는 것이 좋다고 생각했다.

하지만 Batch 차원처럼 크기가 1이어도 실제 의미가 있는 차원이 있다. 무조건 `squeeze`하면 필요한 구조까지 사라질 수 있다.

`squeeze`는 크기가 1인 차원을 제거한다.

```text
(1, 4)
↓ squeeze(0)
(4,)
```

`unsqueeze`와 반대 방향으로 생각할 수 있다.

```text
(4,) → unsqueeze(0) → (1, 4)
(1, 4) → squeeze(0) → (4,)
```

인자 없이 사용하면 크기가 1인 차원이 모두 제거될 수 있다.

```text
(1, 1, 4)
↓ squeeze()
(4,)
```

필요하다면 제거할 위치를 지정한다.

```python
x = x.squeeze(0)
```

올바른 순서는 다음과 같다.

```text
현재 Shape 확인
→ 다음 연산에 필요한 Shape 확인
→ 필요할 때만 squeeze 또는 unsqueeze
→ 계산
```

## Bias와 Shape

### Bias는 무엇이고 왜 `b`라고 쓸까?

Bias는 계산 결과를 이동시키는 편향값 또는 보정값이고, `b`는 Bias의 첫 글자에서 가져온 표기다.

```text
WX + b

X = 입력
W = Weight
b = Bias
```

예를 들어 입력이 2, Weight가 3, Bias가 10이면 출력은 16이다.

```text
2 × 3 + 10 = 16
```

Bias가 없으면 `y = 3x`처럼 원점을 지나지만, Bias가 있으면 `y = 3x + 10`처럼 전체 관계를 이동시킬 수 있다.

### Bias의 개수가 부족하면 0을 추가해도 될까?

처음에는 Padding에서 0을 채우듯 Bias에도 부족한 값을 0으로 추가해 Shape를 맞추면 된다고 생각했다.

하지만 출력 Feature가 4개라면 Bias도 원래부터 다음처럼 4개가 대응되는 것이 정상이다.

```text
[b1, b2, b3, b4]
```

네 번째 Bias가 설계나 학습 결과에 따라 실제로 0인 것은 문제가 아니다.

```text
[b1, b2, b3, 0]
```

반면 Bias가 원래 3개뿐인데 Shape 오류를 없애려고 임의로 0을 붙이는 것은 구조상의 문제를 숨길 수 있다.

```text
Shape Mismatch 발생
→ 임의의 0 추가
→ 오류의 원인을 숨길 수 있음
```

Padding에서 0을 넣는 것은 알고리즘에서 의도한 연산이므로 Bias의 Shape 오류를 억지로 맞추는 것과는 다르다.

## Broadcasting의 기본 개념

Broadcasting은 서로 다른 Shape의 Tensor를 연산할 때 규칙을 만족하면 PyTorch가 자동으로 크기를 맞춰 계산하는 기능이다.

다음 연산을 생각해보자.

```text
x    = (2, 3)
bias = (3,)

(2, 3) + (3,)
```

Bias가 각 행에 반복 적용되는 것처럼 계산된다.

```text
x =
[1, 2, 3]
[4, 5, 6]

bias =
[10, 20, 30]

결과 =
[11, 22, 33]
[14, 25, 36]
```

Bias를 직접 `(2, 3)`으로 복사하지 않아도 Broadcasting이 계산을 처리한다.

## Broadcasting과 Feature 수

### 결국 Feature 수가 같아야 할까?

현재 자주 보는 다음 형태에서는 마지막 Feature 수가 맞아야 한다.

```text
(batch_size, features) + (features,)
```

```text
(10, 4) + (4,)
→ 가능

(10, 4) + (3,)
→ 불가능
```

하지만 Broadcasting의 전체 규칙은 단순히 Feature 수만 비교하는 것이 아니다.

각 차원은 다음 조건 중 하나를 만족해야 한다.

```text
두 크기가 같음
또는
둘 중 하나가 1
또는
한쪽에 해당 차원이 없음
```

---

## Broadcasting 규칙

Broadcasting은 Shape를 오른쪽부터 비교한다.

```text
x = (2, 3, 4)
y =    (3, 1)
```

짧은 쪽 Shape 앞에 크기 1인 차원이 있다고 생각할 수 있다.

```text
x = (2, 3, 4)
y = (1, 3, 1)
```

오른쪽부터 비교하면 다음과 같다.

```text
4와 1
→ 하나가 1이므로 가능

3과 3
→ 같으므로 가능

2와 1
→ 하나가 1이므로 가능
```

결과 Shape는 `(2, 3, 4)`가 된다.

```text
같음
→ 가능

한쪽이 1
→ 가능

한쪽 차원이 없음
→ 가능

그 외
→ 불가능
```

## Broadcasting 실패 사례

다음 두 Tensor를 더한다고 하자.

```text
x = (2, 3)
y = (2,)
```

`y`를 오른쪽 기준으로 맞추면 다음과 같다.

```text
x = (2, 3)
y = (1, 2)
```

마지막 차원 `3`과 `2`가 다르고 어느 쪽도 1이 아니므로 Broadcasting에 실패한다.

행마다 하나의 값을 더하려는 의도였다면 `y`를 `(2, 1)`로 만들어야 한다.

```python
y = y.unsqueeze(1)
```

```text
(2, 3)
(2, 1)

오른쪽부터 비교
3과 1 → 가능
2와 2 → 가능

결과 = (2, 3)
```

---

## 의도하지 않은 Broadcasting

### `pred=(4, 1)`, `target=(4,)`이면 어떻게 될까?

처음에는 Sample 수가 둘 다 4이므로 같은 위치끼리 계산될 것처럼 보였다.

하지만 Broadcasting에서는 `target=(4,)`가 오른쪽에 맞춰져 `(1, 4)`처럼 취급된다.

```text
pred   = (4, 1)
target = (1, 4)

결과   = (4, 4)
```

원했던 계산은 다음과 같은 1:1 대응이다.

```text
예측 1 - 정답 1
예측 2 - 정답 2
예측 3 - 정답 3
예측 4 - 정답 4
```

Target에 두 번째 차원을 추가하면 의도한 Shape가 된다.

```python
target = target.unsqueeze(1)
```

```text
target
(4,) → (4, 1)

pred   = (4, 1)
target = (4, 1)
```

이제 같은 위치끼리 계산할 수 있다.

> Broadcasting에서 가장 위험한 점은 코드가 실행됐다고 해서 계산까지 올바르다는 보장이 없다는 것이다.

## Shape 검증

중요한 연산 전에는 Shape를 직접 확인하는 습관이 필요하다.

```python
print(pred.shape)
print(target.shape)
```

두 Tensor의 Shape가 반드시 같아야 하는 연산이라면 다음처럼 검사할 수 있다.

```python
assert pred.shape == target.shape, (
    f"shape mismatch: pred={pred.shape}, target={target.shape}"
)
```

Shape를 변경할 때는 다음 순서로 생각한다.

```text
현재 Shape 확인
→ 필요한 Shape 결정
→ squeeze 또는 unsqueeze 사용
→ Broadcasting 가능 여부 확인
→ 실제 계산의 의미 확인
```

## Broadcasting 연습 예제

다음 두 Shape를 더한다고 하자.

```text
a = (3, 1)
b = (1, 4)
```

각 차원을 비교하면 다음과 같다.

```text
첫 번째 차원
3과 1 → 3

두 번째 차원
1과 4 → 4

결과 = (3, 4)
```

숫자로 보면 다음과 같다.

```text
a =
[10]
[20]
[30]

b =
[1, 2, 3, 4]

결과 =
[11, 12, 13, 14]
[21, 22, 23, 24]
[31, 32, 33, 34]
```

## 다시 볼 때 핵심

`(4,)`는 길이가 4인 1차원 Tensor다. `(1, 4)`는 Sample 하나와 Feature 4개인 2차원 Batch 형태이고, `(4, 1)`는 서로 다른 구조다.

`unsqueeze`의 인자는 새 차원의 크기가 아니라 새 차원을 추가할 위치다. `unsqueeze(0)`과 `unsqueeze(1)`의 결과를 한 번 혼동했으므로 다시 확인해야 한다.

`squeeze`는 크기가 1인 차원을 제거하지만 Batch Dimension처럼 필요한 차원까지 지울 수 있으므로 무조건 사용하면 안 된다.

Broadcasting은 오른쪽부터 Shape를 비교한다. 두 크기가 같거나 한쪽이 1이거나 한쪽에 차원이 없으면 계산할 수 있다.

`pred=(4, 1)`과 `target=(4,)`은 오류가 나지 않고 `(4, 4)`로 Broadcasting될 수 있다. 코드 실행 성공과 계산의 정확성은 다르므로 연산 전후의 Shape를 확인해야 한다.
