# 데이터·모델·손실·최적화·평가 흐름

> 학습일: 2026-08-19

## 핵심 정리

딥러닝 학습은 데이터를 Batch 단위로 모델에 넣고, Prediction과 Label의 차이로 Loss를 계산한 뒤, Backward로 Gradient를 구하고 Optimizer가 파라미터를 수정하는 과정을 반복하는 것이다.

Dataset은 데이터에 접근하는 방법을 정하고, DataLoader는 데이터를 Batch 단위로 꺼내 학습 루프에 전달한다. 전체 Train 데이터를 한 번 사용하면 1 Epoch이다.

Train Loop에서는 `backward()`와 `optimizer.step()`으로 파라미터를 변경하지만, Validation Loop에서는 예측과 성능 확인만 하고 파라미터를 변경하지 않는다.

Validation 결과는 모델 선택과 Early Stopping에 사용하므로 모델 개발에 간접적으로 영향을 준다. Test는 모델과 설정을 모두 확정한 뒤 마지막 성능을 확인할 때 사용한다.

> 결국 데이터에서 예측을 만들고, 틀린 정도를 계산하고, 덜 틀리는 방향으로 모델을 고친 뒤, 학습에 사용하지 않은 데이터에서 정말 좋아졌는지 확인하는 흐름이다.

---

## Prediction, Label, Loss

### 모델이 예측한 다음에는 무엇을 할까?

모델의 Prediction과 실제 Label을 비교해 Loss를 계산한다.

```text
실제 Label
→ 고양이

모델 Prediction
→ 강아지 90%
→ 고양이 10%
```

정답과 크게 다르면 Loss가 크게 나오고, 정답에 가까운 예측을 하면 Loss가 작게 나온다.

```text
Prediction
→ Label과 비교
→ Loss 계산
→ Loss를 줄이는 방향으로 파라미터 수정
→ 다시 Prediction
```

Loss를 계산하는 것만으로 파라미터가 바로 바뀌는 것은 아니다. Loss로부터 Gradient를 계산하고, Optimizer가 그 Gradient를 사용해 업데이트해야 한다.

---

## Loss Function은 모델이 알아서 정할까?

아니다. 풀려는 문제와 모델 출력 방식에 맞춰 사람이 선택한다.

대표적인 예는 다음과 같다.

```text
회귀
→ MSELoss

다중 클래스 분류
→ CrossEntropyLoss

이진 분류
→ BCELoss 또는 BCEWithLogitsLoss
```

```python
pred = model(x)
loss = loss_fn(pred, y)
```

같은 분류 문제라도 모델이 Logit을 출력하는지 확률을 출력하는지에 따라 적절한 Loss가 달라질 수 있다.

---

## Train, Validation, Test

딥러닝에서도 데이터를 목적에 따라 나누어 사용한다.

```text
전체 데이터
├─ Train
├─ Validation
└─ Test
```

### Train

- 모델 파라미터를 직접 학습한다.
- Forward, Loss, Backward, Optimizer Step을 수행한다.

### Validation

- 학습 중 일반화 성능을 확인한다.
- 모델 선택, 하이퍼파라미터 조정, Early Stopping에 사용한다.
- Gradient를 이용해 파라미터를 직접 업데이트하지 않는다.

### Test

- 모델과 학습 방법을 모두 확정한 뒤 최종 성능을 평가한다.
- 가능한 한 개발 중 모델 수정 판단에 사용하지 않는다.

```text
Train = 공부할 때 푸는 문제
Validation = 모의고사
Test = 최종 시험
```

### 딥러닝이 Test 데이터 관리도 알아서 할까?

아니다. 데이터를 어떻게 분리하고 어느 시점에 사용할지는 사람이 설계해야 한다.

```text
전체 10,000개 예시

Train       8,000
Validation  1,000
Test        1,000
```

이 비율은 예시이며 데이터 양과 문제에 따라 다르게 정할 수 있다.

---

## 나중에 수집한 새 데이터를 Test로 사용해도 될까?

가능하다.

새 데이터가 모델 학습, 하이퍼파라미터 선택, 모델 구조 결정에 전혀 사용되지 않았다면 좋은 독립 Test Set이 될 수 있다.

```text
기존 데이터
→ Train·Validation으로 모델 개발
→ 모델 확정

이후 새 데이터 확보
→ 최종 Test
```

Test의 핵심은 처음부터 떼어놓았는지가 아니라 모델 개발과 선택 과정에 관여하지 않았는가이다.

---

## Test 결과를 보고 모델을 다시 만들면 어떻게 될까?

새 Test에서 정확도가 70%라는 결과를 본 뒤 모델 구조나 학습 방법을 바꾸면 그 Test 정보가 개발 결정에 사용된다.

```text
모델 학습
→ Test 정확도 70%
→ 성능이 부족하다고 판단
→ 모델 수정·재학습
```

데이터 자체가 망가지는 것은 아니지만 더 이상 완전히 독립적인 최종 Test로 보기는 어렵다. 역할이 Validation이나 분석 데이터에 가까워진다.

### 모델을 삭제하고 처음부터 학습하면 오염이 사라질까?

아니다.

새 모델의 파라미터는 Test를 직접 본 적이 없어도, 사람이 Test 결과를 보고 다시 만들기로 결정했다면 정보가 간접적으로 전달된 것이다.

```text
Test 결과
→ 사람의 의사결정
→ 새 모델의 구조·학습 방법
```

> 모델의 파라미터 초기화와 실험 과정에서 얻은 정보의 초기화는 다르다.

### 랜덤 시드를 바꿔 여러 번 학습하는 것도 Test 오염일까?

처음부터 같은 모델을 여러 Seed로 학습하고 평균을 보고하겠다고 실험 계획을 정했다면 반복 실험 자체가 곧 오염을 뜻하지는 않는다.

하지만 Test 점수를 확인할 때마다 다시 학습하고 가장 높은 Test 점수의 모델을 선택하면 Test가 모델 선택 기준으로 사용된 것이다.

```text
미리 정한 실험
→ Seed 5개를 모두 실행
→ 평균과 분산 보고

Test 결과를 보고 반복
→ 점수가 낮으면 다시 실행
→ 가장 높은 Test 모델 선택
→ Test에 맞춘 선택
```

---

## 새로운 독립 Test를 구하지 못한다면?

현재 데이터 안에서 k-Fold CV 등을 이용해 일반화 성능을 다시 추정할 수 있다.

모델 선택과 성능 추정을 더 엄격히 분리해야 한다면 Outer Fold에서 평가하고 Inner Fold에서 모델과 하이퍼파라미터를 선택하는 Nested CV를 사용할 수 있다.

```text
Outer Fold
├─ Train
│  └─ Inner CV로 모델·설정 선택
└─ Test
   └─ 선택 과정과 분리된 평가
```

다만 CV가 완전히 새로운 환경에서 수집한 독립 Test 데이터와 항상 같은 역할을 하는 것은 아니다. 새 Test를 확보하지 못했다는 한계도 함께 기록해야 한다.

### Test를 두 개 준비하면 될까?

첫 번째 평가 결과를 보고 모델을 수정할 계획이라면 정확한 역할은 보통 Validation과 Test로 나누는 것이다.

```text
Train
→ 파라미터 학습

Validation
→ 모델 수정·선택

Test
→ 마지막 최종 평가
```

데이터가 적다면 Train과 Validation 부분에서 CV를 사용하고 Test만 별도로 봉인할 수 있다.

## 딥러닝 학습의 전체 준비 과정

학습 전에 다음 구성요소를 준비한다.

```text
Dataset
→ DataLoader
→ Model
→ Loss Function
→ Optimizer
→ Epoch 반복
```

### Epoch 전에 데이터 전체를 모델에 넣을까?

아니다.

Epoch 전에 Dataset과 DataLoader를 준비한다. 실제 데이터는 Epoch 안에서 DataLoader가 Batch 단위로 꺼내 모델에 전달한다.

```python
dataset = MyDataset(...)

dataloader = DataLoader(
    dataset,
    batch_size=32,
    shuffle=True
)
```

```python
for epoch in range(10):
    for x, y in dataloader:
        pred = model(x)
```

```text
Dataset 준비
→ DataLoader 준비
→ Epoch 시작
→ Batch 가져오기
→ 모델에 입력
```

## Dataset과 DataLoader

Dataset은 각 데이터와 Label에 어떻게 접근할지를 정의한다.

DataLoader는 Dataset에서 데이터를 꺼내 Batch로 묶고, 필요하면 학습 순서를 섞어 반복 가능한 형태로 제공한다.

`shuffle=True`이면 일반적인 Map-style Dataset에서 Epoch마다 데이터 순서를 다시 섞어 학습할 수 있다.

### Batch의 Shape는 어떻게 읽을까?

입력 Feature가 4개이고 Batch Size가 32라면 다음 Shape를 가질 수 있다.

```text
x.shape = [32, 4]

32 = 한 번에 처리하는 Sample 수
4  = Sample 하나의 Feature 수
```

---

## 입력, Hidden Dimension, ReLU, 출력

다음 모델을 생각해보자.

```python
model = nn.Sequential(
    nn.Linear(4, 16),
    nn.ReLU(),
    nn.Linear(16, 1)
)
```

### ReLU가 16개 값을 1개로 줄일까?

아니다.

```text
입력 4개
→ Linear(4, 16)
→ 값 16개
→ ReLU
→ 값 16개
→ Linear(16, 1)
→ 출력 1개
```

ReLU는 각 값에 다음 규칙을 적용할 뿐 차원 수를 줄이지 않는다.

$$
\mathrm{ReLU}(x)=\max(0,x)
$$

```text
ReLU 이전
[-2.1, 0.5, 3.2, -0.7, ...]

ReLU 이후
[0.0, 0.5, 3.2, 0.0, ...]
```

최종 출력 하나를 만드는 층은 마지막 `Linear(16, 1)`이다.

---

## 모델 구조와 파라미터 값

### 파라미터의 구조와 값은 누가 정할까?

`nn.Linear(4, 16)`을 만들 때 사람은 입력 Feature 4개를 출력 16개로 바꾸는 레이어 구조를 정한다.

PyTorch는 그 구조에 필요한 Weight와 Bias 파라미터를 생성하고 초기값을 넣는다.

```text
Linear(4, 16)

Weight Shape: [16, 4]
Bias Shape:   [16]
```

PyTorch의 Linear Weight는 출력 차원이 앞에 오므로 Shape가 `[16, 4]`이다.

초기 파라미터 값은 학습이 진행되면서 Loss를 줄이는 방향으로 계속 변경된다.

---

## Optimizer

Optimizer는 Gradient를 이용해 모델 파라미터를 실제로 업데이트한다.

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01
)
```

대표적인 Optimizer에는 SGD, Adam, AdamW, RMSprop 등이 있다.

역할을 나누면 다음과 같다.

```text
Model
→ 현재 파라미터로 Prediction 생성

Loss
→ Prediction이 얼마나 틀렸는지 계산

Backward
→ 각 파라미터의 Gradient 계산

Optimizer
→ Gradient로 파라미터 업데이트
```

---

## Gradient

### Gradient를 쉽게 어떻게 이해할까?

한 파라미터를 조금 바꿨을 때 Loss가 어느 방향으로 얼마나 민감하게 변하는지를 나타내는 값이다.

```text
Gradient의 부호
→ Loss가 증가하는 방향

Gradient의 절댓값
→ Loss가 변하는 민감도
```

예를 들어 파라미터 $w$를 조금 증가시켰더니 Loss도 증가했다면 Gradient는 양수이다.

```text
w 증가
→ Loss 증가
→ Gradient > 0
→ Loss를 줄이려면 w를 감소
```

반대로 $w$를 증가시켰을 때 Loss가 감소했다면 Gradient는 음수이다.

```text
w 증가
→ Loss 감소
→ Gradient < 0
→ Loss를 줄이려면 w를 증가
```

Gradient의 크기가 크면 파라미터의 작은 변화에도 Loss가 민감하게 변하고, 크기가 작으면 Loss 변화도 상대적으로 작다는 뜻이다.

---

## Gradient Descent의 업데이트

기본적인 파라미터 업데이트는 다음처럼 이해할 수 있다.

$$
w_{\mathrm{new}} =
w_{\mathrm{old}}-\eta\frac{\partial L}{\partial w}
$$

- $\eta$: Learning Rate
- $\partial L/\partial w$: 파라미터 $w$에 대한 Loss의 Gradient

예를 들어 현재 Weight가 5, Gradient가 2, Learning Rate가 0.1이면 다음과 같다.

$$
5-(0.1\times2)=4.8
$$

Gradient가 양수이므로 그 반대 방향으로 Weight가 감소한다.

---

## `loss.backward()`

### Backward는 실제로 무엇을 계산할까?

계산 그래프를 거꾸로 따라가며 모든 학습 가능한 파라미터에 대한 Gradient를 계산한다.

```text
Input
→ W₁
→ Hidden
→ W₂
→ Prediction
→ Loss

Backward
→ Loss에서 시작해 W₂, W₁ 방향으로 Gradient 계산
```

```python
loss.backward()
```

PyTorch의 Autograd가 각 연산의 미분 관계를 이용해 이 계산을 처리한다.

중요한 점은 `backward()`가 Gradient를 계산할 뿐 파라미터 자체를 변경하지는 않는다는 것이다.

---

## `optimizer.step()`

Gradient를 계산한 뒤 실제 파라미터를 변경하는 단계이다.

```python
optimizer.step()
```

```text
loss.backward()
→ 파라미터별 Gradient 계산

optimizer.step()
→ Gradient를 사용해 파라미터 변경
```

Optimizer에 따라 Learning Rate뿐 아니라 Momentum이나 과거 Gradient 정보 등을 함께 사용할 수 있다.

---

## `optimizer.zero_grad()`

### 왜 Batch마다 Gradient를 초기화할까?

PyTorch의 Gradient는 기본적으로 누적된다.

이전 Batch의 Gradient를 의도적으로 누적하는 것이 아니라면 새로운 Batch의 Backward 전에 초기화해야 한다.

```python
optimizer.zero_grad()
```

기본적인 순서는 다음과 같다.

```python
for x, y in dataloader:
    optimizer.zero_grad()

    pred = model(x)
    loss = loss_fn(pred, y)

    loss.backward()
    optimizer.step()
```

```text
1. zero_grad()
   이전 Gradient 초기화

2. model(x)
   Prediction 생성

3. loss_fn(pred, y)
   Loss 계산

4. loss.backward()
   Gradient 계산

5. optimizer.step()
   파라미터 업데이트
```

---

## Sample, Batch, Epoch

```text
Sample
= 데이터 하나

Batch
= 한 번의 Forward·Backward에서 처리하는 데이터 묶음

Epoch
= 전체 Train 데이터를 한 번 사용한 것
```

전체 데이터가 1,000개이고 Batch Size가 100이라면 한 Epoch에는 10개의 Batch가 있다.

```text
Batch 1  → 100개
Batch 2  → 100개
...
Batch 10 → 100개

10번의 파라미터 업데이트
→ 1 Epoch
```

데이터 수가 Batch Size로 정확히 나누어지지 않으면 마지막 Batch가 더 작을 수 있다. DataLoader에서 `drop_last=True`를 사용하면 이 마지막 불완전 Batch를 제외할 수 있다.

### Epoch가 20이면 업데이트는 몇 번 일어날까?

데이터 10,000개, Batch Size 100, Epoch 20이라고 하자.

$$
\frac{10{,}000}{100}=100
$$

한 Epoch에 100번 업데이트하므로 총 업데이트 횟수는 다음과 같다.

$$
100\times20=2{,}000
$$

---

## Epoch를 많이 돌릴수록 좋을까?

아니다.

처음에는 Train Loss와 Validation Loss가 함께 감소할 수 있다.

하지만 너무 오래 학습하면 Train Loss는 계속 감소하는데 Validation Loss는 다시 증가할 수 있다.

```text
Epoch 1: Validation Loss = 0.80
Epoch 2: Validation Loss = 0.60
Epoch 3: Validation Loss = 0.45
Epoch 4: Validation Loss = 0.40
Epoch 5: Validation Loss = 0.42
Epoch 6: Validation Loss = 0.47
```

이 경우 Epoch 4 이후부터 Train 데이터에 지나치게 맞춰지는 과적합을 의심할 수 있다.

### 언제 학습을 끝낼까?

두 가지 기본 방법을 생각할 수 있다.

- Epoch 수를 미리 정한다.
- Validation 성능이 일정 횟수 동안 좋아지지 않으면 Early Stopping한다.

```text
Validation Loss가 5 Epoch 동안 개선되지 않음
→ 학습 종료
```

Validation 성능이 가장 좋았던 시점의 모델 파라미터를 따로 저장해 사용하는 것도 중요하다.

---

## Train Loop

Train Loop는 학습 데이터로 모델 파라미터를 실제로 변경하는 과정이다.

```python
model.train()

for x, y in train_loader:
    optimizer.zero_grad()

    pred = model(x)
    loss = loss_fn(pred, y)

    loss.backward()
    optimizer.step()
```

```text
Train Batch
→ Forward
→ Prediction
→ Loss
→ Backward
→ Gradient
→ Optimizer Step
→ Parameter Update
```

Batch마다 파라미터가 바뀌므로 다음 Batch는 방금 수정된 모델을 사용한다.

Train Loop의 핵심은 `backward()`와 `optimizer.step()`이 있어 파라미터가 변경된다는 점이다.

---

## Validation Loop

Validation Loop는 현재 모델이 학습에 직접 사용하지 않은 데이터에서도 잘 작동하는지 확인한다.

```python
model.eval()

with torch.no_grad():
    for x, y in val_loader:
        pred = model(x)
        val_loss = loss_fn(pred, y)
```

```text
Validation Batch
→ Forward
→ Prediction
→ Loss·Accuracy 확인
→ Parameter 변경 없음
```

Validation에서는 `loss.backward()`와 `optimizer.step()`을 실행하지 않는다.

---

## `model.train()`과 `model.eval()`

```python
model.train()
```

은 모델을 학습 모드로 바꾼다.

```python
model.eval()
```

은 모델을 평가 모드로 바꾼다.

Dropout과 BatchNorm처럼 학습과 평가에서 동작이 다른 레이어가 있기 때문에 모드를 구분해야 한다.

`model.eval()`은 평가 동작으로 전환할 뿐 Gradient 계산 자체를 끄지는 않는다.

---

## `torch.no_grad()`

Validation에서는 Backward를 하지 않으므로 Gradient 계산 그래프를 만들 필요가 없다.

```python
with torch.no_grad():
    pred = model(x)
```

Gradient 추적을 끄면 평가 중 메모리 사용과 계산량을 줄일 수 있다.

`torch.no_grad()`는 Gradient 추적을 끄지만 Dropout과 BatchNorm의 동작 모드를 바꾸지는 않는다. 따라서 평가할 때는 보통 `model.eval()`과 `torch.no_grad()`를 함께 사용한다.

---

## Epoch 안에서 Train과 Validation은 어떤 순서일까?

보통 한 Epoch의 Train이 끝난 뒤 Validation을 수행한다.

```python
for epoch in range(num_epochs):
    model.train()

    for x, y in train_loader:
        optimizer.zero_grad()

        pred = model(x)
        loss = loss_fn(pred, y)

        loss.backward()
        optimizer.step()

    model.eval()

    with torch.no_grad():
        for x, y in val_loader:
            pred = model(x)
            val_loss = loss_fn(pred, y)
```

```text
Epoch 시작
→ Train Loop
→ 파라미터 업데이트
→ Validation Loop
→ 일반화 성능 확인
→ 다음 Epoch
```

---

## Validation을 매 Epoch 사용해도 될까?

Validation은 Backward나 Optimizer Step에 사용하지 않으므로 Gradient를 통해 파라미터에 직접 반영되지는 않는다.

하지만 완전히 영향이 없는 데이터는 아니다.

Validation 결과를 보고 다음 결정을 내릴 수 있기 때문이다.

- 가장 좋은 Epoch 선택
- Early Stopping
- Learning Rate 변경
- 모델 구조 변경
- 하이퍼파라미터 변경

```text
Train
→ 파라미터를 직접 학습

Validation
→ 파라미터를 직접 학습하지 않음
→ 모델 선택과 튜닝에 간접적으로 사용

Test
→ 모든 선택이 끝난 뒤 최종 평가
```

Validation을 반복해서 확인하며 지나치게 많은 결정을 내리면 Validation 데이터에도 간접적으로 맞춰질 수 있다. 그래서 마지막까지 독립적인 Test가 필요하다.

---

## 전체 딥러닝 학습 흐름

```text
Dataset 준비
→ DataLoader 준비
→ Model 생성
→ Loss Function 선택
→ Optimizer 선택

각 Epoch
├─ Train Loop
│  ├─ Batch
│  ├─ Forward
│  ├─ Prediction
│  ├─ Loss
│  ├─ zero_grad()
│  ├─ backward()
│  ├─ Gradient 계산
│  └─ optimizer.step()
│     → Parameter Update
│
└─ Validation Loop
   ├─ model.eval()
   ├─ no_grad()
   ├─ Forward
   └─ Loss·Accuracy 확인
      → Parameter 변경 없음

모델과 설정 확정
→ Test에서 최종 평가
```

핵심 역할은 다음과 같다.

- Model: 현재 파라미터로 Prediction을 만든다.
- Loss: Prediction과 Label의 차이를 계산한다.
- Backward: 파라미터별 Gradient를 계산한다.
- Optimizer: Gradient를 이용해 파라미터를 수정한다.
- Epoch: 전체 Train 데이터를 한 번 사용한다.
- Validation: 현재 모델의 일반화 성능을 확인하고 선택에 사용한다.
- Test: 확정된 최종 모델의 독립적인 성능을 평가한다.
