# 머신러닝과 딥러닝의 차이

> 학습일: 2026-08-19

## 핵심 정리

딥러닝은 머신러닝과 완전히 별개의 분야가 아니라 머신러닝에 포함되는 방법이다.

전통적인 머신러닝은 사람이 유용한 특징을 선택하거나 가공한 뒤 비교적 작은 모델을 학습시키는 경우가 많다. 딥러닝은 여러 층을 이용해 원본 데이터에서 필요한 특징 표현까지 모델이 함께 학습할 수 있다.

전통적인 머신러닝은 CPU와 비교적 적은 데이터로도 학습할 수 있어 비용이 낮은 경우가 많고, 딥러닝은 많은 파라미터와 데이터 때문에 GPU·학습 시간·서버 비용이 커질 수 있다.

하지만 어느 방법이 항상 더 좋거나 저렴한 것은 아니다. 데이터의 형태와 양, 문제의 복잡도, 필요한 성능과 설명 가능성을 보고 선택해야 한다.

> 결국 가장 큰 차이는 “사람이 특징을 많이 설계한 뒤 모델을 학습할 것인가, 모델이 특징 표현까지 함께 학습하게 할 것인가”에 가깝다.

---

## 머신러닝과 딥러닝의 관계

### 딥러닝은 머신러닝과 다른 분야일까?

딥러닝은 머신러닝의 한 종류이고, 머신러닝은 인공지능에 포함된다.

```text
인공지능 AI
└─ 머신러닝 Machine Learning
   └─ 딥러닝 Deep Learning
```

딥러닝이 아닌 전통적인 머신러닝 모델의 예는 다음과 같다.

- Linear Regression
- Logistic Regression
- Decision Tree
- Random Forest
- XGBoost

---

## 머신러닝은 딥러닝보다 저렴할까?

일반적으로 전통적인 머신러닝이 딥러닝보다 계산 비용이 낮은 경우가 많다.

전통적인 머신러닝은 다음과 같은 상황에서 비교적 적은 자원으로 학습할 수 있다.

- CPU만으로도 충분한 모델
- 데이터가 아주 크지 않은 문제
- 파라미터 수가 비교적 적은 모델
- 표 형태의 정형 데이터

딥러닝은 신경망의 층과 파라미터가 많고 대규모 데이터를 사용하는 경우가 많아 다음 비용이 커질 수 있다.

- GPU 사용 비용
- 학습 시간
- 메모리 사용량
- 서버 운영 비용
- 데이터 수집과 정제 비용

### 그러면 항상 전통적인 머신러닝부터 써야 할까?

항상 그런 것은 아니다.

문제에 따라 딥러닝이 필요한 특징을 직접 설계하는 비용을 줄이거나, 전통적인 방법으로 얻기 어려운 성능을 낼 수도 있다.

대략 다음처럼 출발점을 잡을 수 있다.

```text
정형 데이터
+ 데이터가 많지 않음
→ 전통적인 머신러닝부터 고려

이미지·음성·자연어
+ 데이터가 많음
→ 딥러닝 고려
```

실제로는 데이터 규모, 원하는 성능, 개발 시간과 배포 환경까지 함께 비교해야 한다.

## Feature Engineering

### 전통적인 머신러닝에서 사람이 특징을 만든다는 것은 무슨 뜻일까?

원본 데이터에서 모델이 사용하기 좋은 정보를 사람이 선택하거나 새로 계산하는 것이다.

예를 들어 다음 고객 데이터가 있다고 하자.

```text
나이: 25
최근 3개월 구매: 10회
총 결제액: 500,000원
```

사람이 총 결제액을 구매 횟수로 나누어 새로운 특징을 만들 수 있다.

$$
\mathrm{평균\ 구매\ 금액} =
\frac{\mathrm{총\ 결제액}}
{\mathrm{구매\ 횟수}}
$$

결과적으로 모델에 다음 특징을 넣을 수 있다.

```text
나이 = 25
구매 횟수 = 10
평균 구매 금액 = 50,000원
```

이처럼 도메인 지식을 이용해 유용한 입력값을 선택하고 가공하는 과정을 Feature Engineering이라고 한다.

```text
원본 데이터
→ 사람이 특징 선택·가공
→ 머신러닝 모델
→ 예측
```

---

## Feature Learning

### 딥러닝이 특징을 스스로 학습한다는 것은 무슨 뜻일까?

딥러닝 모델은 원본 데이터에서 예측에 필요한 내부 표현을 여러 층을 거치며 학습할 수 있다.

```text
Raw Data
→ Feature Learning
→ Feature Representation
→ Task-specific Model
→ Prediction
```

이미지를 예로 들면 각 층이 대략 다음과 같은 수준의 특징에 반응할 수 있다.

```text
원본 이미지
→ 초기 층: 선·모서리
→ 중간 층: 질감·부분 형태
→ 깊은 층: 더 복잡한 패턴
```

이 설명은 직관적인 예시이다. 실제 모델의 각 내부 값에 사람이 이해할 수 있는 이름이 하나씩 붙는 것은 아니다.

### Feature Representation은 사람이 읽을 수 있는 특징일까?

반드시 그렇지는 않다.

모델이 학습한 특징 표현은 다음처럼 숫자로 이루어진 벡터일 수 있다.

```text
0.81
-0.35
1.27
0.04
...
```

숫자 하나가 “눈”이나 “귀”처럼 사람이 정한 개념 하나와 정확히 대응하지 않더라도, 여러 숫자의 조합이 예측에 유용한 정보를 담을 수 있다.

---

## 특징을 학습하면 바로 예측이 끝날까?

아니다. 학습한 특징 표현을 실제 목적에 맞는 출력으로 바꾸는 부분이 필요하다.

```text
원본 데이터
→ Feature Learning
→ Feature Representation
→ Task-specific Model
→ Prediction
```

이미지 분류에서는 다음처럼 생각할 수 있다.

```text
CNN
→ 특징 벡터
→ Fully Connected Layer
→ 고양이·강아지 점수
```

Feature Learning 부분은 데이터에서 유용한 표현을 만들고, Task-specific 부분은 그 표현을 이용해 분류·회귀 같은 실제 문제의 답을 만든다.

---

## 전이 학습

### 한 문제에서 학습한 특징을 다른 문제에도 사용할 수 있을까?

가능하다.

이미 많은 이미지로 학습한 모델은 선, 모서리, 색, 질감과 같은 일반적인 시각 패턴을 표현하는 방법을 알고 있을 수 있다.

이 특징 추출 부분을 새로운 이미지 문제에 재사용하고, 새로운 문제에 맞는 출력 부분을 학습할 수 있다.

```text
기존 모델의 Feature Representation
→ 새로운 Task-specific Model
→ 새로운 문제의 Prediction
```

이러한 생각이 Transfer Learning과 연결된다.

새 데이터와 기존 데이터의 성격이 크게 다르면 기존 표현이 그대로 유용하지 않을 수도 있으므로 무엇을 고정하고 다시 학습할지는 문제에 맞게 결정해야 한다.

---

## 딥러닝이 자동으로 해주는 것과 사람이 정하는 것

### 특징을 알아서 학습한다면 사람이 거의 아무것도 하지 않아도 될까?

아니다.

딥러닝이 자동으로 학습하는 핵심은 유용한 Feature Representation과 모델 파라미터이다.

사람은 여전히 다음을 정해야 한다.

- 어떤 문제를 풀 것인가?
- 어떤 데이터를 수집하고 사용할 것인가?
- Label을 어떻게 정의할 것인가?
- 어떤 모델 구조를 사용할 것인가?
- 어떤 Loss Function을 사용할 것인가?
- 어떤 Optimizer와 학습률을 사용할 것인가?
- 어떤 지표와 데이터로 평가할 것인가?

잘못 정의한 Label이나 편향된 데이터에서 모델이 특징을 잘 학습하더라도 원래 원했던 문제를 올바르게 해결한다고 볼 수는 없다.

> 딥러닝은 특징 설계의 부담을 크게 줄여주지만 문제 정의부터 평가까지 전체 과정을 자동으로 대신해주지는 않는다.
