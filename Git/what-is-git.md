# Git이란 무엇인가

## 1. 버전 관리의 필요성과 Git의 등장

버전 관리는 파일의 변경 내용을 시간 순서대로 기록하고, 필요할 때 특정 시점의 상태를 확인하거나 이전 상태로 되돌릴 수 있도록 관리하는 방식이다.

버전 관리 도구가 없을 때는 파일 이름에 날짜나 버전 번호를 붙여 구분하는 경우가 많았다.

```text
project_final
project_final_2
project_final_last
```

하지만 이러한 방식은 파일마다 어떤 내용이 변경되었는지 확인하기 어렵고, 여러 사람이 함께 작업할 때 변경 내용을 관리하기도 어렵다.

Git은 파일의 변경 이력을 체계적으로 기록하여 변경 내용을 추적하고, 이전 상태를 복구하거나 여러 개발자가 협업할 수 있도록 도와주는 버전 관리 시스템이다.

## 2. DVCS와 Git의 구조

Git은 DVCS(Distributed Version Control System), 즉 분산 버전 관리 시스템이다.

### 중앙 집중식 버전 관리

중앙 서버 한 곳에서 저장소와 변경 이력을 관리하는 방식이다.

- 작업 내용을 중앙 서버를 통해 공유한다.
- 서버에 연결할 수 없으면 일부 버전 관리 작업이 제한될 수 있다.
- 중앙 서버에 문제가 발생하면 협업에 영향을 줄 수 있다.

### 분산 버전 관리

각 사용자의 로컬 컴퓨터에 저장소와 변경 이력을 함께 보관하는 방식이다.

- 인터넷에 연결되지 않아도 로컬에서 변경 내용을 확인하고 커밋할 수 있다.
- 각 사용자가 저장소의 전체 변경 이력을 가지고 있다.
- 원격 서버에 문제가 발생해도 로컬 저장소의 이력은 유지된다.

Git에서는 로컬 저장소에서 작업한 뒤, 필요한 커밋을 GitHub와 같은 원격 저장소에 업로드하여 다른 사용자와 공유할 수 있다.

## 3. Git의 세 영역

Git은 파일의 변경 상태를 작업 디렉터리, 스테이징 영역, 로컬 저장소의 세 영역으로 나누어 관리한다.

### 작업 디렉터리

사용자가 실제로 파일을 생성하고 수정하는 공간이다.

### 스테이징 영역

다음 커밋에 포함할 변경 사항을 임시로 모아두는 공간이다.

작업 디렉터리에서 수정한 파일에 `git add`를 실행하면 해당 변경 사항이 스테이징 영역에 등록된다.

```bash
git add README.md
```

### 로컬 저장소

스테이징 영역에 등록된 변경 사항을 커밋으로 기록하는 공간이다.

```bash
git commit -m "docs: Git 개념 정리"
```

전체 흐름은 다음과 같다.

```text
작업 디렉터리
    ↓ git add
스테이징 영역
    ↓ git commit
로컬 저장소
    ↓ git push
원격 저장소
```

## 정리

Git은 파일의 변경 이력을 기록하고, 이전 상태를 복구하며, 여러 개발자가 변경 내용을 안전하게 공유하고 협업할 수 있도록 도와주는 분산 버전 관리 시스템이다.
