# Q·K·V로 이해하는 Self-Attention 계산과 Context Vector

> 학습일: 2026-09-02

## 핵심 정리

- Self-Attention은 각 토큰이 같은 시퀀스의 다른 토큰 정보를 참고해 문맥이 반영된 표현을 만드는 연산이다.
- Q(Query), K(Key), V(Value)는 같은 입력에서 서로 다른 Linear Projection으로 만든다. Q와 K는 참고할 비율을 계산하고, V는 그 비율에 따라 전달할 정보를 담는다.
- 계산 순서는 `QKᵀ → √dₖ로 나누기 → Softmax → Attention Weight → Weight × V → Context Vector`다.
- 일반적인 Attention의 Softmax는 각 Query가 참고할 Key 방향으로 적용한다. `[B, L, L]`에서는 마지막 차원이 Key이므로 `dim=-1`을 사용한다.
- Context Vector는 Value 벡터의 가중합이다. 같은 위치의 성분끼리 더하므로 벡터가 하나의 숫자로 줄어들지 않는다.
- Q와 K의 내적 차원은 같아야 하지만, Cross-Attention에서는 Query와 Key의 토큰 수가 다를 수 있다.
- Attention Weight는 내부의 정보 혼합 비율이다. 높은 가중치만으로 최종 예측에 가장 중요한 토큰이라고 단정할 수는 없다.
- GPT의 Causal Mask는 미래 토큰을 참조하지 못하게 한다. 학습에서는 여러 위치의 다음 토큰 예측을 병렬로 계산할 수 있고, 생성에서는 선택한 토큰을 문맥에 붙여 다음 토큰을 이어서 예측한다.

이 문서는 3-1강의 Attention 필요성과 Q·K·V, 3-2강의 Scaled Dot-Product Attention 계산, 3-3강의 Attention Weight와 Context Vector 해석을 통합한 정리다. 아래 벡터 값과 문장 분할은 개념 설명을 위한 예시이며 실제 모델의 출력이나 성능 측정값은 아니다.

## 1. Self-Attention과 Query·Key·Value — 3-1강

### 각 토큰이 필요한 정보를 참고한다

같은 토큰도 함께 등장하는 토큰에 따라 해석이 달라질 수 있다. Self-Attention은 토큰 사이의 관련도를 계산하고 다른 토큰의 정보를 섞어 문맥이 반영된 표현을 만든다.

일반적인 Self-Attention에서는 같은 입력 X에 서로 다른 학습 가능한 선형 변환을 적용해 Q, K, V를 만든다. 편향을 생략한 표기는 다음과 같다.

$$
Q = XW_Q,\qquad K = XW_K,\qquad V = XW_V
$$

| 표현 | 역할 |
| --- | --- |
| Q(Query) | 현재 토큰이 어떤 정보를 찾을지 나타내는 표현 |
| K(Key) | 각 Query와 관련도를 비교하기 위한 표현 |
| V(Value) | 계산된 참고 비율에 따라 실제로 가중합할 정보 |

Q·K·V는 토큰 ID 자체가 아니라 입력 벡터를 변환한 표현이다. 특히 K를 단순히 V의 ID처럼 이해하면 관련도 계산과 정보 전달의 역할을 구분하기 어렵다.

```text
같은 입력 X
  ├─ 서로 다른 선형 변환 → Q
  ├─ 서로 다른 선형 변환 → K
  └─ 서로 다른 선형 변환 → V

Q와 K → 어떤 토큰을 얼마나 참고할지 계산
V     → 계산된 비율에 따라 정보 전달
```

### K와 V는 같은 입력에서 만드는데 왜 분리하는가?

처음에는 K를 V의 ID처럼 생각했고, Q와 V를 직접 비교하거나 Q와 K를 비교한 뒤 K를 그대로 전달해도 되는 것 아닌지 의문이 들었다.

하나의 벡터를 비교와 정보 전달에 함께 사용하는 것도 수학적으로 가능하다. K를 V 대신 가중합하는 형태로 Attention을 계산할 수도 있다.

다만 일반적인 Transformer는 두 역할을 나눈다.

- K는 Q와의 관련도 계산에 유용한 특징을 학습한다.
- V는 다른 토큰으로 전달할 정보를 표현하도록 학습한다.

같은 표현에 두 역할을 모두 맡기면 관련도 계산에 유리한 특징과 전달에 유리한 특징을 독립적으로 조정하기 어렵다. 별도의 변환을 사용하면 표현의 자유도를 높일 수 있다.

따라서 K와 V를 분리해야만 Attention이 성립하는 것은 아니다. 역할을 분리해 학습의 유연성을 높인다는 점이 핵심이다.

학습 당시에는 이 분리의 필요성이 직관적으로 완전히 납득되지는 않았다. 우선 각 역할과 계산 구조를 이해하고 넘어가기로 했다.

## 2. Scaled Dot-Product Attention 계산 — 3-2강

### 전체 계산 순서

$$
\operatorname{Attention}(Q,K,V)
= \operatorname{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V
$$

여기서 dₖ는 Q와 K의 내적에 사용하는 특징 차원이다. Softmax는 Key 방향으로 적용한다.

```text
Q × Kᵀ
    ↓
Query와 Key의 내적 점수
    ↓ √dₖ로 나누기
스케일을 조정한 점수
    ↓ Key 방향으로 Softmax
Attention Weight
    ↓ V와 행렬곱
Context Vector
```

내적 점수를 √dₖ로 나누면 차원이 커질 때 점수의 크기가 지나치게 커지는 것을 완화한다. 점수 차이가 너무 커져 Softmax가 일부 위치에 과도하게 집중하는 문제를 줄이는 데 도움이 된다.

Scaling은 Softmax 전에 수행한다. 두 연산 모두 Tensor Shape은 바꾸지 않는다.

### 왜 K의 마지막 두 차원을 전치하는가?

각 Query 벡터와 모든 Key 벡터의 내적을 행렬곱 한 번으로 계산하기 위해서다.

배치 크기가 2, 토큰 수가 5, Q·K의 특징 차원이 8이라고 가정한다.

```text
Q:                    [2, 5, 8]
K:                    [2, 5, 8]
K.transpose(-2, -1):   [2, 8, 5]

Q @ Kᵀ:               [2, 5, 5]
```

결과의 각 `[5, 5]` 행렬에는 해당 입력의 5개 Query와 5개 Key 사이의 점수가 담긴다. 행은 Query, 열은 Key에 대응한다.

전치는 원소의 숫자를 바꾸지 않고 행과 열의 위치를 교환한다. K에 담긴 정보를 내적에 맞게 재배열하는 것이지만, 전치 전후의 행렬이 수학적으로 동일하다는 뜻은 아니다. 배치 차원은 유지하고 마지막 두 차원만 교환한다.

### 전치행렬과 역행렬 구분

처음에는 전치행렬을 곱하면 단위행렬이 나온다고 기억했다. 하지만 전치와 역행렬은 다른 개념이다.

| 구분 | 의미 |
| --- | --- |
| 전치행렬 Aᵀ | 행과 열의 위치를 교환한 행렬 |
| 역행렬 A⁻¹ | 존재할 때 AA⁻¹ = I를 만족하는 행렬 |
| 직교행렬 | 실수 정사각행렬에서 Aᵀ = A⁻¹을 만족하는 특별한 경우 |

일반적인 K의 전치를 역행렬로 생각하거나 `KKᵀ = I`가 된다고 가정하면 안 된다. Attention에서 전치하는 목적은 Query와 Key의 내적을 계산하는 데 있다.

### Q와 K는 항상 같은 Shape이어야 하는가?

일반적인 Self-Attention에서는 같은 시퀀스에서 Q와 K를 만들기 때문에 토큰 수가 같다. 하지만 Cross-Attention에서는 Query를 만드는 입력과 Key·Value를 만드는 입력이 달라 토큰 수도 다를 수 있다.

일반화한 Shape은 다음과 같다.

| 항목 | Shape |
| --- | --- |
| Q | `[B, Lq, dₖ]` |
| K | `[B, Lk, dₖ]` |
| Kᵀ | `[B, dₖ, Lk]` |
| Attention Score / Weight | `[B, Lq, Lk]` |
| V | `[B, Lk, dᵥ]` |
| Context | `[B, Lq, dᵥ]` |

Q와 K는 내적에 사용하는 특징 차원 dₖ가 같아야 한다. K와 V는 참고 대상의 토큰 수 Lk가 같아야 한다. Query의 수 Lq와 Key의 수 Lk가 반드시 같을 필요는 없다.

### 줄바꿈을 복원한 계산 코드

아래는 Q, K, V가 이미 PyTorch Tensor로 준비되어 있고, Mask를 적용하지 않는 경우의 기본 계산이다.

```python
import torch

d_k = Q.shape[-1]
scores = Q @ K.transpose(-2, -1)
scores = scores / (d_k ** 0.5)
weights = torch.softmax(scores, dim=-1)
context = weights @ V
```

Q·K·V가 모두 `[2, 5, 8]`인 예시에서는 Score와 Weight가 `[2, 5, 5]`, Context가 `[2, 5, 8]`이 된다.

## 3. Softmax 축과 Attention Weight 해석 — 3-2~3-3강

### dim=-1은 어느 방향인가?

Attention Score의 Shape이 `[B, L, L]`인 경우 각 차원은 다음과 같다.

| 차원 | 의미 |
| --- | --- |
| `dim=0` | Batch |
| `dim=1` | Query |
| `dim=2` 또는 `dim=-1` | Key |

각 Query가 여러 Key를 참고하는 비율을 구하려면 Key 방향으로 Softmax를 적용한다. 따라서 각 행의 Attention Weight 합이 1이 된다.

$$
\alpha_{ij}
= \frac{\exp(s_{ij})}{\sum_{k=1}^{L_k}\exp(s_{ik})},
\qquad \sum_{j=1}^{L_k}\alpha_{ij}=1
$$

여기서 s는 Scaling을 마친 점수이며, i는 Query 위치, j는 Key 위치다.

Softmax를 항상 마지막 차원에만 써야 하는 것은 아니다. 일반적인 Attention에서 마지막 차원이 Key를 나타내므로 `dim=-1`을 선택하는 것이다.

### dim=1을 사용해도 계산은 되는가?

`[B, L, L]`에서 `dim=1`을 사용해도 Tensor Shape은 유지되고 V와의 행렬곱도 수행된다. 하지만 정규화의 의미가 달라진다.

| 구분 | `dim=-1` | `dim=1` |
| --- | --- | --- |
| 정규화 방향 | Key | Query |
| 배치별 점수 행렬에서 합이 1인 방향 | 각 행 | 각 열 |
| 의미 | 각 Query가 Key들을 참고하는 비율 | 각 Key에 대한 여러 Query의 점수를 정규화 |

`dim=1`에서는 한 Query의 가중치가 다른 Query의 점수에도 영향을 받는다. 각 Query의 Key 방향 가중치 합이 1이라는 보장도 없어지므로, 만들어지는 Context Vector가 달라질 수 있다.

Shape이 같다고 같은 계산은 아니다. Context가 바뀌면 최종 예측 확률이나 생성 결과도 달라질 수 있다. 기존 `dim=-1` 구조로 학습한 모델에서 축만 바꾸면 성능이 저하될 가능성이 있지만, 어떤 토큰이 출력될지 또는 얼마나 성능이 달라질지는 이 설명만으로 알 수 없다.

### 높은 Attention Weight는 곧 높은 최종 중요도인가?

Attention Weight는 해당 연산에서 각 Value를 얼마나 섞을지 나타내는 내부 가중치다. 특정 Key 위치의 가중치가 높다는 사실만으로 그 토큰이 최종 예측에 가장 중요하다고 단정할 수는 없다.

가중치를 해석할 때는 어느 Query가 어느 Key를 참고하는지를 함께 보아야 한다.

## 4. Value의 가중합과 Context Vector — 3-3강

### 여러 벡터를 더하면 하나의 숫자가 되는가?

처음에는 여러 Value를 합치면 모든 성분이 하나의 숫자로 합쳐진다고 생각했다. 하지만 벡터의 덧셈은 같은 위치의 성분끼리 이루어진다.

$$
[1,2,3]+[4,5,6]=[5,7,9]
$$

Attention도 각 Value 벡터에 해당 Weight를 곱한 뒤 같은 성분끼리 더한다. 설명을 위한 예시로 다음을 가정한다.

$$
V_1=[1,2,3],\qquad V_2=[4,5,6]
$$

$$
\begin{aligned}
\operatorname{Context}
&=0.2V_1+0.8V_2\\
&=[0.2\times1+0.8\times4,\;
    0.2\times2+0.8\times5,\;
    0.2\times3+0.8\times6]\\
&=[3.4,4.4,5.4]
\end{aligned}
$$

두 개의 3차원 벡터를 가중합했지만 결과는 여전히 3차원이다. 마찬가지로 8차원 Value를 여러 개 가중합해도 결과는 8차원 벡터다.

### Query마다 Context Vector 하나를 만든다

각 Query는 자신의 Attention Weight로 Value들을 가중합한다.

$$
c_i=\sum_{j=1}^{L_k}\alpha_{ij}v_j
$$

Q·K·V의 토큰 수가 L이고 Value 차원이 D인 Self-Attention 예시에서는 다음과 같다.

```text
Attention Weight: [B, L, L]
Value:            [B, L, D]
    ↓ 행렬곱
Context:          [B, L, D]
```

- Query가 L개이므로 결과 벡터도 L개다.
- 각 Value가 D차원이므로 각 Context Vector도 D차원이다.
- 가중합으로 벡터의 값은 바뀌지만 이 예시의 Shape은 유지된다.

일반적인 출력의 마지막 차원은 Value의 차원 dᵥ를 따른다. 입력과 출력 Shape이 항상 같아야 하는 것은 아니며, 위 예시는 Value 차원을 입력과 같은 D로 둔 경우다.

## 5. Batch·Label·Embedding에 관한 질문

### 왜 문장을 하나씩 처리하지 않고 Batch로 묶는가?

Batch는 여러 입력을 한 번에 처리하는 단위다. GPU에서 여러 입력의 행렬 연산을 병렬로 처리해 효율을 높일 수 있다.

예를 들어 `batch_size=2`라면 두 입력을 묶어 순전파를 수행하고, 일반적으로 배치의 Loss를 집계해 역전파와 가중치 업데이트를 진행한다.

이때 Self-Attention은 각 입력 내부에서 독립적으로 계산된다. 두 문장을 같은 배치로 묶었다고 서로 다른 문장의 토큰 사이에 Attention이 생기는 것은 아니다.

### 문장 하나당 Label 하나가 붙는가?

Label의 단위는 학습 목적에 따라 다르다.

| 학습 목적 | 정답의 단위 |
| --- | --- |
| 문장 분류 | 문장 전체에 대한 Label |
| 토큰 분류 | 각 토큰에 대응하는 Label |
| GPT의 다음 토큰 예측 | 각 위치에서 예측할 다음 토큰 |

따라서 모든 언어모델이 문장마다 하나의 분류 Label을 사용하는 것은 아니다.

### Embedding Table 조회와 무작위 초기화는 어떤 관계인가?

처음부터 학습하는 모델의 Embedding Table은 일반적으로 무작위로 초기화하는 학습 가능한 가중치 행렬이다. Token ID로 그 안의 해당 벡터를 조회한다.

```text
모델 생성 시 Embedding Table을 무작위 초기화
    ↓
Token ID로 해당 벡터 조회
    ↓
모델 순전파와 Loss 계산
    ↓
역전파로 Gradient 계산
    ↓
Optimizer가 Embedding을 포함한 학습 대상 가중치 갱신
```

무작위 초기화와 Table 조회는 같은 학습 구조 안에서 서로 다른 단계다. 초기화는 모델을 처음 만들 때 수행하며, 입력을 처리할 때마다 벡터를 새로 무작위 생성하는 것이 아니다. 학습이 진행되면 Embedding Table의 값도 수정된다.

사전학습 모델을 불러오는 경우에는 이미 학습된 Embedding 가중치를 사용할 수 있다.

## 6. 다음 토큰 예측과 Causal Mask

### '나는 사과를 먹었다'를 학습하면 무엇을 예측하는가?

GPT는 문장 내부의 여러 위치에서 다음 토큰을 예측한다. 각 어절을 하나의 토큰으로 가정하면 다음과 같다.

| 입력 문맥 | 예측 정답 |
| --- | --- |
| 나는 | 사과를 |
| 나는 사과를 | 먹었다 |
| 나는 사과를 먹었다 | 이어지는 다음 토큰 또는 종료 토큰 |

실제 토큰화 결과는 이 어절 구분과 다를 수 있다. 마지막 위치의 정답도 학습 데이터의 구성과 종료 토큰 처리에 따라 달라진다.

학습에서는 정답 시퀀스가 주어지므로 전체 입력을 한 번에 처리하면서 여러 위치의 다음 토큰 예측 Loss를 계산할 수 있다. BERT의 대표적인 사전학습 방식인 Masked Language Modeling은 일부 토큰을 가리고 앞뒤 문맥으로 그 토큰을 예측한다는 점에서 다르다.

### 다음에 올 수 있는 토큰이 많으면 정답 확률이 낮지 않은가?

가능한 다음 토큰이 많으므로 정답 토큰의 확률이 낮을 수 있다. 하지만 모델이 모든 후보에 같은 확률을 주는 것은 아니다. 학습한 패턴과 현재 문맥에 따라 서로 다른 확률을 계산한다.

한 위치의 정답 토큰을 y, 앞선 문맥을 x라고 하면 Cross-Entropy Loss는 다음과 같이 표현할 수 있다.

$$
\mathcal{L}=-\log P(y\mid x)
$$

정답 토큰에 부여한 확률이 낮으면 Loss가 커진다. 언어모델의 학습 목표는 다양한 문맥에서 다음 토큰의 확률 분포를 학습하는 것이다.

### 모든 토큰을 참고할 수 있는데 왜 미래를 가리는가?

Self-Attention은 Mask로 제한하지 않으면 시퀀스의 모든 토큰을 직접 참고할 수 있다. 하지만 GPT의 다음 토큰 예측에서 미래의 정답을 미리 보면 학습 목적에 맞지 않으므로 Causal Mask를 적용한다.

```text
                  Key
              T1  T2  T3
Query  T1      O   X   X
       T2      O   O   X
       T3      O   O   O

O: 참조 가능
X: 참조 차단
```

각 Query는 자신과 이전 토큰만 참고한다. 일반적으로 차단할 위치의 점수를 Softmax 전에 음의 무한대로 처리해 해당 위치의 가중치가 0이 되게 한다.

이는 Self-Attention 자체가 먼 위치를 참조하지 못해서가 아니라, 학습 목적에 맞춰 참조 범위를 제한한 것이다.

### 미래를 볼 수 없다면 문장을 어떻게 이어서 생성하는가?

생성에서는 문장 전체를 한 번에 정하지 않고 다음 토큰을 선택한 뒤 문맥에 추가한다.

```text
나는
    ↓ 다음 토큰 선택
나는 사과를
    ↓ 다음 토큰 선택
나는 사과를 먹었다
```

이는 가능한 생성 경로를 설명하는 예시다. `나는`만 입력했다고 반드시 `사과를`이 생성되는 것은 아니다. 모델이 계산한 확률 분포와 토큰 선택 방식에 따라 결과가 달라진다.

학습에서 여러 위치의 예측을 한 번에 계산하는 것과, 생성에서 앞서 선택한 토큰에 의존해 문장을 이어 가는 것은 구분해야 한다.
