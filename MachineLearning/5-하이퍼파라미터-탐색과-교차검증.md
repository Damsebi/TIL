# 하이퍼파라미터 탐색과 교차검증

> 학습일: 2026-08-18

## 핵심 정리

파라미터는 모델이 데이터에서 학습하는 값이고, 하이퍼파라미터는 학습 전에 사람이 설정하는 값이다. 사람은 모델이 제공하는 하이퍼파라미터 중 무엇을 어떤 범위에서 탐색할지 결정한다.

교차검증은 하나의 Train 데이터를 여러 Fold로 나누어 같은 하이퍼파라미터 조합을 여러 번 평가하는 방법이다. Fold 모델 중 가장 좋은 하나를 고르는 것이 아니라, 각 조합의 Fold 평균 점수를 비교한다.

Grid Search는 지정한 모든 조합을 확인하고, Random Search는 정한 횟수만큼 조합을 뽑아 확인한다. Optuna는 이전 Trial 결과를 활용해 다음에 시험할 후보를 선택하는 최적화 도구이다.

탐색 결과를 볼 때는 평균 점수만 보지 않고 Fold 사이의 편차와 학습 시간도 함께 확인한다. 최종 설정을 정하면 Train 전체로 모델을 다시 학습하고, 마지막까지 사용하지 않은 Test Set으로 한 번 평가한다.

> 결국 하이퍼파라미터 튜닝은 여러 설정을 공정하게 비교해서 성능, 안정성, 비용의 균형이 목적에 맞는 모델을 선택하는 과정이다.

## 파라미터와 하이퍼파라미터

### 모델이 학습하는 값과 사람이 정하는 값은 어떻게 다를까?

파라미터는 모델이 학습 과정에서 데이터로부터 스스로 결정하는 값이다.

예를 들어 선형회귀의 가중치와 편향, 신경망의 가중치가 파라미터이다.

하이퍼파라미터는 모델을 어떤 방식으로 학습할지 사람이 미리 설정하는 값이다.

예를 들면 다음과 같다.

- 트리의 최대 깊이 `max_depth`
- 트리 개수 `n_estimators`
- 학습률
- 규제 강도
- 배치 크기

### 하이퍼파라미터 이름도 사람이 만드는 것일까?

아니다. `max_depth`나 `n_estimators` 같은 이름과 기능은 모델이나 라이브러리가 제공한다.

사람이 결정하는 것은 다음과 같다.

- 어떤 하이퍼파라미터를 튜닝할지
- 어떤 값이나 범위를 탐색할지
- 몇 번 시험할지
- 무엇을 좋은 결과라고 판단할지

모든 하이퍼파라미터를 반드시 탐색할 필요는 없다. 일부만 탐색하고 나머지는 기본값이나 고정값을 사용할 수 있다.

하이퍼파라미터가 많아질수록 가능한 조합 수가 빠르게 증가하므로 중요한 값부터 선택해서 탐색해야 한다.

## Train, Validation, Test 데이터

### 전체 데이터를 Train과 Test로 나눈 뒤 Validation을 또 나눌까?

가능하다. 예를 들어 전체 데이터의 80%를 Train, 20%를 Test로 먼저 나눌 수 있다.

```text
전체 데이터
├─ Train 80%
└─ Test 20%
```

80%와 20%는 예시일 뿐 반드시 사용해야 하는 고정 비율은 아니다.

CV를 사용하지 않는다면 Train 일부를 고정 Validation Set으로 나눌 수 있다. 하지만 k-Fold CV를 사용한다면 Train 안에서 Fold마다 Validation 역할을 바꾸어가며 평가한다.

### Validation은 모델이 얼마나 많이 학습했는지 보는 데이터일까?

단순히 학습량을 확인하는 데이터가 아니다.

> 학습에 직접 사용하지 않은 데이터에서도 현재 모델과 설정이 잘 맞는지 확인하는 데이터이다.

```text
Train 성능은 높음
Validation 성능은 낮음
→ 과적합 가능성을 의심
```

하나의 고정 Validation 분할만 사용하면 우연히 그 분할에 잘 맞는 설정을 선택할 수 있다. CV는 여러 분할에서 나온 점수를 평균내어 특정 분할의 우연한 영향을 줄인다.

---

## k-Fold 교차검증

5-Fold CV에서는 Train 데이터를 다섯 부분으로 나누고 각 Fold가 한 번씩 Validation 역할을 맡는다.

```text
Fold 1: A = Validation / B C D E = Train
Fold 2: B = Validation / A C D E = Train
Fold 3: C = Validation / A B D E = Train
Fold 4: D = Validation / A B C E = Train
Fold 5: E = Validation / A B C D = Train
```

각 Fold에서는 같은 종류의 모델과 같은 하이퍼파라미터를 사용하지만, 학습 데이터가 다르므로 새로운 모델을 각각 학습한다.

### 가장 점수가 높은 Fold 모델 하나를 선택할까?

처음에는 다섯 Fold 모델 중 점수가 가장 높은 하나를 고르는 것으로 생각했다.

하지만 비교하는 대상은 개별 Fold 모델이 아니라 하이퍼파라미터 조합의 평균 검증 점수이다.

```text
조합 1
max_depth = 5
n_estimators = 200

Fold 점수: 88, 91, 90, 89, 92
평균 점수: 90
```

다른 조합도 같은 방식으로 모든 Fold에서 평가한다.

```text
조합 1 평균: 90
조합 2 평균: 92
조합 3 평균: 89
```

최종적으로 비교하는 값은 각 조합의 CV 평균 점수이다.

### CV에서 만든 모델은 최종 모델일까?

아니다. 각 Fold 모델은 하이퍼파라미터 조합을 평가하기 위한 임시 모델이다.

Train이 전체 데이터의 80%이고 5-Fold를 사용한다면, 한 Fold 모델은 전체 데이터의 약 64%만 학습한다.

$$
0.8\times\frac{4}{5}=0.64
$$

좋은 하이퍼파라미터를 선택한 뒤에는 그 설정으로 Train 80% 전체를 사용해 최종 모델을 다시 학습한다.

---

## 기존 Fold 모델에 남은 데이터를 추가로 학습하면 안 될까?

처음부터 다시 학습하는 대신 한 Fold 모델에 남은 Validation 데이터를 추가하면 더 빠를 것 같았다.

일부 점진 학습 모델에서는 비슷한 접근을 사용할 수도 있지만 일반적인 CV의 기본 흐름은 아니다.

이유는 다음과 같다.

- 모든 모델이 추가 학습을 지원하지 않는다.
- 다섯 Fold 모델 중 어느 모델을 출발점으로 고를지가 임의적이다.
- 일부 데이터를 먼저 학습하고 나중에 추가한 결과가 전체 데이터를 처음부터 함께 학습한 결과와 같다고 보장할 수 없다.
- 신경망은 초기값, 데이터 순서, 배치, 옵티마이저와 학습률 등에 따라 학습 경로가 달라질 수 있다.
- 트리 모델도 기존 트리에 데이터를 단순히 추가한다고 전체 데이터로 새로 만든 트리와 같아지지 않는다.

따라서 CV 모델은 평가가 끝나면 버리고, 선택한 설정으로 Train 전체에서 새 모델을 학습하는 것이 일반적이다.

### 같은 데이터를 결국 모두 봤다면 같은 모델이 되지 않을까?

같은 데이터를 모두 봤다는 것과 같은 내부 상태를 학습했다는 것은 다르다.

두 모델이 학습 데이터에는 비슷하게 맞더라도 새로운 데이터에서는 다른 예측을 할 수 있다. 특히 학습 경로에 영향을 받는 모델은 데이터 순서와 초기 상태에 따라 서로 다른 파라미터에 도달할 수 있다.

다만 항상 달라지는 것은 아니다. 유일한 최적해로 안정적으로 수렴하는 단순한 문제에서는 순서의 영향이 매우 작거나 같은 결과에 도달할 수도 있다.

## Grid Search

Grid Search는 사람이 지정한 후보 값의 모든 조합을 빠짐없이 평가한다.

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV

model = RandomForestClassifier(random_state=42)

param_grid = {
    "n_estimators": [100, 200],
    "max_depth": [3, 5, 7]
}

grid = GridSearchCV(
    model,
    param_grid,
    cv=5,
    scoring="accuracy"
)

grid.fit(X_train, y_train)
```

후보 조합 수는 다음과 같다.

$$
2\times3=6
$$

각 조합을 5-Fold로 평가하면 모델 학습은 총 30번 일어난다.

$$
6\times5=30
$$

탐색이 끝난 뒤 최적 조합으로 Train 전체를 다시 학습하는 `refit` 단계가 있다면 실제 학습 횟수는 그만큼 추가된다.

## Random Search

### 전체 조합의 절반 정도를 무작위로 볼까?

아니다. 전체 조합의 일정 비율을 자동으로 고르는 방식이 아니라 `n_iter`로 시험할 조합 수를 직접 정한다.

```python
from sklearn.model_selection import RandomizedSearchCV

param_distributions = {
    "n_estimators": [100, 200, 300],
    "max_depth": [3, 5, 7, 10]
}

random_search = RandomizedSearchCV(
    model,
    param_distributions,
    n_iter=5,
    cv=5,
    scoring="accuracy",
    random_state=42
)

random_search.fit(X_train, y_train)
```

가능한 리스트 조합은 12개이지만 `n_iter=5`이므로 그중 5개 조합만 평가한다.

$$
3\times4=12
$$

5-Fold라면 총 25번 학습한다.

$$
5\times5=25
$$

Random Search가 반환하는 최적 조합은 전체 탐색 공간의 절대 최적값이 아니라 실제로 시험한 조합 중 가장 좋은 값이다.

### 같은 조합이 여러 번 뽑힐 수 있지 않을까?

scikit-learn의 `RandomizedSearchCV`에서 모든 후보가 리스트라면 전체 조합을 중복 없이 샘플링한다.

각 하이퍼파라미터의 개별 값은 다른 조합에서 반복될 수 있다.

```text
max_depth=5, n_estimators=100
max_depth=5, n_estimators=200
```

두 조합에서 `max_depth=5`는 반복되지만 전체 조합은 다르다.

하나 이상의 값을 확률분포에서 샘플링하도록 지정하면 복원추출 방식이 사용되므로 같은 값이나 조합이 다시 나올 가능성이 있다.

### 분포에서 값을 뽑는다는 것은 무엇일까?

후보를 직접 모두 나열하지 않고 범위와 샘플링 규칙을 정하는 것이다.

```text
max_depth: 3~10 사이 정수
learning_rate: 일정 범위의 실수
```

Grid Search에 다음 값만 넣었다면 0.037은 직접 시험하지 않는다.

```text
0.001, 0.01, 0.1, 1.0
```

연속적인 하이퍼파라미터는 적절한 분포를 사용하면 더 다양한 값을 탐색할 수 있다.

---

## Grid Search를 항상 사용하면 안 될까?

탐색 공간이 작고 계산 비용을 감당할 수 있다면 Grid Search도 합리적인 선택이다.

하지만 Grid Search는 연속적인 모든 값을 확인하는 것이 아니라 사람이 나열한 후보 조합만 모두 확인한다.

하이퍼파라미터가 늘어나면 조합 수도 곱셈으로 증가한다.

```text
하이퍼파라미터 3개
각각 후보 10개
→ 10 × 10 × 10 = 1000개 조합

5-Fold
→ 1000 × 5 = 5000번 학습
```

탐색 공간이 크다면 Random Search나 Optuna가 더 효율적일 수 있다.

실용적으로 넓은 범위를 Random Search나 Optuna로 먼저 탐색하고, 유망한 범위를 좁힌 뒤 Grid Search로 세밀하게 확인할 수도 있다.

## 탐색 공간의 축과 PCA 축은 같은 개념일까?

서로 다른 의미이다.

하이퍼파라미터 탐색 공간의 축은 모델 설정값의 종류를 의미한다.

```text
max_depth 축
n_estimators 축
learning_rate 축
```

PCA의 축은 데이터의 특징 공간을 변환해서 얻는 주성분 방향이다.

하이퍼파라미터 탐색에서는 좋은 축 하나를 찾는 것이 아니라 각 하이퍼파라미터 축에서 값 하나씩 골라 하나의 설정 조합을 만든다.

## `random_state=42`

### 42라서 랜덤 시드가 되는 것일까?

42라는 숫자에 특별한 기능이 있는 것은 아니다.

중요한 점은 `random_state`에 같은 값을 지정하면 의사난수 생성 과정을 재현하기 쉬워진다는 것이다.

```python
random_state=42
```

C#이나 Unity에서는 다음과 비슷하게 생각할 수 있다.

```csharp
new Random(42);
UnityEngine.Random.InitState(42);
```

42는 예제에서 자주 사용하는 숫자일 뿐이며 다른 정수를 사용해도 된다.

## 탐색 전략과 라이브러리의 차이

Grid, Random, Bayesian 계열 탐색은 하이퍼파라미터 후보를 어떤 방식으로 선택할지에 대한 전략이다.

scikit-learn과 Optuna는 그 전략을 구현하고 실행할 수 있게 도와주는 라이브러리 또는 도구이다.

```text
탐색 전략
├─ Grid Search
├─ Random Search
└─ Bayesian 계열 탐색

도구
├─ scikit-learn
│  ├─ GridSearchCV
│  └─ RandomizedSearchCV
└─ Optuna
```

`GridSearchCV`와 `RandomizedSearchCV`는 scikit-learn이 제공하는 클래스이다.

Optuna는 하이퍼파라미터 최적화 프레임워크이며 한 가지 탐색 전략만을 뜻하는 이름은 아니다.

## Optuna

### Optuna를 모델을 감독하는 AI라고 보면 될까?

외부에서 모델을 반복 평가하면서 더 좋은 설정을 찾는다는 점에서는 그렇게 느낄 수 있다.

하지만 정확히는 일반적인 의미의 AI 감독자가 아니라 하이퍼파라미터 최적화를 관리하는 도구이다.

사람이 정하는 것은 다음과 같다.

- 탐색할 하이퍼파라미터
- 각 값의 범위와 분포
- 평가 지표
- Trial 수
- CV 방식과 Fold 수

Optuna는 다음 과정을 자동화한다.

- 이번 Trial에서 시험할 값 선택
- Trial 결과 기록
- 이전 결과를 활용한 다음 후보 선택
- 가장 좋은 Trial과 설정 관리

## Trial과 `objective()`

### Trial은 무엇일까?

Trial은 하나의 하이퍼파라미터 조합을 실제로 시험하는 한 번의 시도이다.

```text
Trial 1
max_depth=4
n_estimators=130
CV 평균 점수=0.87

Trial 2
max_depth=7
n_estimators=210
CV 평균 점수=0.92
```

### `objective()`는 무엇을 하는 함수일까?

Optuna가 선택한 하이퍼파라미터 조합을 모델에 적용하고, 그 조합이 얼마나 좋은지 평가한 값을 반환하는 함수이다.

```python
import optuna

from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score


def objective(trial):
    max_depth = trial.suggest_int(
        "max_depth",
        3,
        10
    )
    n_estimators = trial.suggest_int(
        "n_estimators",
        100,
        300
    )

    model = RandomForestClassifier(
        max_depth=max_depth,
        n_estimators=n_estimators,
        random_state=42
    )

    score = cross_val_score(
        model,
        X_train,
        y_train,
        cv=5,
        scoring="accuracy"
    ).mean()

    return score
```

흐름은 다음과 같다.

```text
Optuna가 하이퍼파라미터 선택
→ objective(trial) 실행
→ 모델 생성
→ CV 수행
→ 평균 점수 계산
→ Optuna에 점수 반환
```

C#식으로 생각하면 하나의 설정을 입력받아 성능 점수를 반환하는 평가 함수와 비슷하다.

## `trial.suggest_*()`

다음 코드는 이번 Trial에 사용할 `max_depth`를 3~10 사이의 정수에서 선택하라는 뜻이다.

```python
max_depth = trial.suggest_int(
    "max_depth",
    3,
    10
)
```

사람은 탐색 범위를 정하고 Optuna는 각 Trial에서 실제로 시험할 값을 고른다.

```text
사람이 정함
max_depth: 3~10
n_estimators: 100~300

Optuna가 이번 Trial에서 선택
max_depth: 7
n_estimators: 183
```

값의 종류에 따라 다음 메서드를 사용할 수 있다.

```python
trial.suggest_int(...)
trial.suggest_float(...)
trial.suggest_categorical(...)
```

## Study와 `optimize()`

Study는 여러 Trial과 그 결과를 관리하는 하나의 최적화 작업이다.

```python
study = optuna.create_study(
    direction="maximize"
)

study.optimize(
    objective,
    n_trials=50
)
```

`direction="maximize"`는 `objective()`가 반환한 값이 클수록 좋은 것으로 판단한다는 뜻이다.

`n_trials=50`은 총 50번의 Trial을 실행하겠다는 탐색 예산이다. Random Search의 `n_iter=50`과 “몇 개의 조합을 시험할지 정한다”는 점은 비슷하지만 다음 후보를 고르는 방식은 다르다.

### 50개를 10개씩 다섯 묶음으로 실행할까?

그런 고정 묶음 구조는 아니다.

기본적인 단일 작업 흐름에서는 Trial이 하나씩 완료되고 그 결과가 Study에 추가된다.

```text
Trial 1
→ 결과 기록
→ Trial 2
→ 결과 기록
→ ...
→ Trial 50
```

Optuna는 병렬 실행도 지원하지만 `n_trials=50` 자체가 “10개씩 다섯 묶음”을 뜻하지는 않는다.

---

## Optuna가 다음 Trial을 선택하는 방식

Optuna에서 TPE Sampler를 사용할 때는 초반 Trial에서 무작위 탐색으로 정보를 모으고, 이후에는 좋은 결과가 나온 값들과 그렇지 않은 값들의 분포를 비교해 다음 후보를 선택한다.

```text
초반
→ 여러 영역에서 정보 수집

이후
→ 이전 Trial 결과 분석
→ 더 유망한 후보 선택
→ 새 결과를 다시 반영
```

현재 최고 점수가 `A=4, B=73`에서 나왔다고 해서 바로 옆의 값만 계속 시험하는 방식은 아니다.

여러 좋은 Trial과 나머지 Trial의 전체적인 경향을 이용하면서 탐색과 활용 사이의 균형을 잡는다.

`8개는 좋은 영역, 2개는 무작위`처럼 사용자가 적은 고정 비율로 반복하는 구조라고 이해하면 안 된다.

## scikit-learn 탐색 결과 확인

### `best_params_`

설정한 평가 기준에서 CV 평균 점수가 가장 좋았던 하이퍼파라미터 조합이다.

```python
search.best_params_
```

`best`는 모든 면에서 절대적으로 가장 좋은 모델이라는 뜻이 아니다. 지정한 `scoring` 기준에서 가장 좋은 후보라는 뜻이다.

### `best_score_`

선택된 조합의 CV 평균 검증 점수이다.

```python
search.best_score_
```

봉인해둔 최종 Test Set의 점수와는 다르다.

```text
best_score_
→ Train 내부 CV에서 얻은 평균 검증 점수

최종 Test 점수
→ 마지막까지 사용하지 않은 Test Set에서 얻은 점수
```

### `cv_results_`

시험한 모든 조합의 점수와 계산 시간 등을 담고 있다.

```python
results = search.cv_results_

results["mean_test_score"]
results["std_test_score"]
results["mean_fit_time"]
results["mean_score_time"]
```

- `mean_test_score`: Fold 검증 점수의 평균
- `std_test_score`: Fold 검증 점수의 표준편차
- `mean_fit_time`: 평균 모델 학습 시간
- `mean_score_time`: 평균 예측 및 점수 계산 시간

### `test_score`의 test는 최종 Test Set일까?

아니다.

`cv_results_`에서 test는 각 Fold에서 학습에 사용되지 않고 검증 역할을 맡은 부분을 뜻한다. 마지막까지 봉인한 hold-out Test Set과는 별개이다.

---

## 결과 이름을 어떻게 읽을까?

철자를 통째로 외우기보다 이름을 나누어 읽으면 된다.

```text
mean = 평균
test = CV에서 검증 역할을 한 부분
score = 점수

mean_test_score
→ CV 평균 검증 점수
```

```text
std = standard deviation
    = 표준편차

std_test_score
→ CV 검증 점수의 표준편차
```

```text
fit = 학습
time = 시간

mean_fit_time
→ 평균 학습 시간
```

### `std_test_score`의 std는 C++의 `std::`와 같은 뜻일까?

서로 다르다.

C++의 `std::`는 standard library의 namespace를 나타낸다.

```cpp
std::vector<int> values;
std::cout << "hello";
```

머신러닝 결과의 `std`는 standard deviation, 즉 표준편차를 뜻한다.

---

## 평균 점수가 가장 높은 모델을 무조건 선택할까?

반드시 그런 것은 아니다.

```text
조합 A
CV 평균 = 0.910
표준편차 = 0.010
학습 시간 = 2초

조합 B
CV 평균 = 0.920
표준편차 = 0.080
학습 시간 = 15초

조합 C
CV 평균 = 0.918
표준편차 = 0.015
학습 시간 = 5초
```

평균만 보면 B가 가장 높다. 하지만 Fold에 따른 점수 변화가 크고 학습 시간도 길다.

C는 B보다 0.2%p 낮지만 더 안정적이고 빠르므로 실제 목적에 따라 C를 선택할 수 있다.

A도 평균 성능을 조금 더 포기하는 대신 안정성과 속도를 중요하게 본다면 가능한 선택이다.

학습할 때는 다음 순서로 단순화해서 볼 수 있다.

```text
1. 평균 성능이 충분한가?
2. 성능이 비슷하면 Fold별 안정성은 어떤가?
3. 또 비슷하면 학습 및 예측 비용은 어떤가?
```

하지만 실제 서비스에서는 안정성이나 비용이 평균 성능보다 더 중요할 수도 있으므로 고정된 절대 순위는 없다.

### Fold 점수 하나만 크게 튀어도 표준편차가 커질까?

그럴 수 있다.

표준편차는 각 값이 평균에서 떨어진 정도를 반영하고 편차를 제곱하므로 하나의 값이 크게 벗어나도 커질 수 있다.

표준편차가 크다면 어떤 Fold에서 점수가 달라졌는지와 그 Fold의 데이터 분포도 함께 확인하는 것이 좋다.

## `best_estimator_`와 재학습

scikit-learn의 Grid/Random Search는 기본적으로 `refit=True`이다.

탐색이 끝나면 선택된 최적 설정을 사용해 `fit()`에 전달했던 Train 데이터 전체로 모델을 다시 학습하고, 그 모델을 `best_estimator_`로 제공한다.

```text
여러 조합을 CV로 평가
→ 최적 조합 결정
→ best_params_
→ Train 전체로 재학습
→ best_estimator_
```

```python
best_model = search.best_estimator_
```

`refit=False`로 설정하면 재학습된 `best_estimator_`는 만들어지지 않는다.

## Optuna 결과와 최종 모델

Optuna Study에서는 다음 값으로 가장 좋은 Trial의 결과를 확인할 수 있다.

```python
study.best_params
study.best_value
```

```text
scikit-learn Search       Optuna Study

best_params_          ↔   best_params
best_score_           ↔   best_value
```

`best_value`는 `objective()`가 반환한 값 중 최적화 방향에 따라 가장 좋았던 값이다.

일반적인 Optuna 사용에서는 선택한 하이퍼파라미터로 최종 모델을 직접 생성하고 Train 전체에서 학습한다.

```python
best_params = study.best_params

final_model = RandomForestClassifier(
    **best_params,
    random_state=42
)

final_model.fit(
    X_train,
    y_train
)
```

`**best_params`는 딕셔너리의 키와 값을 함수의 이름 있는 인자로 풀어서 전달한다.

## 최종 Test 평가

최종 모델은 마지막까지 사용하지 않은 Test Set에서 평가한다.

```python
test_score = final_model.score(
    X_test,
    y_test
)

print(test_score)
```

### Test 데이터에는 정답이 없는 것 아닐까?

Test Set에는 실제 정답 `y_test`가 이미 있다. 다만 모델을 학습하고 설정을 선택하는 동안 그 정답을 사용하지 않을 뿐이다.

```text
모델에게 제공
→ X_test

평가할 때만 사용
→ y_test
```

모델의 예측과 숨겨둔 실제 정답을 비교해서 성능을 계산한다.

$$
\mathrm{Accuracy}=
\frac{\mathrm{맞힌\ 샘플\ 수}}
{\mathrm{전체\ Test\ 샘플\ 수}}
$$

예를 들어 100명의 Test 유저 중 87명의 이탈 여부를 맞혔다면 정확도는 87%이다.

### 실제 미래 데이터와 Test Set은 어떻게 다를까?

Test Set은 이미 결과까지 알고 있는 과거 데이터를 모델에게만 미래처럼 숨겨놓고 시험하는 데이터이다.

실제 미래 데이터는 아직 결과가 발생하지 않았으므로 바로 점수를 계산할 수 없다. 시간이 지나 실제 결과를 확보한 뒤에야 예측과 비교할 수 있다.

---

## 최종 점수는 항상 클수록 좋을까?

`.score()`의 반환값은 보통 하나의 실수이지만 의미는 모델과 평가 지표에 따라 달라진다.

- `RandomForestClassifier.score()`: 기본적으로 정확도
- `RandomForestRegressor.score()`: 기본적으로 $R^2$

$R^2$는 1에 가까울수록 좋고 음수가 나올 수도 있다.

MAE나 MSE 같은 오차를 직접 계산했다면 작을수록 좋다.

scikit-learn의 하이퍼파라미터 탐색에서는 높은 값을 좋은 점수로 처리하도록 손실 지표를 음수 형태의 scorer로 제공하는 경우도 있으므로 `scoring`의 의미를 반드시 확인해야 한다.

## 전체 흐름

```text
전체 데이터
        ↓
Train / Test 분리
        ↓
Test는 마지막까지 봉인
        ↓
Train 안에서 CV 수행
        ↓
여러 하이퍼파라미터 조합 평가
        ↓
조합별 CV 평균과 표준편차 계산
        ↓
성능 + 안정성 + 비용 비교
        ↓
최종 하이퍼파라미터 선택
        ↓
Train 전체로 최종 모델 재학습
        ↓
Test의 X만 모델에 입력
        ↓
예측 결과와 y_test 비교
        ↓
최종 Test 성능 확인
```

## Grid, Random, Optuna 한 번에 비교

```text
Grid Search
→ 지정한 후보 값의 모든 조합 탐색

Random Search
→ 지정한 횟수만큼 무작위 조합 탐색

Optuna
→ Trial 결과를 기록하고
→ 이전 결과를 이용해 다음 후보를 선택
```

세 방법 모두 사람이 탐색할 하이퍼파라미터, 범위와 평가 기준을 정해야 한다.

탐색 방법은 달라도 최종 목적은 좋은 설정을 선택하고 Train 전체로 모델을 다시 학습한 뒤, 봉인해둔 Test Set에서 공정하게 평가하는 것이다.
