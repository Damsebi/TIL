# 텍스트 임베딩과 벡터 검색·성능 평가

> 학습일: 2026-10-20

## 핵심 정리

- 임베딩은 텍스트를 의미 비교에 사용할 숫자 벡터로 변환하는 과정이다. 교안에서는 12개 문서를 28개 청크로 나누고 청크마다 384차원 벡터를 생성한다.
- E5 모델은 문서에 `passage:`, 질문에 `query:` 접두사를 사용한다. 문서와 질문은 같은 모델로 임베딩해야 한다.
- Padding은 배치의 토큰 길이를 맞추며 임베딩 차원을 바꾸지 않는다. Attention Mask는 실제 토큰과 PAD 위치를 구분한다.
- Mean Pooling은 PAD를 제외한 토큰 벡터의 평균으로 청크 벡터 하나를 만든다.
- L2 정규화는 0이 아닌 벡터의 길이를 1로 만들고 방향과 Shape은 유지한다. 정규화된 두 벡터의 내적은 코사인 유사도와 같다.
- Top-K는 최대 검색 개수이고 Threshold는 반환할 최소 점수다. 유사도 점수는 정답 확률이 아니므로 점수가 높아도 필요한 근거가 없을 수 있다.
- Hit@K는 정답 문서를 하나라도 찾았는지, Recall@K는 전체 정답 문서 중 얼마나 찾았는지를 평가한다. 여러 질문의 Hit 평균은 Hit Ratio@K다.
- 모델과 검색 설정은 동일한 문서·질문·Gold Document를 기준으로 비교한다. 내부 평가에서 Baseline을 이겼다고 SOTA라고 단정할 수는 없다.

## 1. 전체 학습 흐름

```text
원본 문서 12개
→ Chunking으로 28개 청크 생성
→ E5-small로 청크별 임베딩
→ Mean Pooling과 L2 정규화
→ 문서 벡터 행렬 (28, 384)

사용자 질문
→ 같은 모델로 임베딩·정규화
→ 질문 벡터 (384,)
→ 청크별 코사인 유사도 계산
→ Top-K 선택
→ Threshold 필터링
→ 대응하는 청크 원문 확보
→ Gold Document와 비교
→ Hit·Recall 계산
→ 검색 설정과 임베딩 모델 비교
```

이 장에서 확인할 것은 유사도 점수가 높은 후보를 찾았는지뿐 아니라, 질문에 필요한 정답 근거를 실제로 확보했는지다.

## 2. 텍스트 임베딩과 벡터 Shape

교안에서 사용하는 모델은 `intfloat/multilingual-e5-small`이다. 출력 차원은 384이며 최대 입력 길이는 512토큰으로 정리했다.

문자 수와 토큰 수는 다르다. 모델에 전달할 실제 입력에는 문서의 `passage:`, 질문의 `query:` 접두사와 특수 토큰도 포함될 수 있으므로 최종 토큰 길이를 확인해야 한다.

### 토큰 벡터에서 청크 벡터로

청크 하나를 Tokenizer로 나누면 여러 토큰이 만들어진다. Transformer는 각 토큰 위치에 대해 384차원 표현을 생성한다.

```text
청크 하나의 토큰별 표현
(토큰 수, 384)
→ Mean Pooling
→ 청크 벡터 하나
(384,)

전체 청크 28개
→ 청크 벡터 28개
→ (28, 384)
```

벡터가 28개인 이유는 원본 문서 수가 아니라 임베딩한 청크 수가 28개이기 때문이다.

### Padding이 필요한 이유

같은 배치의 입력도 토큰 길이가 서로 다를 수 있다. 텐서로 묶기 위해 짧은 입력에 PAD 토큰을 추가한다.

```text
문장 A: [토큰1, 토큰2, 토큰3, 토큰4]
문장 B: [토큰1, 토큰2, PAD,   PAD  ]
```

Padding으로 맞추는 길이는 설정에 따라 배치에서 가장 긴 입력이나 지정한 최대 길이일 수 있다.

PAD도 토큰 위치 하나를 차지하므로 Transformer 출력에는 해당 위치의 벡터가 존재한다. Padding이 바꾸는 것은 토큰 길이이며, 임베딩 차원인 384가 아니다.

### Attention Mask와 Mean Pooling

Tokenizer는 Padding 위치를 구분하는 `attention_mask`를 생성한다.

```text
토큰: [A, B, C, PAD, PAD]
Mask: [1, 1, 1,  0,   0 ]
```

- `1`: 실제 입력 토큰
- `0`: Padding 토큰

PAD까지 평균에 포함하면 원래 문장에 없는 위치가 결과에 영향을 준다. 따라서 Mean Pooling에서는 Mask를 적용해 실제 토큰의 벡터만 합하고 유효 토큰 수로 나눈다.

```python
mask = attention_mask.unsqueeze(-1)
sum_vectors = (token_embeddings * mask).sum(dim=1)
valid_tokens = mask.sum(dim=1)
sentence_embeddings = sum_vectors / valid_tokens
```

위 예시는 각 입력에 유효 토큰이 있다는 전제다. 배치 크기를 B, Padding 이후 길이를 T라고 하면 Shape은 다음과 같다.

| 값 | Shape | 역할 |
| --- | --- | --- |
| `token_embeddings` | `(B, T, 384)` | 토큰별 문맥 표현 |
| `attention_mask` | `(B, T)` | 실제 토큰과 PAD 구분 |
| `mask` | `(B, T, 1)` | 벡터에 곱할 수 있도록 마지막 차원 추가 |
| `sum_vectors` | `(B, 384)` | 유효 토큰 벡터의 합 |
| `valid_tokens` | `(B, 1)` | 입력별 유효 토큰 수 |
| `sentence_embeddings` | `(B, 384)` | 입력별 평균 벡터 |

Pooling은 토큰 차원을 줄이고 임베딩 차원은 유지한다.

## 3. L2 정규화와 코사인 유사도

### L2 정규화

0이 아닌 벡터의 각 원소를 벡터의 L2 Norm으로 나누면 길이가 1인 벡터가 된다.

$$
\hat{v} = \frac{v}{\lVert v \rVert_2}
$$

```text
v = (3, 4)
L2 Norm = 5
정규화 결과 = (0.6, 0.8)

길이: 5 → 1
방향: 유지
차원: 2 → 2
```

384차원 벡터도 같은 원리로 정규화한다. 값의 크기가 달라질 뿐 Shape이나 차원 수가 줄어드는 것은 아니다.

### 코사인 유사도

두 벡터의 방향이 얼마나 비슷한지 비교하는 값이다.

$$
\cos(\theta) =
\frac{A \cdot B}{\lVert A \rVert_2 \lVert B \rVert_2}
$$

| 값 | 수학적 의미 |
| --- | --- |
| `1` | 같은 방향 |
| `0` | 직각 |
| `-1` | 반대 방향 |

코사인 유사도 0은 두 벡터가 직각이라는 뜻이다. 실제 문장들이 의미적으로 완전히 무관하다고 단정하는 값은 아니다.

두 벡터가 모두 L2 정규화되어 있으면 분모가 1이므로 내적이 곧 코사인 유사도다.

$$
\lVert A \rVert_2 = \lVert B \rVert_2 = 1
\quad\Rightarrow\quad
\cos(\theta) = A \cdot B
$$

### NumPy의 @는 정규화가 필수인가?

`@` 연산 자체는 정규화와 관계없이 수행할 수 있다.

```python
import numpy as np

a = np.array([3., 4.])
b = np.array([6., 8.])
dot_product = a @ b  # 50.0
```

두 벡터는 같은 방향이므로 코사인 유사도는 1이지만, 정규화하지 않은 내적은 50이다. `@`를 사용할 수 있는 조건과 내적을 코사인 유사도로 해석할 수 있는 조건은 다르다.

### 전체 청크의 점수 계산

```python
scores = vectors @ query_vector
# (28, 384) @ (384,) → (28,)
```

문서 벡터 행렬의 각 행과 질문 벡터의 내적을 계산한다.

```text
청크 1 벡터 · 질문 벡터 → 점수 1
청크 2 벡터 · 질문 벡터 → 점수 2
...
청크 28 벡터 · 질문 벡터 → 점수 28
```

질문 벡터가 `(384,)`인 1차원 배열이므로 결과는 `(28,)`이다. 질문 벡터를 `(384, 1)`로 바꾸면 결과는 `(28, 1)`이다.

이 검색에서는 행렬 곱셈으로 여러 내적을 한 번에 계산하는 것이므로, 행렬 곱셈과 청크별 내적은 같은 계산을 서로 다른 관점에서 설명한 것이다.

## 4. 벡터와 청크 원문 연결

강의에서는 다음 파일을 서로 대응하도록 관리한다.

| 파일 | 저장 내용 |
| --- | --- |
| `vectors.npy` | 청크별 임베딩 벡터 |
| `chunks.json` | 청크 원문과 문서 정보 |
| `embedding_config.json` | 모델과 임베딩 설정 |

`vectors[i]`와 `chunks[i]`가 같은 청크를 가리켜야 검색한 벡터를 올바른 원문으로 연결할 수 있다.

```python
best_idx = np.argmax(scores)

matched_vector = vectors[best_idx]
matched_text = chunks[best_idx]["text"]
```

벡터는 유사도 계산에 사용하고, LLM에는 대응하는 원문을 근거로 전달한다.

### 높은 유사도가 정답을 보장하는가?

```text
질문: 대한민국의 수도는 어디인가?

문서 A: 대한민국의 수도는 서울이다.
문서 B: 대한민국의 수도는 부산이다.
```

두 문서 모두 질문과 관련성이 높지만 B의 내용은 사실과 다르다. 검색 점수는 정답 확률이 아니므로 실제 원문과 질문에 필요한 근거를 확인해야 한다.

## 5. Top-K와 Threshold

### Top-K 선택

Top-K는 점수가 높은 순서로 최대 K개의 청크를 선택한다.

```python
similarities = np.array([0.72, 0.95, 0.61, 0.88, 0.91])
top_k = 3

top_indices = np.argsort(similarities)[::-1][:top_k]
print(top_indices)  # [1 4 3]
```

- `np.argsort()`: 점수의 정렬 순서에 해당하는 인덱스를 반환한다.
- `[::-1]`: 오름차순 결과를 뒤집어 내림차순으로 만든다.
- `[:top_k]`: 상위 K개를 선택한다.

K가 작으면 필요한 근거를 놓칠 수 있고, 크면 불필요하거나 충돌하는 자료가 함께 들어갈 수 있다.

### Threshold 필터링

Threshold는 반환할 최소 유사도 기준이다. Top-K 선택 후 이 기준을 적용하면 실제 반환 결과는 K개보다 적을 수 있다.

정답 문서가 A와 B라고 가정한다.

| 순위 | 문서 | 유사도 | 정답 여부 |
| --- | --- | --- | --- |
| 1 | A | 0.93 | O |
| 2 | C | 0.90 | X |
| 3 | B | 0.82 | O |

```text
K=3, Threshold 없음
→ A, C, B 반환
→ 정답 A, B 모두 확보

K=3, Threshold=0.85
→ A, C 반환
→ 정답 B 누락
```

식비 한도는 A, 숙박비 한도는 B에 있다면 점수가 가장 높은 문서 하나만으로는 질문에 필요한 근거를 모두 얻지 못할 수 있다.

Threshold를 0.80으로 낮추면 불필요한 C도 남지만 A와 B를 함께 확보할 수 있다. 다만 불필요한 자료가 많거나 내용이 충돌하면 답변 오류를 늘릴 수 있으므로 균형이 필요하다.

### Threshold를 높이면 항상 정확한가?

그렇지 않다. 다음과 같은 상황도 가능하다.

| 질문 | 최고 유사도 | 실제 정답 존재 |
| --- | --- | --- |
| A | 0.81 | O |
| B | 0.89 | X |

Threshold 0.85는 A의 정답 후보를 제외하면서 B의 부적절한 후보를 통과시킬 수 있다.

높은 Threshold는 관련성 낮은 자료를 줄일 수 있지만 정답 문서도 놓칠 수 있다. 점수 하나를 정답 존재 여부의 절대 기준으로 사용해서는 안 된다.

### 검색 원문을 Context로 결합하기

```python
retrieved_texts = ["문서A", "문서B", "문서C"]
context = "\n\n".join(retrieved_texts)
```

`join()`은 원본 리스트를 바꾸지 않고 새 문자열을 반환한다. Context를 질문과 함께 Prompt에 포함하면 LLM이 검색 근거를 참고한다. 이는 모델 가중치를 변경하는 학습 과정이 아니다.

## 6. Gold Document와 검색 평가

검색 성능을 계산하려면 질문마다 필요한 정답 문서를 미리 정해야 한다.

- `gold_docs`: 정답으로 지정한 원본 문서 ID 집합
- `retrieved_docs`: 실제 검색 결과에 대응하는 원본 문서 ID 집합
- `found`: 두 집합의 교집합

검색은 청크 단위로 하더라도 이 장의 평가는 원본 문서 ID를 기준으로 한다. 같은 원본의 청크가 여러 개 검색되었다고 서로 다른 정답 문서를 여러 개 찾은 것으로 세지 않는다.

### Hit@K와 Recall@K

```python
gold_docs = {"meal", "travel"}
retrieved_docs = {"meal", "education"}
found = gold_docs & retrieved_docs

hit = int(len(found) > 0)
recall = len(found) / len(gold_docs)

print(hit)     # 1
print(recall)  # 0.5
```

`&`는 교집합 연산이다. 위 예시는 정답이 meal과 travel인데 meal만 찾았으므로 Hit은 1이고 Recall은 0.5다.

| 지표 | 질문 |
| --- | --- |
| Hit@K | 상위 K개에 정답 문서가 하나라도 있는가? |
| Recall@K | 전체 정답 문서 중 상위 K개에서 얼마나 찾았는가? |
| Hit Ratio@K | 여러 질문에서 정답을 하나 이상 찾은 비율은 얼마인가? |

Recall의 분모는 K나 반환 문서 수가 아니라 전체 정답 문서 수다.

$$
\mathrm{Recall@K}
= \frac{\text{검색된 정답 문서 수}}{\text{전체 정답 문서 수}}
$$

위 Recall 계산은 정답 문서가 있는 질문을 전제로 한다. 정답 문서가 없는 질문은 분모가 0이므로 별도의 평가 기준을 정해야 한다.

### @K의 의미와 계산 예시

```text
정답: {A, B, C, D}

검색 순위
1위 A
2위 E
3위 C
4위 B
5위 D
```

- Recall@3: 전체 정답 4개 중 A와 C를 찾았으므로 `2/4 = 0.5`
- Recall@5: 전체 정답을 찾았으므로 `4/4 = 1.0`

여기서 `@`는 NumPy의 행렬 곱셈이 아니라 상위 K개를 기준으로 평가한다는 표기다.

정답이 `{A, B, C}`이고 검색 결과가 `{A, D, E}`라면 Hit@3은 1, Recall@3은 1/3이다. Hit이 1이어도 답변에 필요한 근거 전체를 확보했다고 볼 수 없다.

Top-K에 Threshold까지 적용하면 위 5절의 사례처럼 K=3을 유지해도 Recall이 `1.0 → 0.5`로 낮아질 수 있다. 이때는 Threshold 적용 여부와 값도 함께 기록해야 결과를 비교할 수 있다.

### Hit Ratio@K

여러 질문의 Hit 값을 평균 낸다.

| 질문 | Hit@3 |
| --- | --- |
| 질문 1 | 1 |
| 질문 2 | 1 |
| 질문 3 | 0 |
| 질문 4 | 1 |
| 질문 5 | 1 |

$$
\mathrm{Hit\ Ratio@3} = \frac{4}{5} = 0.8
$$

5개 질문 중 4개에서 정답 문서를 하나 이상 찾았다는 의미다.

## 7. 임베딩 모델 비교와 결론의 범위

E5-small과 E5-base 같은 모델을 비교할 때는 다음 조건을 맞춘다.

- 평가 문서와 청킹 결과
- 평가 질문과 Gold Document
- Top-K와 Threshold 등 검색 조건
- 문서 ID 기준 등 평가 단위와 지표 계산 방법

모델별로 문서와 질문을 각각 해당 모델로 임베딩해야 한다. 한 모델의 문서 벡터와 다른 모델의 질문 벡터를 섞어 비교하지 않는다.

다음 수치는 설명을 위해 가정한 예시다.

| 모델 | Hit Ratio@3 |
| --- | --- |
| E5-small | 0.80 |
| E5-base | 0.90 |

동일한 조건에서 이런 결과를 얻었다면 “이번 평가에서는 E5-base가 더 높은 Hit Ratio@3을 기록했다”라고 결론 내릴 수 있다. 다른 데이터나 모든 RAG 시스템에서도 항상 우수하다는 뜻은 아니다.

### Baseline과 SOTA

| 용어 | 의미 |
| --- | --- |
| Baseline | 비교 기준으로 정한 모델이나 설정 |
| 내부 평가 최고 모델 | 직접 비교한 후보 중 가장 좋은 결과를 기록한 모델 |
| SOTA | 특정 작업·평가 기준에서 현재 알려진 최고 수준의 성능 |

Baseline보다 좋거나 두 후보 중 가장 높았다는 사실만으로 SOTA라고 주장할 수는 없다.

SOTA를 판단하려고 모든 모델을 직접 실험해야 하는 것은 아니다. 해당 작업의 공개 벤치마크나 알려진 연구 결과와 비교해 주장의 범위를 확인한다. 공식 인증 명칭은 아니며 새로운 결과에 따라 달라질 수 있다.

## 8. 함께 정리한 Python 함수의 반환값

원본을 변경하는지와 무엇을 반환하는지는 별도로 확인해야 한다.

| 함수 | 원본 변경 | 반환값 |
| --- | --- | --- |
| `list.append()` | O | `None` |
| `list.sort()` | O | `None` |
| `sorted()` | X | 새 리스트 |
| `np.argsort()` | X | 정렬 인덱스 배열 |
| `list.pop()` | O | 제거한 값 |

```python
numbers = [1, 2, 3]
result = numbers.append(4)

print(numbers)  # [1, 2, 3, 4]
print(result)   # None
```

정렬 인덱스를 얻는 `np.argsort()`와 원본 리스트를 정렬하는 `list.sort()`의 동작을 혼동하지 않아야 한다.

## 오답 노트

| 처음 이해 | 수정된 이해 |
| --- | --- |
| Padding이 임베딩 차원에도 영향을 준다. | 토큰 길이를 맞추는 과정이며 E5-small의 임베딩 차원 384는 유지된다. |
| Mean Pooling을 하면 벡터 차원도 줄어든다. | 토큰 차원을 평균으로 줄여 청크 하나당 384차원 벡터를 만든다. |
| 코사인 유사도 0이면 두 문장의 의미가 완전히 무관하다. | 벡터가 직각이라는 수학적 관계이며 의미적 무관함을 단정할 수는 없다. |
| `@`는 정규화된 벡터에만 사용할 수 있다. | 연산 자체는 정규화와 무관하며, 양쪽이 정규화되어야 내적을 코사인 유사도로 바로 해석할 수 있다. |
| 유사도가 높으면 정답 문서다. | 관련성 높은 문서도 틀린 사실을 포함할 수 있다. 점수와 정답 여부는 다르다. |
| Recall의 분모는 K나 반환 문서 수다. | 전체 정답 문서 수가 분모다. |
| Hit@3은 찾은 정답 수의 비율이다. | 하나라도 찾으면 1이며, 전체 정답 중 찾은 비율은 Recall@3이다. |
| Threshold를 높이면 항상 더 정확하다. | 필수 근거를 제외할 수 있고 정답 없는 질문도 높은 점수를 받을 수 있다. |
| Baseline을 이긴 모델은 SOTA다. | 해당 실험의 개선 결과이며, SOTA는 특정 작업의 알려진 최고 수준과 비교해야 한다. |
