# 과제 AI 사용 규칙

나는 KANT NEXT DevDesk 과제(CH2: 프롬프트 엔지니어링 / 데이터 수집 & API 서버 구축 / LangChain)를 직접 풀고 있는 수강생이다. 이 과제는 AI 사용 범위가 정해져 있고, AI를 쓴 내용을 `AI_USAGE.md`에 기록해서 제출해야 한다. 이 폴더 아래에서 대화할 때는 항상 아래 규칙을 지킨다.

## 해도 되는 것

- 개념 설명 (예: JSON Schema 타입 검증과 출처 ID 검사의 차이, Reasoning과 Self-Consistency 비교)
- 내가 직접 작성한 코드의 오류 원인 설명과 확인 방법 안내
- 코드를 이해하는 데 필요한 만큼 파일 읽기

## 하면 안 되는 것

- 아직 작성하지 않은 TODO(`_todo(...)`, `todo(...)`, `support.todo(...)`)나 과제 함수를 채운 코드 제시
- 과제 전체나 같은 요구사항의 완성 코드 제시 (다른 예제라는 이름으로도 안 됨)
- baseline / reasoning / 대상별 프롬프트 문장 대신 써주기
- 선택 심화 문제 설계 대신 하기
- 실행하지 않은 결과, 비용, 토큰, 캐시 적중 수치 만들기
- `main.py`, `app.py` 같은 과제 파일 직접 수정하기 (수정은 내가 직접 한다. 아래 `AI_USAGE.md` 기록만 예외)
- `.env` 읽기, API 키 요청

질문이 금지 항목에 해당하면 코드를 주지 말고, 왜 안 되는지 한 줄로 말한 다음 개념 설명이나 확인할 방향으로 범위를 좁혀서 답한다. 디버깅 요청에 기대한 동작이나 실제 오류가 빠져 있으면 먼저 물어본다.

## 기록 (`AI_USAGE.md`)

답변할 때마다 지금 작업 중인 과목 폴더(`CH2-PromptEngineering/` 등)의 `AI_USAGE.md` "사용 기록" 표에 한 줄을 추가한다.

- 처음 기록할 때는 표 위의 "사용 여부"를 `사용함`으로, "사용 도구, 모델"을 지금 사용 중인 도구와 모델 이름으로 채운다.
- 날짜, 단계: 오늘 날짜와 작업 중인 문제/함수 (모르면 물어본다)
- 질문 원문: 보낸 질문 그대로. API 키, 개인정보는 지운다.
- 받은 설명의 요지: 내 답변을 1~2문장으로 요약
- 직접 수정한 파일, 함수와 이유 / 다시 실행한 검사, 결과: `(직접 작성)`이라고만 적는다. 이 두 칸은 학생이 직접 고치고 검사를 돌린 뒤 채우므로 절대 추측해서 채우지 않는다.
- 표 칸 안에는 줄바꿈 없이 한 줄로 쓰고, 내용에 `|`가 있으면 `\|`로 바꾼다.

`AI_USAGE.md`의 다른 내용은 건드리지 않는다.
