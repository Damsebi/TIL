# Attention Score: 내적과 QKᵀ Shape 추론

> 학습일: 2026-08-07

## 1. 오늘 학습한 내용을 나만의 언어로 정리하기

> Q와 K를 내적해서 나온 값은 V를 얼마나 중요하게 볼지 결정하기 위한 점수다.

### 내가 이해한 Attention의 흐름

Attention은 **어디를 볼지 정한 다음, 그곳의 정보를 중요한 만큼 가져와 섞는 과정**으로 이해했다.

- **Q/K**: 누구를 얼마나 볼지 결정한다.
- **V**: 선택한 토큰에서 실제로 가져올 정보다.
- **Attention**: Q/K로 정한 중요도에 따라 여러 V를 가중합한다.
- **Multi-Head**: 여러 관점에서 위 과정을 각각 수행한 뒤 `Concat → Linear`로 다시 하나의 표현으로 합친다.

예를 들어 `"재설정"`의 Query와 모든 Key를 비교했을 때 `"비밀번호"`의 점수가 크다면 다음과 같은 의미다.

```text
"재설정"은 "비밀번호"를 많이 참고해야 함
→ "비밀번호"에 해당하는 V를 많이 가져옴
```

여기서 큰 내적값 자체를 정보로 가져오는 것은 아니다. 내적값은 **몇 번째 V를 얼마나 중요하게 볼지 정하는 점수**다.

### Q·K·V는 현재 입력에서 만든다

`X`는 현재 입력 문장의 토큰 표현이고, 여기에 학습된 가중치를 적용해 Q, K, V를 각각 만든다.

```text
Q = X @ W_Q
K = X @ W_K
V = X @ W_V
```

학습 데이터의 K나 V를 저장해 두었다가 검색하는 구조가 아니다. 학습 데이터의 영향은 `W_Q`, `W_K`, `W_V`에 반영되어 있고, 그 가중치로 현재 입력 `X`를 변환한다.

### `QKᵀ`의 Shape를 읽는 방법

토큰마다 Q와 K가 하나씩 있으므로, 여러 토큰을 행으로 쌓아 모든 조합을 한 번에 계산한다.

```text
Q   : (seq_len, d_k)
K.T : (d_k, seq_len)

Q @ K.T → (seq_len, seq_len)
```

결과의 한 행은 **해당 Query가 각 Key를 얼마나 볼지 적어둔 점수표**라고 이해했다.

### 점수에서 Attention 출력까지

Q, K, V는 먼저 모두 만든다. Q/K 점수에 Scaling과 Softmax를 적용해 중요도 비율로 바꾼 뒤, 그 비율대로 V들을 섞는다.

```text
Q, K, V 생성
→ QKᵀ로 누구를 볼지 점수 계산
→ Scaling과 Softmax로 중요도 비율 생성
→ 중요도에 따라 V들을 가중합
→ 문맥이 반영된 Attention 출력
```

이 출력은 모델이 바로 내뱉는 최종 단어가 아니라, 다음 계산으로 전달되는 내부 표현이다.

## 2. 학습하며 겪었던 문제점과 해결 과정

### 질문: `K @ q`로 하면 전치하지 않아도 되는 것 아닌가?

Query가 하나의 1차원 벡터 `q`라면 가능하다. `K @ q`를 계산하면 각 Key와 `q`의 내적값이 나온다.

```text
K     : (3, 2)
q     : (2,)
K @ q : (3,)
```

하지만 Query가 여러 개 쌓인 `Q`가 되면 `K @ Q`는 Shape이 맞지 않는다. 모든 Query와 Key 조합을 구하려면 `Q @ K.T`로 계산해야 한다.

```text
Q @ K.T
(4, 2) @ (2, 4)
→ (4, 4)
```

---

### 질문: 토큰을 왜 열이 아니라 행으로 쌓는가?

반드시 행으로 쌓아야 하는 것은 아니다. 다만 딥러닝에서는 보통 Feature 차원을 마지막에 두는 형태를 많이 사용한다.

```text
(batch, seq, feature)
```

이렇게 두면 토큰을 행으로 쌓아 `X @ W` 형태로 한 번에 변환하기 편하다.

---

### 이해 수정: `X`와 학습 데이터의 관계

#### 처음 이해

`X`에서 Query를 만들고 학습 데이터에 저장된 K와 V를 검색하는 구조처럼 생각했다.

#### 해결 및 이해

`X`는 현재 입력 문장의 토큰을 임베딩한 표현이다. 저장된 학습 데이터를 검색하는 것이 아니라, 현재 `X`를 학습된 가중치로 바꿔 Q, K, V를 만든다.

```text
현재 입력
→ 토큰화·임베딩
→ X
→ Q, K, V
```

---

### 이해 수정: Q·K·V를 질문·조건·답변으로 나눈 이해

#### 처음 이해

Q는 질문, K는 조건, V는 실제 답변이거나 각각 특정 문법 역할을 담당한다고 생각했다.

#### 해결 및 이해

Q, K, V는 문장 자체나 고정된 문법 역할이 아니다. 같은 토큰을 서로 다른 용도로 바꾼 표현이다.

```text
Q/K → 누구를 얼마나 볼지 결정
V   → 그 토큰에서 실제로 가져올 정보
```

---

### 질문: Q와 V를 바로 내적하면 안 되는가?

표준 Attention에서는 Q/K가 볼 곳을 정하고 V가 정보를 전달하도록 역할을 나눈다. K와 V를 분리하면 같은 토큰도 비교하기 좋은 표현과 전달하기 좋은 표현을 따로 학습할 수 있다.

---

### 질문: Q와 K의 내적값이 V인가?

아니다.

```text
QKᵀ = 어느 토큰을 얼마나 참고할지 나타내는 관련도 점수
V   = X @ W_V로 미리 만든 정보 벡터
```

두 번째 Key의 점수가 가장 크다면 그 숫자가 V가 되는 것이 아니다. **두 번째 토큰의 `V₂`를 많이 가져오라**는 뜻이다.

---

### 질문: V는 필요 없는 것 아닌가?

Q와 K만 있으면 누구를 볼지는 알 수 있지만 무엇을 가져올지는 없다. V가 실제로 가져올 정보를 담당한다.

---

### 질문: V들을 가중해서 더한 값이 모델이 내뱉는 값인가?

여러 V를 중요도에 따라 가중합한 값은 Attention 출력 벡터다.

```text
Softmax 결과가 [0.1, 0.7, 0.2]라면
→ 0.1V₁ + 0.7V₂ + 0.2V₃
```

이 값은 바로 최종 단어가 아니라 문맥이 반영된 내부 표현이다.

---

### 질문: Softmax는 V를 구한 이후에 적용하는가?

Q, K, V는 먼저 모두 만든다. Softmax는 V가 아니라 Q/K 점수에 적용하며, 각 V를 얼마나 가져올지 비율로 바꾼다.

```text
Q, K, V 생성
→ QKᵀ 점수 계산
→ Scaling과 Softmax
→ V 가중합
```
