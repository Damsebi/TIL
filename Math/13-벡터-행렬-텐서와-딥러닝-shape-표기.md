# 벡터·행렬·텐서와 딥러닝 Shape 표기

> 학습일: 2026-08-07

## 핵심 정리

Shape는 배열의 각 축에 원소가 몇 개씩 있는지를 나타낸다. `shape[i]`는 `axis=i`의 크기이다.

벡터는 보통 1차원 배열, 행렬은 2차원 배열이며, 텐서는 이들을 포함한 다차원 배열을 통틀어 부르는 말로 사용할 수 있다.

딥러닝에서는 Shape의 숫자만 읽는 것으로는 부족하다. 각 축이 배치, 문장 길이, 특징 수, 채널, 높이, 너비 중 무엇을 뜻하는지 함께 확인해야 한다.

`sum(axis=n)`처럼 축을 따라 값을 합치면 기본적으로 그 축은 결과에서 사라지고, `keepdims=True`를 사용하면 크기가 1인 축으로 남는다.

> 결국 Shape를 읽는다는 것은 숫자의 개수만 보는 것이 아니라 각 축이 실제 데이터에서 무엇을 나타내는지 해석하는 것이다.

---

## Shape

Shape는 배열의 각 축 크기를 순서대로 적은 튜플이다.

```python
import numpy as np

vector = np.array([3, 5, 7])

print(vector.shape)  # (3,)
print(vector.ndim)   # 1
```

이 벡터는 축이 하나이고 그 축에 원소가 3개 있다.

```text
axis=0
  ↓
[3, 5, 7]
```

### $(3,)$의 쉼표는 왜 필요할까?

`(3,)`은 길이가 3인 1차원 Shape라는 뜻이다.

Python에서 원소가 하나인 튜플을 표현하려면 쉼표가 필요하다. `(3)`은 숫자 3을 괄호로 감싼 것일 뿐 튜플이 아니다.

```text
(3,) → 축 1개, axis=0의 크기가 3
(3,1) → 축 2개, axis=0의 크기가 3, axis=1의 크기가 1
```

두 Shape는 원소 수가 같더라도 차원과 행렬 연산 결과가 다를 수 있다.

---

## 벡터, 행렬, 텐서

### 벡터

NumPy에서는 보통 1차원 배열로 표현한다.

```text
shape: (3,)
ndim: 1
```

### 행렬

행과 열을 가진 2차원 배열이다.

```python
matrix = np.zeros((3, 2))

print(matrix.shape)  # (3, 2)
print(matrix.ndim)   # 2
```

```text
shape = (3, 2)
          ↑  ↑
          │  └─ axis=1의 크기
          └──── axis=0의 크기
```

- `axis=0`의 크기: 3
- `axis=1`의 크기: 2

### 3차원 텐서

```python
tensor3d = np.zeros((2, 3, 4))

print(tensor3d.shape)  # (2, 3, 4)
print(tensor3d.ndim)   # 3
```

```text
axis=0 → 크기 2
axis=1 → 크기 3
axis=2 → 크기 4
```

### 텐서는 꼭 3차원 이상일까?

문맥에 따라 다르다.

수학에서는 벡터, 행렬, 고차원 텐서를 구분해서 말하기도 하지만, 딥러닝 프레임워크에서는 1차원 벡터와 2차원 행렬까지 모두 텐서라고 부르는 경우가 많다.

지금 단계에서는 텐서를 “여러 차원의 숫자 배열을 통틀어 부르는 말”로 이해하면 된다.

## Shape에서 중요한 것은 숫자의 의미

다음 Shape는 3차원 텐서라는 사실만으로는 충분히 설명되지 않는다.

```text
(32, 10, 512)
```

자연어 처리에서는 보통 다음 의미로 사용할 수 있다.

```text
(batch, seq_len, hidden_dim)
   32       10        512
```

- `batch=32`: 한 번에 처리하는 문장이 32개
- `seq_len=10`: 각 문장을 토큰 위치 10개로 표현
- `hidden_dim=512`: 각 토큰을 숫자 512개로 표현

따라서 전체 구조는 다음처럼 읽는다.

```text
문장 32개
→ 문장마다 토큰 10개
→ 토큰마다 특징값 512개
```

### hidden dimension 512는 공간이 실제로 512차원이라는 뜻일까?

기하학적으로는 512차원 벡터 공간의 한 점으로 볼 수 있다.

직관적으로는 단어나 토큰 하나를 표현하기 위해 숫자 512개를 사용한다고 생각하면 된다. 사람이 각 숫자에 이름을 직접 붙이는 것이 아니라 모델이 학습하면서 여러 특징을 그 벡터에 나누어 담는다.

---

## 문장 길이가 서로 다르면 어떻게 묶을까?

하나의 배치로 묶으려면 각 샘플의 Shape가 맞아야 한다.

보통 짧은 문장 뒤에 PAD 토큰을 추가해 `seq_len`을 통일한다.

```text
문장 A: [나, 게임, 한다, PAD, PAD]
문장 B: [오늘, 나는, 재미있는, 게임, 한다]

두 문장의 seq_len = 5
```

PAD는 길이를 맞추기 위한 값이므로 모델이 실제 내용으로 사용하지 않도록 보통 마스크도 함께 사용한다.

### 항상 배치에서 가장 긴 문장에 맞출까?

간단하게는 현재 배치의 가장 긴 문장에 맞출 수 있다. 모델이 요구하는 고정 최대 길이가 있다면 그 길이까지만 자르거나 채우기도 한다.

길이를 지나치게 크게 잡으면 PAD가 많아져 불필요한 계산이 늘어난다.

## 이미지 데이터의 Shape

PyTorch에서는 이미지 배치를 흔히 다음 순서로 표현한다.

```text
(batch, channel, height, width)
```

예를 들어 다음 Shape를 생각해보자.

```text
(16, 3, 224, 224)
```

- 이미지 16장
- RGB 3채널
- 높이 224픽셀
- 너비 224픽셀

계층 구조로 보면 다음과 같다.

```text
16개의 이미지
│
├─ 이미지 1
│  ├─ Red:   224 × 224
│  ├─ Green: 224 × 224
│  └─ Blue:  224 × 224
│
└─ 나머지 이미지도 같은 구조
```

컬러 이미지는 보통 Red, Green, Blue의 3채널을 사용하고, 흑백 이미지는 보통 1채널을 사용한다.

### 원본 화면 크기를 그대로 사용하면 안 될까?

1920×1080 크기의 RGB 이미지 한 장은 다음 Shape로 표현할 수 있다.

```text
(3, 1080, 1920)
```

하지만 이미지가 커질수록 처리해야 할 픽셀 수가 크게 늘어난다.

$$
224\times224=50{,}176
$$

$$
1920\times1080=2{,}073{,}600
$$

원본은 224×224보다 픽셀 수가 약 41배 많다. 그래서 실제 모델에서는 입력 이미지를 모델이 요구하는 크기로 줄이거나 잘라서 사용하는 경우가 많다.

224×224는 절대적인 규칙이 아니며 모델마다 입력 크기가 다르다.

## NCHW와 NHWC

이미지 Shape의 축 순서는 프레임워크와 코드에 따라 다를 수 있다.

### NCHW

```text
(batch, channel, height, width)
```

PyTorch에서 흔히 사용하는 순서이다.

### NHWC

```text
(batch, height, width, channel)
```

일부 다른 프레임워크나 이미지 처리 코드에서 사용하는 순서이다.

같은 숫자 네 개가 있어도 순서가 다르면 완전히 다른 의미가 된다. 따라서 Shape 숫자를 외우기보다 각 축의 이름을 먼저 확인해야 한다.

---

## `sum(axis=n)`에서 축이 사라진다는 뜻

다음 2차원 배열을 생각해보자.

```python
X = np.array([
    [1, 2, 3],
    [4, 5, 6]
])

print(X.shape)  # (2, 3)
```

`axis=1`을 따라 합하면 각 행 안의 열 방향 값을 하나로 합친다.

```python
result = X.sum(axis=1)

print(result)        # [ 6 15]
print(result.shape)  # (2,)
```

```text
[1, 2, 3] → 6
[4, 5, 6] → 15
```

결과에 숫자 두 개가 남았지만 `axis=1`을 선택할 필요는 없어졌다. 그래서 두 번째 축이 사라지고 Shape가 `(2,)`가 된다.

> 축이 사라진다는 것은 값이 하나도 남지 않는다는 뜻이 아니라, 그 축을 선택하기 위한 인덱스가 더 이상 필요하지 않다는 뜻이다.

### `keepdims=True`를 사용하면?

합한 축을 없애지 않고 크기가 1인 축으로 남긴다.

```python
result_keepdims = X.sum(axis=1, keepdims=True)

print(result_keepdims)
# [[ 6]
#  [15]]

print(result_keepdims.shape)  # (2, 1)
```

```text
keepdims=False → [6, 15]   → shape (2,)
keepdims=True  → [[6],     → shape (2, 1)
                  [15]]
```

크기가 1인 축을 유지하면 이후 브로드캐스팅이나 다른 행렬과의 연산에서 Shape를 맞추기 편할 수 있다.

## Shape를 읽을 때 확인할 순서

```text
1. ndim으로 축이 몇 개인지 확인
2. shape로 각 축의 크기 확인
3. 각 axis가 실제로 무엇을 뜻하는지 확인
4. 연산 전후 어떤 축이 바뀌거나 사라지는지 확인
5. 프레임워크가 요구하는 축 순서 확인
```

같은 Shape라도 데이터의 문맥에 따라 의미가 달라질 수 있으므로 변수 이름과 라이브러리 문서도 함께 확인한다.
